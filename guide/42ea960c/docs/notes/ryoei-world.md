# 「良栄」のトップ r/ の「記憶の中を歩く空間」（#657）

r/ は平野良栄の経歴とポートフォリオを1枚で見せるページ。HTML（一覧）に中身をすべて焼き込み、その上に
「スマホで一人称視点で歩き回れる、平野の記憶の中の空間」を重ねる。「新サイトの基本の形」（面・400px・白地）の例外（2026-11-03 の決定）。
決定の一覧は `docs/decisions/ryoei.md`。公開は #656（noindex・メニュー未掲載のまま）。

## ファイル

## 中身と見た目の分け方（2026-11-03 の決定、RYO-08〜10）

r/ は出来事を足しながら育てる。毎回作り直して既存の部分が変わらないよう、中身はシート「R_良栄」（説明・基本・出来事・駅・路線・ライフライン・素材の7つ。列の意味は「説明」シート）、
見た目（駅の中の配置・作り込んだ場面）はコードに分ける。

- **読み方**: 生成のたびに「R_良栄」を読み、`ryoei_book.parse()` で確かめる。ID の重複・参照切れ（出来事の駅ID・素材の出来事ID・路線の駅の並び）・日付の書式（YYYY／YYYY-MM／YYYY-MM-DD／空）・
  見せ方・表示・使い方の値・ライフラインの高さ（−100〜100）・家族の出来事が灯りでない、のどれかに当たれば、行と理由を出して止める（平野さんがシートを直す）。表示＝N の行は出さない
- **ページに出す「基本」の項目**: 名前・読み・肩書き・写真・自己紹介の7つ（`ABOUT_KEYS`。肩書き・生年月日・出身・所在地・専門・所属・目標。出身・目標は 2026-11-04 の決定。どれも無ければ止める）・SNS の5つ（`SNS_ICONS` のアイコンがあるもの）・「数字: 」で始まる項目（値は「数＋単位（説明）」）。
  ほかの項目は、出すと決めて `ABOUT_KEYS` などに足すまで出さない（`--check` が警告で知らせる）
- **出演**: 「素材」の使い方がスクリーン・看板・リンクで表示＝Y の行（シートの並び）。サムネイルは YouTube の動画なら動画の ID から作り、ほかは `THUMBS`（素材 ID で引く）。媒体の名前は出どころのホストから（`MEDIA_LABELS`）
- **家族の出来事**: 見せ方＝灯りの出来事と灯りの駅に置かれた出来事は ID・年・見せ方だけ、灯りの駅は ID・見せ方だけ（駅名・時代を書かない）、灯りの駅を含む路線は名前を書かず色と駅の並びだけ（2026-11-04 の決定）を `r/world-data.json` に書き出す。物の出来事は題・説明を書かない。灯りの出来事を指す素材（写真パネルを除く）が表示＝Y なら止める（題が出演に出るため）。
  書く前に、灯りの出来事・灯りの駅に置かれた出来事（表示＝N を含む）の題・説明、灯りの駅の名前、灯りの駅を含む路線の名前が HTML・JSON に出ていないことを確かめ、出ていれば止める（どの ID かを出す）。ライフラインはラベルを書かず年と高さだけ（使う場面を決めるまで）
- **既存が変わらないための決まり**:
  - ID（出来事の E・駅の S・路線の L・素材の M）は変えない・使い回さない。並べ替えや追加で既存が動かないように、コードは ID で引く（`THUMBS` など）
  - 写真の線画は、素材 ID から名前を決めて一度だけ作り、元の写真が変わったときだけ作り直す（仕組みは写真パネルを作る指示で）
  - 駅の中は番号付きの置き場所にし、新しい物は空いている置き場所に入る（既存の物の位置は変えない）
- **フォルダ「【Claude受渡用】」**: 写真の受け渡しにだけ使う（2026-11-03 時点は特別授業のスライドの PDF 1件）。ふだんの生成は読まず、`--check` だけが一覧と PDF のページ数を出す（届かなくても止めない）

## 仕組み

- **出し分け**: `prefers-reduced-motion: reduce` か WebGL が無い端末では「入る」を出さず、一覧だけにする（理由を一覧の上に書く）。JS が無ければ一覧だけ
- **一覧**: 自己紹介 → 数字で見る → 成績（成績・成績詳細へのリンク。空間に入らずに読む人向け、2026-11-03 の決定。牌譜は 2026-11-06 に廃止、#673）→ 出演（サムネイルだけを大きく）。目次は対局室（自己紹介・数字で見る・成績）と屋外上映（出演）
- **場面**（屋外、2026-11-03 の決定。m 単位。南〈+z〉から北の水辺へ）: 石畳の広場（入口、z -6〜12。立て看板に名前と肩書き）→ 砂利の上映の場（z -27〜-6。足場に張った大スクリーンに最新の1本、客席を囲む左右の立て看板の小さなスクリーンに残りの6本、まばらな折りたたみ椅子）→ 板張りの桟橋と手すり（z -31〜-27）→ 水（光の筋がゆっくり流れる）→ 対岸の街の灯り（灯りの窓の箱）。
  広場の東の一角に雀荘の建物（x 12〜18・z -4〜2、灯りのついた窓・扉は西）があり、中が対局室（全自動卓1台・上から1灯・手前の手牌13枚）。実在の映画祭のロゴ・名前・会場は描かない。
  建物は `roomShell()`（床・天井・壁。開口は `gaps`）、歩ける範囲は `walkable`（屋外は建物を避ける重なった4つの長方形・建物の中）と `doors`（扉。壁の厚みを越えるので余白を取らない）、ぶつかる物は `obstacles`（椅子・スクリーン・卓）
- **絵柄**: `MeshToonMaterial`（3段の平塗り、`toonGradient()`）＋反転した殻の輪郭線（`outline()`。一回り大きくした黒い裏面。太さ `OUTLINE` は 6cm、薄い物はいちばん薄い辺の3割まで）＋折れた辺の線（`EdgesGeometry`）＋地面の目地・板の線＋月の平行光（面ごとの段をはっきり分ける）＋霧（`Fog`）＋紙の粒子（CSS の重ね。8コマ／秒でずらす）。
  RYO-04 の試作は輪郭線 2.5cm・半球の光だけで、線と段が見えず写実に寄った（2026-11-03 の所見）。直した前後は `docs/logs/CHAT-1103-RYO-06/compare-before-after.png`。
  札・額・牌の面はカンバスに鉛筆風の枠と明朝で描く。人物は置かない。写真のパネル（線画・減色）は次の指示で
- **触れる**: 近く（4.2m 以内。大スクリーンは 18m）で前にある物の案内を下に出し、スクリーンは枠が暖色に光る。タップ・クリックで、最初に当たった物が触れられる物なら開く（壁越しは開かない）。キーボードは Enter・E で案内の出ている物を開く。
  スクリーン: YouTube は画面の前面に `youtube-nocookie.com/embed/...?autoplay=1`（触れたときに再生が始まる）、YouTube でない2本（ICU 同窓会・Amazon）は前面にサムネイル・題と、新しいタブで開くリンク。
  牌: 自己紹介・数字で見るの紙片が浮かぶ。点棒: 音だけ。卓の上の点数表・壁の貼り紙: 成績・成績詳細のページへふつうに移る（牌譜の紙は牌譜のページの廃止で物ごと外した、#673）（`RESULTS`。対局室から成績へつながる、2026-11-03 の決定。連盟プロの個別ページへのつなぎは pro/ の公開〈#641〉の後、#656）
- **操作**: スマホは左半分を押したところに出る仮想スティックで歩き、右半分のドラッグで見回す。PC は WASD・矢印・ドラッグ。Esc で前面を閉じる／空間を出る。空間を開いている間は外（一覧・共通ナビ）を `inert` にし、出ると移った場所の節の見出しへフォーカスを戻す。窓を離れるとキーを放し、タブを隠すと音を止める
- **メニュー**（右上「場所」）: 場所の一覧（`PLACES` の道順。一覧の目次は入口を除く2つを本文の並び〈`SECTION_ORDER`〉で出す）・空間を出て一覧で読む。場所を選ぶと 2.4 秒で浮いて移る（`goTo()`）
- **音**（右上「音」）: 風（低域のノイズを揺らす）と水音・雫が主（水辺に近い上映の場で水音が大きい）・対局室の低いうなり（中では風が遠い）・足音（床で石畳／砂利／板張りを変える）・牌と点棒の音・移るときの風切り。
  「入る」で鳴り始める（ブラウザが音を許すのは押した後だけ）。消した状態は `localStorage` の `mj:ryoei-sound`（JSON の真偽）。「保存データを消す」のリンクは作らず、右上の「音」で切り替えるだけ（2026-11-03 の決定）

## 場面の足し方

1. `World` に `build<場面>()` を足す。屋外は地面の長方形を `floors`（足音の材質）と `walkable` に足し、建物は `roomShell()` で作って、扉は壁の `gaps` と `doors` に同じ範囲を入れる（同じ面に壁を2枚置かない。ちらつく）。屋外の `walkable` は建物を避けるように重ねて足す（境目に隙間を作らない）
2. `addPlace('<id>', x, z, yaw)` で着く位置を決め、`roomAt()` に場所の判定を足す
3. `scripts/generate_ryoei_pages.py` の `PLACES` に `(id, 一覧の目次の名前, 空間のメニューの名前, 一覧の節の id)` を足す（メニューと一覧の目次に出る）
4. 光は少なく保つ（点光源は場面ごとに1〜2個。すべての光がすべての面の計算に入るので、増やすとスマホで重くなる）

## 重さ（2026-11-03、屋外の版）

- 最初の画面（HTML・CSS・JS、gzip）: 約137KB（上限 600KB）。Three.js（gzip 約170KB）は「入る」を押してから読み、入った後の合計は約307KB
- `world.js`: 約53KB（上限 150KB、Three.js を除く r/ 専用の JS）
- 描画: headless Chrome（ソフトウェア描画 SwiftShader、2倍の解像度）で約20fps。GPU のある端末の目安にはならない。iPhone での実測は平野さんの確かめ
- 光: 半球1・月の平行光1・街灯の点光源2・対局室のスポット1（場面を足すときも増やしすぎない）
- 計り方: 作業ログの「重さ」（gzip は Python の `gzip.compress`）
