# 候補の調べもの（research-candidates）

Claude API の Web 検索・Web 取得で、平野さんの手作業の調べものを「出典付きの候補」に置き換える仕組み（CHAT-1029-RSC-01 の設計、CHAT-1031-RSC-02 で実装）。
候補は R_候補 の「候補」タブに足すだけで、本体のタブ（「連盟プロ以外」「最強戦」「タイトル」）に入れるのは今どおり平野さん。決定は docs/decisions/automation.md。

## 部品

| もの | 役目 |
|---|---|
| `scripts/research_candidates.py` | 種別ごとの対象の一覧・プロンプト・照合と、費用の上限・候補タブへの追記 |
| `scripts/lib/candidates_book.py` | R_候補 の ID・タブ名・見出し。ID はログ・issue・コミットメッセージに書かない |
| `.github/workflows/research-candidates.yml` | 手動実行（既定は dry-run）と、毎朝 `run-daily.yml` のジョブ `sokuho` からの `workflow_call`（D だけ） |
| R_候補（ブック） | 専用フォルダ「【本番環境】」。`live-channel-writer` が編集者（書く）、`sheets-reader` はフォルダの閲覧者（`check-sheets-reader.yml` で確かめる） |

書き込み先は `scripts/lib/sheets_write.py` の `WRITABLE` に「候補」タブだけを足してある。

## 1件の調べ方

- Messages API に、`web_search`（基本の版、`max_uses` 2〈入力 `max_uses` で 1〜10 に変えられる。検索・取得とも同じ値、CHAT-1113-RSC-14〉、日本の位置）・`web_fetch`（基本の版、`max_uses` 2、citations 有効、本文は 8,000 トークンまで）と、答えを返すクライアント側のツール `submit_candidate`（`strict`）を渡す。`tool_choice` は `auto` で、プロンプトで最後に呼ばせる（Sonnet 5.5 は強制の指定が 400）
- A は web_search・web_fetch の両方とも `blocked_domains` で ryoei.pro（www. を含む）を外す（このサイト自身は循環する出典になるため、2026-10-31 の決定）
- B は両方とも `allowed_domains` で mahjong-saikyosen.com・mahjong-saikyosen.jimdoweb.com（2013年ごろの旧公式）・kinmaweb.jp・times.abema.tv に絞る（2026-10-31 の決定）。`allowed_domains` と `blocked_domains` は同時に使えないが、ryoei.pro はこの4つに入らないので外れる
- B の `submit_candidate` は 4人の名前と順位（`ranks`）・出典・引用文を返す。記事が通過・敗退だけで4人の順位が分からなければ「見つからない」
- B は卓ごとに呼ぶ（卓ごとにすることは 2026-10-31 の決定）。同じ記事を卓どうしで使い回す仕組みは持たず、同じ対局の記事を卓の数だけ読む（コードの `簡略化:` の行）
- 動的フィルタの版（`_20260209` 以降）を使わないのは、結果のブロックがそのまま返り、コードで出典を照合できるため（コードの `簡略化:` の行）
- `pause_turn` なら続きを送り、答えが無ければ「検索・取得はせずに答える」よう催促する。`tools` は全要求で同じにする（変えると前の thinking のブロックの照合に当たりうる）。1対象 最大3要求
- 答えは structured outputs にしない（Web 検索の citations との組み合わせが公式に書かれていないため）

## 確度（コードの照合）

| 確度 | 条件 |
|---|---|
| 照合済み | 出典の URL を同じ会話の `web_fetch` で取っていて、引用文がその本文にあり、引用文に名前と読みがある（NFKC・空白を除き、カタカナはひらがなに揃えて比べる。名前の直後に漢字が続く箇所は数えない〈「小川光」と「小川光太郎」〉。名前の字の間の空白は許す。読みは部分一致なので、読みの一部だけでも照合済みになりうる） |
| 未照合 | 候補はあるが上の条件のどれかに合わない。理由は「備考」（本文に無い・名前が無い・読みが無い・`abema.tv`）。出典が検索結果の抜粋（ページを開けない、または開いた本文には無く抜粋にある）の候補もここで、備考は「検索結果の抜粋（コードでは本文を確かめられない…）: 」の後にモデルの説明か、名前・読みが無い理由。抜粋の候補でも名前・読みが抜粋にあるかは確かめる（2026-10-31 の決定） |
| 見つからない | `submit_candidate` の `found` が偽、または呼ばれなかった |

名前は姓だけでもよい（2026-11-04 の決定、A・B とも）: 引用文に名前が無くても、名前の先頭の漢字だけの部分（2字以上）が引用文にあり、前に漢字が無く、後ろに漢字・かな・英数字が続かず、卓のほかの人の名前の先頭と重ならなければ、名前ありとみなす（`missing_names()`）。2字の名前・かなや英字で始まる名前は完全一致だけ。同じ卓に同じ姓の2人（「佐々木」など）がいるときは、先頭が重なるので完全一致だけになる。姓の長さは分からないので先頭の部分で見る（コードの `簡略化:` の行）

C の照合（同じく）: 候補の日付が `YYYY-MM-DD` の実在する日で、年がシートの年と1年を超えてずれない（シートの年は公式HPの年度を暦年とみなした仮の値で、決勝が1〜3月なら1年ずれる。シートの月〈`YYYY-MM-XX`〉は予定の値で前後するため見ない）。合えば、出典の引用文に月日（「5月26日」「5/26」「2013-05-26」など。複数日の「5月25日・26日」「7月16日から20日」は後ろの日〈最終日〉だけ。同じ月日に違う西暦が付いていれば無いとみなす）・大会名（改称前の名前も可、`lib/taikai_names.py`）・期（「第30期」）があるかを照合する。年は引用文に無くてもよい・記事の別の大会名の書き方（「鳳凰位決定戦」など）と漢数字は未照合に倒れる（コードの `簡略化:` の行）

B の照合（上の表の「名前と読み」の代わり）: 候補の4人が卓の4人と完全一致（「別名」で直した現在名）、順位が1〜4位を1つずつ、通過の人が敗退の人より上位、シートに順位がある人はそれと同じ。どれかに合わなければ未照合で、理由を備考に書く。合えば、出典の引用文に4人の名前があるかを A と同じ形で照合する。引用文の中の順位の書き方（「1位」「トップ」・点数の並び）は確かめない（コードの `簡略化:` の行）。名前は「別名」で直した現在名で照らすので、改名した人の当時の名前だけが書かれた記事は未照合になる（同じく `簡略化:`）

## B の旧公式の結果一覧（`source=official`）

API を使わず、最強戦の旧公式サイト（mahjong-saikyosen.jimdoweb.com、Copyright TAKESHOBO。#469 の許可に入るとみなす、2026-11-04 の決定）の結果一覧から卓の順位を当てる（CHAT-1104-RSC-06）。

- 読むのは 2019〜2021年度の3ページ（`/broadcast/2019/`・`/broadcast/2020/`・`/broadcast/`）だけ。2018年度以前のページには順位が無い（CHAT-1104-RSC-05 で調べた）。robots.txt を読み、禁じられていれば止める。ページの間は Crawl-Delay（5秒）あける。UA は `mj-internal research (ryoei.pro)`
- 各ページの「対局結果」から下の「1位:名前 2位:名前 3位:名前 4位:名前」の行（各対局の決勝と、2020 のファイナル1st の卓）を読む
- 当て方: 同じ年度で4人の名前（NFKC・空白を除く）がそろう行を先に探し、無ければ3人がそろい残りの1人どうしが同じ字数で1字だけ違う行（表記の揺れ）を探す。4人そろい、順位がシートの結果（通過・敗退）と食い違わなければ照合済み。揺れ・食い違いは未照合で候補タブに書き、備考に理由を書く（「旧公式の表記の揺れ: 斎藤敬輔(シート: 齋藤敬輔)」「順位がシートの結果(通過・敗退)と食い違う」）
- 候補タブの行は、モデルの列が「旧公式」、費用 0、出典は年度のページの URL、引用文は「日付 対局名 / 1位:…」の形。旧公式の行がある卓は、API の実行でも飛ばす
- `source=official` では `targets`・`limit`・`model`・`max_cost` を使わない（当たる卓をすべて書く）。dry-run でも robots.txt と3ページを読む（費用は無い）。Crawl-Delay が60秒を超える・HTTP 200 以外なら止まる
- 入力 `years` で年度を絞れる（API の実行で、旧公式に無い 2019〜2021年度の予選の卓だけを調べるときなど）
- 入力 `skip_found` で、どれかのモデル（旧公式を含む）が候補（照合済み・未照合、状態が却下でない）を出した対象を飛ばす（ほかのモデルで調べ直さない。種別を問わない、CHAT-1113-RSC-14）。飛ばさないと、ほかのモデルの行は同じ（種別, 対象キー, モデル）にならないので調べ直す

## D のテキスト速報（API を使わない）

最強戦の対局の後、キンマweb（竹書房の運営。#469 の許可の内とみなす、2026-11-04 の決定）のテキスト速報から卓の順位・結果を読む。毎朝 `run-daily.yml` のジョブ `sokuho` から動く（手動実行もできる）。記事の作りは CHAT-1104-RSC-09 のログ。

- 新しい速報: カテゴリの RSS（`/archives/category/mahjong-championship/feed`、2ページ目まで）のうち、カテゴリ「テキスト速報」で公開から `lookback_hours`（既定 30時間。毎朝 04:00 の起動で前の朝の後に出たもの）以内の記事。**無ければ「最強戦」も候補タブも読まずに終わる**（Sheets API の読み取りを増やさない、#662）。あれば記事を読んで候補タブを読み、どれも候補タブに行がある（前の朝に書いた）なら「最強戦」は読まずに終わる。残れば「最強戦」を読む。読んだ記事の記録は候補タブの行（対象キー＝URL、モデル「速報」）で、同じ記事は二度書かない。毎朝の起動が止まった日は、手動実行で `lookback_hours` を広げて拾う
- robots.txt を読み、禁じられていれば止める。記事の間は3秒あける。UA は旧公式と同じ `mj-internal research (ryoei.pro)`。1回に新しい速報が12本を超えたら止める（RSS の取り違えの疑い）。キンマweb が読めない日（HTTP 200 以外・RSS が XML でない）はジョブ `sokuho` が失敗し、run-daily 全体も failure になる（ほかの本と同じ扱い。ほかの本と `logs` は動く）
- 読み方: 題「【麻雀最強戦YYYY <対局名> <A卓戦|B卓戦|決勝戦>】テキスト速報」の記事の、冒頭の席順（「東家：内川幸太郎」…）と「試合結果」の行（「内川：20600　小川：24700　たろう：32600　小林：22100」。略称だが席順と同じ並び、マイナスは「▲」）。点数の順に順位を付け、予選は上位2人が通過・ほかは敗退、決勝は1位が優勝・ほかは敗退。題がこの形でない速報（全日本プロ選手権・アマチュア・ファイナルなど）は「見つからない」で書く（形を見てから足す、2026-11-04 の決定。コードの `簡略化:` の行）
- 照合済みの条件: 点数が4つ読め、試合結果の略称が同じ位置の席の名前に含まれ（「たろう」は「鈴木たろう」）、合計が100,000以下で100点単位、同点が無い。予選は試合結果の前の「○・○が勝ち上がり」（「の勝ち上がり」も）の2人が点数の上位2人と同じ。予選の卓は「最強戦」（表示=Y、`generate_saikyo_pages.load_rows()` で「別名」を通した現在名）の同じ年度・対局名・卓の4人が速報の席順にある（姓だけの照合は A・B と同じ `missing_names()`）、シートにすでにある順位・結果と同じ。決勝の卓は、同じ実行で読んだ予選2卓の通過者4人と同じ（結果記事の「1位：…」は読まない。コードの `簡略化:` の行。シートには決勝の行が無いので、平野さんが候補を見て4行を足す、2026-11-04 の決定）。合わなければ未照合で、理由を備考に書く
- 記事の名前は「別名」で直さない（旧名で書かれた記事は未照合に倒れる。`scripts/check_unused_names.py` の表に載せる処理を足さないため、2026-11-04 の決定）
- 費用は 0（Claude API を使わない）。候補タブの「費用」は 0、「モデル」は「速報」

## 候補タブ

見出し: 種別／対象キー／対象／候補／確度／出典URL／引用文／調べた日時／モデル／費用／状態／備考。空のタブには最初の実行で見出しを書く。見出しが違えば止まる。

- 追記だけ。同じ（種別, 対象キー, モデル）の行があれば飛ばす。入力 `recheck` のときは、どの行も「状態が却下」か「確度が見つからない」の組を調べ直す（古い行は残し、新しい行を足す）
- 「状態」は平野さんが「採用」「却下」を書く（機械は空で書く）

## 費用

- 単価は pricing（2026-10-29）: Haiku 5.5 入力 $0.10・出力 $0.50（プロンプト10万トークン超は $0.50・$2.50）、Sonnet 5.5 $2・$10、Opus 5.5 $4・$20（キャッシュ読み取りは 0.05倍。https://platform.claude.com/docs/en/about-claude/pricing 、2026-11-13 に確かめた。Opus 5.5 にプロンプトの長さによる単価の違いは無い）。Web 検索 1回 $0.01、Web 取得は追加料金なし
- 呼ぶ前に「使った額＋次の要求の最大の見込み」が上限を超えるなら呼ばずに止める（終了コード 1）。見込みは、1要求目が入力 12万（入力 `max_uses` を変えたときは、サーバー側の繰り返しが毎回それまでの結果を読み直すので回数の2乗に比例させる。4回なら 48万、Opus 5.5 で1要求 約 $2.28）・出力 16,000（Opus 5.5 は thinking を止められないので、2026-11-13 に 6,000 から上げた） トークン・検索 `max_uses` 回（既定 2）。2要求目からは、前の要求の入力の合計（サーバー側の繰り返しの分を含む）＋16,000＋1,000（催促の文）に、1要求目と同じ入力・検索の見込みを足したもの。呼んだ後は `usage` で実額を足す
- 途中で止めた対象は候補タブに書かない（費用は実額に入り、実行サマリに対象名が出る）
- 上限は入力 `max_cost`（既定 $1、定数 `MAX_COST_LIMIT` $5 を超えられない）。キーは共有の `ANTHROPIC_API_KEY`（Default のワークスペース。道場部ゲスト・X 投稿の変換と同じ残高）

## 動かし方

1. https://github.com/retroeater/mj/actions/workflows/research-candidates.yml の「Run workflow」（ブランチは `cloudflare`）。Claude Code は `actions_run_trigger`
2. まず `dry_run` のまま、対象・プロンプトの字数・見込みと、候補タブの見出しの状態を実行サマリで見る
3. `dry_run` を外すと、API を呼んで候補タブに1件ずつ足す。実行サマリに結果の表と実額・トークン数・検索回数が出る
