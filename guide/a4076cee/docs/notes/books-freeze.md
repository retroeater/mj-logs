## 調査結果の要点

### 書影の出所の比較（`CHAT-0921-BK-01.md`）

| 候補 | 結果 |
|---|---|
| 国立国会図書館サーチの書影API | 2026-03-31 でサービス終了 |
| Amazon Creators API | 過去30日に適格販売10件以上が常時必要。書影の自前配信も不可（URL保存24時間まで） |
| 楽天ブックス書籍検索API | **採用。** 登録は無料、書影URLをそのまま参照でき、保存期間3か月 |
| openBD | 書影が無い巻が多く候補から外れた |

### 楽天の規約（`docs/notes/books-covers.md`「規約上の制約」に詳細）

- クレジット表記必須（配布HTMLの改変不可）、書影を出すページには楽天ブックスの商品ページへのリンク必須
- 画像は加工しない（`largeImageUrl`、長辺200pxのまま）。自サイトへのコピーもしない
- 保存は「その他の情報」として3か月まで（価格・在庫は出していないためこちらに該当）
- OGP（`og:image`）での利用は規約に直接の記述が無く、未解決の論点が残っていた（`CHAT-0922-BP-01.md`手順2(g)）。
  凍結により当面は判断不要

### 著者の照合

- 「プロ」「連盟プロ以外」「別名」のどこにも見つからない著者が**11名**、凍結まで解消しなかった
  （ASAPIN・独歩・RUKO・こいで・因幡はねる・新倉和花・木村尚嵩・木村由佳・渋谷ハル・神尾亮・竹内隆之）
- 楽天ブックス書籍検索APIの`author`フィールドで、シートの単著者表記と食い違う（楽天側が複数著者を返す）本が**29冊**見つかった
  （`CHAT-0922-BP-01.md`手順2(f)）。今回の「著者・監修」列への改名・複数名反映で解消したかは未確認
  （凍結によりこのセッションでは確かめていない）

## 楽天の期限

**楽天の規約は「その他の情報」（価格・在庫以外）を3か月まで保存できる。** `books/` に焼き込まれている
書影URL・楽天ブックスへのリンクと、`data/rakuten_books.json` が対象。

- 最後に楽天から取得した日: **2026-09-22**（JST）
  - 根拠: `data/rakuten_books.json` の最終コミット `87f060bd`（2026-09-22T01:47:04+09:00、
    `requested: 190 → found: 123` と中身が変わっており、実際に API から取り直した内容と確認）。
    直前の GitHub Actions 経由の取得（`regenerate-page.yml`、run 35618044147、2026-09-21T15:23:48Z 完了）より後
- **期限: 2026-12-22**（3か月後）
- 期限までに再取得しない場合、`books/` の書影・楽天ブックスへのリンクと `data/rakuten_books.json` は
  この期限を過ぎて保存し続けることになる。凍結を続けるなら、期限前に削除するか、再取得（自動実行の再開）が要る
- handover.md「5. 次にやること」の期限付きタスク表と #97 のコメントに同じ期限を書いた

## 再開するときに戻す手順

1. 「書籍」タブの現在の列名・行数に `scripts/generate_books_pages.py` の `BOOK_HEADERS`・
   `MIN_BOOKS`/`MAX_BOOKS`（現行150〜300。凍結時点で95行のため、絞り込み後の行数に合わせて見直しが要る）を合わせる。
   `著者`→`著者・監修` の列名変更も反映する
2. `scripts/sync_books_calendar.py` も同じ列名を読むため、合わせて直す（`--delete-all` は凍結解除後は使わない想定。
   残すか消すかは再開時に判断）
3. `.github/workflows/regenerate-page.yml`「楽天の書影を取得」ステップの `if: false` を、コメントに残した元の条件に戻す
4. `scripts/regenerate.py` の `FROZEN_FROM_ALL` から `books_pages` を外す（または定数ごと削除する）
5. `gh workflow enable 書籍カレンダーの同期`（`sync-books-calendar.yml`）で再開する（再開する場合のみ。
   独立ページを作らない決定のため、カレンダー同期自体を続けるかは要判断）
6. 2026-12-22 を過ぎている場合は、生成・同期の前に `scripts/fetch_rakuten_books.py` を実行して
   書影URLを取り直す（3か月ルールを満たすため）
7. 選手個人ページ（#219、新サイト）の書籍セクションで `data/rakuten_books.json` を流用する場合は、
   上記1〜4は不要（`books/` の生成自体を再開しないため）。
   ただし書影URLの3か月ルールは同様に効くため、期限（2026-12-22）を過ぎたら再取得すること
