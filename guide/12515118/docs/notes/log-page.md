# 「ログ」のページ `log/`（検索の候補とタグ・駅名・現在地から探す）

「ログ」（麻雀プロが訪れた飲食店の X の投稿）のページ `log/` の仕様。作る issue は #639、公開は #640（旧ページ `resource_logs.html` は `log/` へ 301、生成はやめた）。
決定は docs/decisions/operations.md の 2026-10-28〜31（CHAT-1028-LGN-01〜CHAT-1031-LGN-10）の節。2026-10-29 に、Google の規約に合わせたデータ（Places は place_id だけ、駅・都道府県は国土数値情報、LGN-04〜08）の上に作り直した（LGN-09）。ここには決定を画面・データに落とした仕様を書く。
下の「仮置きの一覧」は、平野さんがプレビューで確かめるまでの仮の形。

## 目的

- 表・時系列の一覧をやめ、トップの検索を主な導線にする（2026-10-28 の決定）
- houou/ の個人成績（`houou/players/`）と同じ見た目（幅 400px・新サイトの基本の形・検索欄）にする
- 検索の候補（駅・投稿者・店名・投稿年・ジャンル・都道府県）とタグで絞る。現在地から探す（#378）を入れる
- 検索用のデータを分けて、表の全件をページに焼き込まない（`resource_logs.html` は 2.1MB・DOM 要素数の問題、#255）
- 谷岡育夫の再投稿（過去メシ）と、石立岳大の投稿は出さない（2026-10-29・31 の決定）。閉業の店は毎月1日に自動で外す（2026-11-04 の決定、#664。ページに出るのは次の log/ の再生成の後。下の「データの持ち方」）
- Google から保存するのは place_id だけ。座標・営業状況・ジャンルは Google の値を使わない（2026-10-29 の決定、docs/notes/log-stations.md）

## データの持ち方

- 店の鍵は place_id。place_id が空の行は「p<投稿ID>」で1投稿を1店にする（名寄せは place_id だけ、2026-10-28 の決定）
- 店の URL（2026-11-04 の決定。前の `https://www.google.com/maps/place/?q=place_id:…` は iPhone の Google マップのアプリで「一致する検索結果はありません」になった）: place_id があり「店URL」が空か前の形なら、Maps URLs の search の形 `https://www.google.com/maps/search/?api=1&query=<店名>&query_place_id=<place_id>` に組み立て直す（`generate_log_pages.py` の `shop_link()`・`lib/url.py` の `maps_url()`。query は place ID が見つからないときにだけ使われる。アプリが入っていればアプリで開く）。旧「ログ」の共有リンク（`maps.app.goo.gl`・`goo.gl`）・【3】の手書きの URL・place_id の無い行は今のまま。変換（`convert_x_posts.py`）も新しい行の「店URL」をこの形で書く（既存の【2】の値は書き換えず、生成のときに組み立て直す）
- 店の店名・店の URL・ジャンルは、その値を持つ最も新しい投稿のもの。駅・駅の候補・駅の座標・都道府県・突き合わせ用の駅は、駅を持つ最も新しい1件の投稿からまとめて取る（突き合わせ用の駅は一覧の名前。市ケ谷 → 市ヶ谷）。【県】の印も東京都の駅も無く選び切れない同じ名前の駅は、一覧に無い駅と同じに扱う
- カテゴリ（place_id があり「（店名非公開）」でない店だけ）: 新着は最初の投稿の日付の新しい順、投稿回数の多い店は投稿2件以上で多い順（同じなら新しい順）
- 外す店（#664、2026-11-04 の決定）: 3層の「閉業」シート（列は `place_id` だけ）にある place_id の店は出さない（`generate_log_pages.py` の `drop_closed`。外した店の数を生成のログに出す。シートが無い・空なら何も外さない）。シートは `convert_x_posts.py --mode closed` が毎月1日 02:00 JST（`run-monthly.yml`）に丸ごと書き直す: 外す前の log/ の店（【2】を【3】で直し、飲食店・表示 Y、石立岳大・過去メシを除く。`shown_pairs`）の place_id ごとに Place Details（項目は `businessStatus` だけ）を呼び、`CLOSED_PERMANENTLY` の店だけを書く（臨時休業・見つからない place_id は外さない。再開した店は翌月に戻る）。営業状況そのものは保存しない。上限は1回 2,500回・1分 500回まで。上限・Places の失敗・外す店か見つからない place_id（HTTP 404・400）が対象の 10% を超えるときは書かない。出力は件数だけ。出力（止めたときも）に、そこまで Place Details を呼んだ回数（失敗した要求・繰り返しを含む）を出す（2026-11-04 の決定、CHAT-1104-LGN-31）。運用の注意: 1回の判定は約 1,700回呼ぶ。GetPlace の1日の割り当てと月の無料の枠（値は docs/notes/google-cloud.md）のため、失敗した実行を同じ日・同じ月にやり直す前に、Google Cloud の割り当てと指標の画面で使った回数を確かめる（2026-11-04 は1日の割り当てに届いて止まった）。【1】【2】【3】には書かない
- 「ジャンル」: Claude が付ける【2】の列（後の指示）。列が無い・空の間は、どの店もジャンルなし（ジャンルの候補が出ない）
- `log/search.json`: `{"people": [人の名前…], "shops": [店…], "prefs": {駅名: 都道府県}, "areas": {駅名: 地名}}`（areas は海外の駅〈都道府県の分からない【…】付き〉だけ。prefs は東京都の外の駅だけ。同じ名前で2つ以上の都道府県の駅〈府中: 東京都・広島県〉は付けない〈簡略化。カードは「府中（広島県）」、候補・タグは「府中」。この出方でよいと 2026-11-01 に決定〉）。店の1件は `[鍵, 店名, 駅, 店の URL, 緯度, 経度, [[駅の候補, m], …], [投稿…], 突き合わせ用の駅, ジャンル, 都道府県]`（緯度・経度は店の駅の点〈国土数値情報〉で、駅が一覧に無ければ null。駅の候補は駅どうしの距離。突き合わせ用の駅は【県】を除いた名前）、投稿の1件は `[人の番号, 日付, メニュー, X の URL, 画像の URL, 店名（店の名前と同じなら空）]`。URL は http・https だけ（`lib/url.py` の `safe_url()`）
- 検索用のデータは、検索欄に触れたとき・探す・絞る・店を開くときに初めて読む

## URL パラメータ

`tag`（検索語）・`station`（駅）・`name`（投稿者。完全一致）・`store`（店名）・`year`（投稿年、西暦4桁）・`genre`（ジャンル）・`pref`（都道府県）・`shop`（店の鍵）。タグの種類ごとに1つで、組み合わせてよい（例 `?station=神保町&name=谷岡育夫`）。LGN-02 の `?name=`・`?station=`・`?shop=` はそのまま読める。表は docs/new-page-checklist.md「URL パラメータの規約」
