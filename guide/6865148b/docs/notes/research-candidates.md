# 候補の調べもの（research-candidates）

Claude API の Web 検索・Web 取得で、平野さんの手作業の調べものを「出典付きの候補」に置き換える仕組み（CHAT-1029-RSC-01 の設計、CHAT-1031-RSC-02 で実装）。
候補は R_候補 の「候補」タブに足すだけで、本体のタブ（「連盟プロ以外」「最強戦」「タイトル」）に入れるのは今どおり平野さん。決定は docs/decisions/automation.md。

## 部品

| もの | 役目 |
|---|---|
| `scripts/research_candidates.py` | 種別ごとの対象の一覧・プロンプト・照合と、費用の上限・候補タブへの追記 |
| `scripts/lib/candidates_book.py` | R_候補 の ID・タブ名・見出し。ID はログ・issue・コミットメッセージに書かない |
| `.github/workflows/research-candidates.yml` | 手動実行だけ。既定は dry-run |
| R_候補（ブック） | 専用フォルダ「【本番環境】」。`live-channel-writer` が編集者（書く）、`sheets-reader` はフォルダの閲覧者（`check-sheets-reader.yml` で確かめる） |

書き込み先は `scripts/lib/sheets_write.py` の `WRITABLE` に「候補」タブだけを足してある。

## 1件の調べ方

- Messages API に、`web_search`（基本の版、`max_uses` 2、日本の位置）・`web_fetch`（基本の版、`max_uses` 2、citations 有効、本文は 8,000 トークンまで）と、答えを返すクライアント側のツール `submit_candidate`（`strict`）を渡す。`tool_choice` は `auto` で、プロンプトで最後に呼ばせる（Sonnet 5.5 は強制の指定が 400）
- A は web_search・web_fetch の両方とも `blocked_domains` で ryoei.pro（www. を含む）を外す（このサイト自身は循環する出典になるため、2026-10-31 の決定）
- B は両方とも `allowed_domains` で mahjong-saikyosen.com・mahjong-saikyosen.jimdoweb.com（2013年ごろの旧公式）・kinmaweb.jp・times.abema.tv に絞る（2026-10-31 の決定）。`allowed_domains` と `blocked_domains` は同時に使えないが、ryoei.pro はこの4つに入らないので外れる
- B の `submit_candidate` は 4人の名前と順位（`ranks`）・出典・引用文を返す。記事が通過・敗退だけで4人の順位が分からなければ「見つからない」
- B は卓ごとに呼ぶ（卓ごとにすることは 2026-10-31 の決定）。同じ記事を卓どうしで使い回す仕組みは持たず、同じ対局の記事を卓の数だけ読む（コードの `簡略化:` の行）
- 動的フィルタの版（`_20260209` 以降）を使わないのは、結果のブロックがそのまま返り、コードで出典を照合できるため（コードの `簡略化:` の行）
- `pause_turn` なら続きを送り、答えが無ければ「検索・取得はせずに答える」よう催促する。`tools` は全要求で同じにする（変えると前の thinking のブロックの照合に当たりうる）。1対象 最大3要求
- 答えは structured outputs にしない（Web 検索の citations との組み合わせが公式に書かれていないため）

## 確度（コードの照合）

| 確度 | 条件 |
|---|---|
| 照合済み | 出典の URL を同じ会話の `web_fetch` で取っていて、引用文がその本文にあり、引用文に名前と読みがある（NFKC・空白を除き、カタカナはひらがなに揃えて比べる。名前の直後に漢字が続く箇所は数えない〈「小川光」と「小川光太郎」〉。名前の字の間の空白は許す。読みは部分一致なので、読みの一部だけでも照合済みになりうる） |
| 未照合 | 候補はあるが上の条件のどれかに合わない。理由は「備考」（本文に無い・名前が無い・読みが無い・`abema.tv`）。出典が検索結果の抜粋（ページを開けない、または開いた本文には無く抜粋にある）の候補もここで、備考は「検索結果の抜粋（コードでは本文を確かめられない…）: 」の後にモデルの説明か、名前・読みが無い理由。抜粋の候補でも名前・読みが抜粋にあるかは確かめる（2026-10-31 の決定） |
| 見つからない | `submit_candidate` の `found` が偽、または呼ばれなかった |

B の照合（上の表の「名前と読み」の代わり）: 候補の4人が卓の4人と完全一致（「別名」で直した現在名）、順位が1〜4位を1つずつ、通過の人が敗退の人より上位、シートに順位がある人はそれと同じ。どれかに合わなければ未照合で、理由を備考に書く。合えば、出典の引用文に4人の名前があるかを A と同じ形で照合する。引用文の中の順位の書き方（「1位」「トップ」・点数の並び）は確かめない（コードの `簡略化:` の行）。名前は「別名」で直した現在名で照らすので、改名した人の当時の名前だけが書かれた記事は未照合になる（同じく `簡略化:`）

## 候補タブ

見出し: 種別／対象キー／対象／候補／確度／出典URL／引用文／調べた日時／モデル／費用／状態／備考。空のタブには最初の実行で見出しを書く。見出しが違えば止まる。

- 追記だけ。同じ（種別, 対象キー, モデル）の行があれば飛ばす。入力 `recheck` のときは、どの行も「状態が却下」か「確度が見つからない」の組を調べ直す（古い行は残し、新しい行を足す）
- 「状態」は平野さんが「採用」「却下」を書く（機械は空で書く）

## 費用

- 単価は pricing（2026-10-29）: Haiku 5.5 入力 $0.10・出力 $0.50（プロンプト10万トークン超は $0.50・$2.50）、Sonnet 5.5 $2・$10。Web 検索 1回 $0.01、Web 取得は追加料金なし
- 呼ぶ前に「使った額＋次の要求の最大の見込み」が上限を超えるなら呼ばずに止める（終了コード 1）。見込みは、1要求目が入力 12万・出力 6,000 トークン・検索2回。2要求目からは、前の要求の入力の合計（サーバー側の繰り返しの分を含む）＋6,000＋1,000（催促の文）に、1要求目と同じ 12万・検索2回を足したもの。呼んだ後は `usage` で実額を足す
- 途中で止めた対象は候補タブに書かない（費用は実額に入り、実行サマリに対象名が出る）
- 上限は入力 `max_cost`（既定 $1、定数 `MAX_COST_LIMIT` $5 を超えられない）。キーは共有の `ANTHROPIC_API_KEY`（Default のワークスペース。道場部ゲスト・X 投稿の変換と同じ残高）

## 動かし方

1. https://github.com/retroeater/mj/actions/workflows/research-candidates.yml の「Run workflow」（ブランチは `cloudflare`）。Claude Code は `actions_run_trigger`
2. まず `dry_run` のまま、対象・プロンプトの字数・見込みと、候補タブの見出しの状態を実行サマリで見る
3. `dry_run` を外すと、API を呼んで候補タブに1件ずつ足す。実行サマリに結果の表と実額・トークン数・検索回数が出る
