「ログ」（麻雀プロが訪れた飲食店の X の投稿、今は `resource_logs.html`）を `log/` に作り直す仕様。作る issue は #639、公開は #640。

## 目的

- houou/ の個人成績（`houou/players/`）と同じ見た目（幅 400px・新サイトの基本の形・検索欄）にする

- 検索用のデータを分けて、表の全件をページに焼き込まない（`resource_logs.html` は 2.1MB・DOM 要素数の問題、#255）

- h1「ログ」（見出しの下の店の数は 2026-11-04 にやめた）。説明文（`.mj-lead`、ページの下）は description と同じ文で、店の数と投稿の件数を「飲食店1,734店（2,430件）」の形で含める（2026-11-04 の決定。数は生成のときの数）。title は「ログ | ryoei.pro」（数を入れない）

- 検索の候補: 打った語に合う値を、種類ごとに先頭一致 → 部分一致で3件まで、駅・投稿者・店名・投稿年・ジャンル・都道府県の順に出す。1行は「駅　茗荷谷　…　43店」（種類〈幅をそろえる〉・名前〈左寄せ〉・右端に店数。読み上げも「駅 茗荷谷 43店」の順、2026-10-31 の決定）。東京都の外の駅は「西千葉（千葉県）」と出す（突き合わせは駅名だけ。「千葉」と打っても千葉県の駅は全部は出ない）。店数は今のタグとその候補を合わせて絞ったときの店の数で、0店の候補と、選んでいる種類の候補は出さない（タグで絞っている間も同じ。「×2026年」で「平野」と打っても、平野良栄の 2026年の投稿が無ければ候補は出ない。2026-11-01 のデータでは0件）
- タグ: 候補を選ぶと検索欄の下に「×茗荷谷」のタグ（東京都の外の駅は「×西千葉（千葉県）」）で固定し、検索欄を空にする。タグは種類ごとに1つ（同じ種類を選び直すと置き換わる）で、種類の違うタグと検索欄の語は AND で絞る。× で外れる。カテゴリのカードから開いた店（`?shop=`）と現在地も「×店名」「×現在地」のタグになる

## データの持ち方

- 店の鍵は place_id。place_id が空の行は「p<投稿ID>」で1投稿を1店にする（名寄せは place_id だけ、2026-10-28 の決定）
- 店の店名・店の URL・ジャンルは、その値を持つ最も新しい投稿のもの。駅・駅の候補・駅の座標・都道府県・突き合わせ用の駅は、駅を持つ最も新しい1件の投稿からまとめて取る（突き合わせ用の駅は一覧の名前。市ケ谷 → 市ヶ谷）。【県】の印も東京都の駅も無く選び切れない同じ名前の駅は、一覧に無い駅と同じに扱う
- カテゴリ（place_id があり「（店名非公開）」でない店だけ）: 新着は最初の投稿の日付の新しい順、投稿回数の多い店は投稿2件以上で多い順（同じなら新しい順）
- 「ジャンル」: Claude が付ける【2】の列（後の指示）。列が無い・空の間は、どの店もジャンルなし（ジャンルの候補が出ない）
- `log/search.json`: `{"people": [人の名前…], "shops": [店…], "prefs": {駅名: 都道府県}, "areas": {駅名: 地名}}`（areas は海外の駅〈都道府県の分からない【…】付き〉だけ。prefs は東京都の外の駅だけ。同じ名前で2つ以上の都道府県の駅〈府中: 東京都・広島県〉は付けない〈簡略化。カードは「府中（広島県）」、候補・タグは「府中」。この出方でよいと 2026-11-01 に決定〉）。店の1件は `[鍵, 店名, 駅, 店の URL, 緯度, 経度, [[駅の候補, m], …], [投稿…], 突き合わせ用の駅, ジャンル, 都道府県]`（緯度・経度は店の駅の点〈国土数値情報〉で、駅が一覧に無ければ null。駅の候補は駅どうしの距離。突き合わせ用の駅は【県】を除いた名前）、投稿の1件は `[人の番号, 日付, メニュー, X の URL, 画像の URL, 店名（店の名前と同じなら空）]`。URL は http・https だけ（`lib/url.py` の `safe_url()`）
- 検索用のデータは、検索欄に触れたとき・探す・絞る・店を開くときに初めて読む

## URL パラメータ

`tag`（検索語）・`station`（駅）・`name`（投稿者。完全一致）・`store`（店名）・`year`（投稿年、西暦4桁）・`genre`（ジャンル）・`pref`（都道府県）・`shop`（店の鍵）。タグの種類ごとに1つで、組み合わせてよい（例 `?station=神保町&name=谷岡育夫`）。LGN-02 の `?name=`・`?station=`・`?shop=` はそのまま読める。表は docs/new-page-checklist.md「URL パラメータの規約」

## 仮置きの一覧（平野さんがプレビューで確かめる）

- カテゴリの1行は10店
- 新着は最初の投稿の日付、投稿回数の多い店は投稿2件以上
- 説明文はページの下の今の位置（`.mj-lead`）のまま、文は「日本プロ麻雀連盟の麻雀プロが訪れた飲食店1,734店（2,430件）を、Xポストに基づいてまとめています。店名・メニュー・駅・投稿者で探せます。」
- 候補は種類ごとに3件、駅・投稿者・店名・投稿年・ジャンル・都道府県の順。行は種類の名前（「駅」など、小さく灰色、幅 4.5em）を先に置く。店数は今のタグと合わせた数
- タグは紺の丸いボタン（「×茗荷谷」）。現在地もタグにする。駅のタグを選ぶと現在地は外れる
- 店名の候補は店の名前と投稿の店名の両方から（同じ名前の店をまとめる）。投稿年は「2025年」と出す
- 都道府県は駅の一覧の値（「東京都」の形）。一覧に無い駅は【県】の印から
- ジャンルは Claude が付ける（候補の一覧は後の指示で決める。列が無い間は候補に出ない）
- Google マップのアイコンは地図のピン（14px、リンクの色）。出典の「(i)」はトップの右上（18px、灰色）で、`?station=` などで直接開いた画面には出ない（× で探す条件を外すとトップに戻り、出典に辿れる）
- 結果は20店ずつ。投稿の写真は 120×68、カテゴリのカードは 160×90
- 現在地は、駅の点のある店が無い間「準備中」で押せないボタンを出す（今のデータでは押せる）
- 検索欄の語は、投稿の店名も店の値として扱う（その店のどの投稿にも当たる。投稿の店名に「ラーメン」などの普通の語がある店は、その語で店の投稿がすべて出る）
- 0件の文は「見つかりませんでした。店名・メニュー・駅・投稿者の名前で探してください。」（タグで絞っているときも同じ）
- 打った語も `?tag=` に入れる。URL パラメータは上の「URL パラメータ」
- 白地のナビで「リソース」に印
- 【3】で駅を直した行は、【3】の駅の点・駅の候補・都道府県を使う（【2】の「駅の候補」は使わない）
