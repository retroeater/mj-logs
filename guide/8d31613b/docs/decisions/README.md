# 決定の記録

平野さんの決定（指示文の「決定」節と、作業中に平野さんが答えたこと。grill を含む）を、分野ごとに1ファイルで残す。
経過・理由の詳しい話は各ログ（`docs/logs/<Chat-Ref>.md`）と issue に書き、ここには**決まったことだけ**を書く。

このフォルダは mj-logs の `guide/<SHA>/docs/decisions/` へ写り、写したログの末尾の「ガイド文書」のリンクから読める（`scripts/sync_guides.py`）。
**mj-logs は public**。ログと同じ基準で、公開してよい内容だけを書く（プレビューの URL・鍵やトークンの値・人の個人情報は書かない）。

## 書き方

- 見出しは `## YYYY-MM-DD（Chat-Ref）` で、日付の古い順に並べる。1つの指示の決定を1つの見出しにまとめる
- 決定は1項目1行（長ければ2行）の箇条書きで、平野さんの言葉に近い形で書く。理由は1行まで。関係する issue の番号を添える
- grill の決定は「（grill Qn）」を添える
- 前の決定を置き換えた・取り下げたときは、**前の決定を消さずに**行末に「→ 置き換え: YYYY-MM-DD（Chat-Ref）」「→ 取り下げ: …」を付け、新しい決定の側に「（YYYY-MM-DD の〜を置き換える）」と書く
- 実装がまだの決定は、そのことが分かるように書く（例: 「未マージ」）。実装が済んだかどうかの追記はしない（状態は issue で見る）

## 書く時機

- Claude Code が、指示の完了時（完了・判断待ち・中断の最後の push）に、その指示の「決定」節と作業中の平野さんの回答を該当の分野のファイルへ足す（ログと同じコミットでよい）
- 分野が無ければファイルを作り、上の一覧に1行足す。/live・title/・運用など、ほかの分野も対象にする。分野のファイルは、その分野で次に決定が出たときに作る（前もってまとめては作らない）
- この仕組み（置き場所・書き方・書く時機）そのものの決定は、分野のファイルではなく下の「この仕組みの決定」に書く
