# 放送対局ページ（/live）の設計メモ

2026-09-17作成（CHAT-0916-LV-05）。親issue #346。

「動画 > 放送対局」（`video_live.html`）を、帰り道（`wayhome/`）・最強戦（`saikyo/`）と
同系統の構成で `/live` 以下に作り直す。**`video_live.html` は変更せず、/live 以下に新しく作る**（CHAT-0916-LV-01）。

調査・検証の詳細は作業ログにある（`docs/logs/CHAT-0916-LV-01.md`〜`CHAT-0916-LV-05.md`）。
このメモは決まったことだけをまとめる。各項目の末尾の括弧は、決めたときの Chat-Ref
（LV-01 は CHAT-0916-LV-01、LP-04 は CHAT-0919-LP-04、SX-09 は CHAT-0918-SX-09 の略。「判断」は平野さんの判断、「案」はログの案を判断で採用したもの）。

実装の状況（2026-09-19）: 生放送・メンバー限定の表示（2-9）は LV-27・LV-28 で実装、LV-29 で本番に反映。ページ生成は `scripts/generate_live_pages.py`（共通部品 `scripts/lib/live.py`・`names.py`、CHAT-0916-LV-09〜LV-19）。noindex のまま本番に出ている（2026-09-19 の cloudflare 6b7259e2 の生成物で個別 732・期 135・タイトル戦 14、動画 2,898本。LV-19 では個別 569・動画 2,564本）。「連盟プロ以外」の見出しの `備考`→`所属補足` の改名で生成が止まっていた件は CHAT-0918-SX-09 で解消済み（5b99e43）。正式公開は #362、毎日の自動取り込みは #404（LP-05 で #362 から切り出し）。

**シートの読み方（LV-13）**: /live が読むタブ（連盟プロ以外・別名・放送対局・連盟ch・タイトル戦）は、`lib/sheets.py` の `fetch_records()` で見出しの名前で列を読む。生成に使う列（`lib/live.py` の `*_HEADERS`）が欠けている・重複しているときだけ止め、ほかの列の追加・並べ替えでは止まらない（LV-29 で、並べ替え・未知の列は通り、欠け・重複では止まることを試した）。gviz は存在しないタブ名にも先頭のタブを返すため、先頭のタブ（連盟プロ以外）と中身が同じ応答は、先頭のタブを読んだとき以外は「タブが無い」として止める

1行＝1動画（例外は A 列の注記）。個別ページは「タイトル戦＋期＋まとめ単位」が同じ行の集まり（案 LV-04 4-(3)、LV-05 で初期データに使用）。

### 1-3. 「連盟ch」タブの列定義

タブ名は 2026-09-19 に「全動画」から改名（どの範囲の全動画か分かるように、判断 LV-29）。列は見出しの名前で読み、順序に依存しない（2026-09-19 に平野さんが並べ替えた。下の表は並べ替え後の順）。

| 見出し | 形式 |
|---|---|
| 動画ID | キー |
| 種別 | `ライブ`（生放送だった動画。`liveStreamingDetails` あり、配信予定を含む）/ `動画`（それ以外。ショートを含む）（判断 LV-25・LV-26） |
| 限定 | `Y`（メンバー限定の再生リスト `UUMO…` に載っている）/ `N`。空欄は作らない（判断 LV-23） |
| 公開日時 | `2024-08-30T19:00:00+09:00`（JST の文字列） |
| 配信開始日時 | `2026-09-17T19:00:05+09:00`（`actualStartTime` の JST）。配信予定は空 |
| 長さ | 秒の整数 |
| タイトル | YouTube の現在のタイトル |
| 最終確認日 | `YYYY-MM-DD` |
| 放送対局 | `Y` / 空（下記 3-3 の判別規則に当たったか。/live の候補。旧「候補」、LV-29 で改名） |

### 1-5. 名前の検査

生成・bot の書き込みの前に毎回行う。違反した行は使わずに警告し、サマリに出す（案 LV-03 5-(1)、LV-05 で実物の列に読み替えて実行）。

2. 「連盟プロ以外」の名前に重複が無い
3. 「別名」の変換後が「プロ」か「連盟プロ以外」にある
4. 「別名」の変換前が「プロ」「連盟プロ以外」に無く、重複も無い
5. 「別名」に連鎖が無い（変換後が変換前に現れない）
6. 「放送対局」の対局者・実況・解説の名前が「プロ」「連盟プロ以外」「別名の変換前」のどれかにある。無ければ「未登録」としてその行を公開しない

### 1-7. 生データ（層1、#438）

`/live` のデータの流れを3層（YouTube生データ → 「連盟ch」→「放送対局」）に分ける設計の1本目。
YouTube から取り出した無加工のデータを、手で補正した内容と混ぜないための層（#438「決定」）。

- 取得: `scripts/fetch_live_channel_raw.py`。連盟チャンネルの公開アップロード再生リスト（`UU…`）とメンバー限定再生リスト（`UUMO…`）を `playlistItems.list` で歩いて動画IDを集め、`videos.list`（`snippet,contentDetails,liveStreamingDetails,status`）で属性を取得する
- 保存先: `data/live_channel_raw.jsonl`（1行1動画のJSONL）。`.assetsignore` の `data` 行で配信対象外
- 保存する項目（値は加工しない。「種別」「限定」は `liveStreamingDetails` の有無・再生リストの内訳から機械的に決まる、regexによる文言解釈は含まない）: 動画ID・タイトル・概要欄・公開日時・配信開始日時・長さ・種別（`ライブ`/`動画`）・公開範囲・限定（`Y`/`N`）・取得日時
- 並び: 2026-09-22 の初回取得分は動画IDの昇順。以降は**末尾への追記だけで、既存の行は書き換えない**。JSON化のキー順序は固定
- 同じ動画IDの行が複数あるときは**後の行が正**（`scripts/lib/live_candidate.py` の `load_latest_videos()`）
- 更新（毎日、`.github/workflows/update-live-channel.yml`）:
  - 新着: 再生リストを歩き、まだ無い動画を追記する（約280ユニット）
  - 配信予定・配信中のまま保存した動画（`配信開始日時` が空か `長さ` が `P0D`）を取り直し、取得日時以外が変わっていれば追記する
    （配信後に配信開始日時・長さ・概要欄を埋めるため）
  - 週1回（水曜）: 既知の全動画を取り直し（約280ユニット）、見えなくなった動画に、直前の行の写しに `"状態": "取得不可"` を足した行を追記する。
    また見えるようになったら取り直した行を追記する。取得不可の動画は層2で確認=Y・理由「取得不可(削除・非公開の可能性)」になる
- 層2（「連盟ch(層2試作)」）は Sheets API で直接書く（`docs/notes/live-channel-write.md`）

### 2-2. ページの単位

| ページ | 内容 |
|---|---|
| トップ `/live/` | 全件を HTML に埋め込み、検索していないときは日付の新しい順に12件だけ出す（判断 LV-11）。日付の欄（から・まで）は当面なし（判断 LV-11）。検索バーは「2-8」 |
| タイトル戦 | 期の一覧 |
| 期 | ステージ → まとめ単位 の順に個別ページへのリンク。**期のページの中はキーの順**（判断 LV-03） |
| 個別 | 1まとめ単位＝1ページ |

- **回戦（半荘）ごとの個別ページは作らない。** 個別ページは「同一ステージの同一卓（メンバーが同じ）」を基本の単位とする（判断 LV-04。理由: ページ数が多すぎる、回戦ごとに分かれていない対局がある）
- 複数卓を順番に放送するケースは「同一ステージ・同一日」を単位とする（判断 LV-04）。**王位戦の準決勝は、期ごとに準決勝全体を1ページ**（判断 LV-05）
- 抜け番のある決定戦・決勝（5名）は1ページ（案 LV-04 4-(1)）

### 2-8. 検索バー（判断 LV-15・LV-16・LV-17）

スマホでヒーローの下が混まないよう、タイトル戦・選手・実況解説の3つの検索欄をやめ、帰り道一覧（#189）と同じ固定バー1本にした（判断 LV-15）。**バーはトップだけでなく、タイトル戦・期・個別のすべてのページに置く**（最強戦と同じ一貫性、判断 LV-16）。

- 固定バーはヒーローの直後に置き、navbar 直下に sticky で貼り付く（`.mj-filterbar`。位置と色は帰り道一覧と共通の規則、高さは `assets/live.js` が `--mj-filter-h` に実測）
- **左のプルダウンはタイトル戦の切り替えで、選ぶとそのタイトル戦のページへ移動する**（最強戦の年度プルダウンと同じ。既定は「すべての放送対局」＝トップ自身）。選択肢の値が移動先の href で、**見ているページのタイトル戦が選択状態になる**（判断 LV-16）
- **検索の範囲はページごとに決まり、どのページでもその場で絞り込む**（判断 LV-17。LV-16 の「トップ以外はトップへ移動して検索」を改めた）:

| ページ | 検索の範囲（埋め込むカード） |
|---|---|
| トップ | 全件（個別ページ全部） |
| タイトル戦 | そのタイトル戦の個別ページ |
| 期 | その期の個別ページ |
| 個別 | **その期**の個別ページ（その個別ページの動画ではなく、ひとつ上の階層） |

- トップ以外は、範囲のカードを `hidden` の `#live_results`（日付の降順、`data-scope` に範囲の名前）として埋め込み、ページ本来の内容を `<div data-live-content>` で包む。**検索している間だけ両者を入れ替える**（`assets/live.js`）。検索していないときは本来の内容を出す
- **個別ページの検索も、期のページへ移動せずその場に結果を出す**（判断 LV-19。入力するそばから絞り込む動きをすべてのページで同じにするため、LV-17）
- バーは `<form action="<ページ自身>" method="get">`、入力欄は `name="q"`。送信（Enter）してもページは移動しない（`preventDefault`）。`?q=` 付きで開くと検索欄の初期値になる
- 件数の表示（検索欄の右）: **検索している間だけ出す**（判断 LV-28。検索していないときの「最近の12件を表示（全N件）」「第39期十段戦 全10件」はやめた）。トップは「N件中 M件を表示」、トップ以外は「第39期十段戦の10件中 3件を表示」、0件「（第39期十段戦に）該当する対局がありません」（LV-17）。検索中も消すと0件のときに何も出なくなるため残した
- 埋め込みでページが大きくなるのは了承済み（判断 LV-19。2026-09-18 でトップ 546KB・タイトル戦の最大 `gpmax.html` 179KB、gzip 62KB・19KB）
- 右の欄はカードの `data-info` への部分一致。`data-info` はタイトル戦名・期・ステージ・卓・回戦・対局者・実況・解説（放送時点の名前を含む）と**日付**
- **日付は「2020-07-29」と「2020年7月29日」の両方を入れる**（判断 LV-16）。年（`2024`）・年月（`2024-05` / `2024年5月`）・年月日のどれでも引ける。**入れるのは、そのカードの個別ページに含まれる全動画の日付（2-6。ライブは配信日、判断 LP-09）**（判断 LV-17。LV-16 ではカードに出る日付＝最初の動画の公開日だけだった）
- **空白で区切った語は、すべてを含むものに絞る**（例「佐々木寿人 十段戦」「2024-05 グランプリ」）。正規化は NFKC・小文字・連続する空白を1つに
- URL のパラメータは `?q=`（検索語）の1つだけ。`?title=` `?player=` `?staff=` は廃止した。個別ページの「すべて見る」も `?q=<選手名>` で移動する
- 検索していないときに最近の12件だけを出す動きは変えていない（判断 LV-11）

- スマホ幅（390px）ではプルダウン・検索欄・件数の3行になる。ひとまずこのまま（判断 LV-16）

### 2-9. 生放送とメンバー限定の動画（判断 LV-25・LV-26、実装 LV-27）

- **載せる生放送はメンバー限定版（全編）**。公開版の生放送は冒頭の無料部分だけ（長さはメンバー限定版の中央値28.5%、概要欄にも「一部のみ無料」）なので、「放送対局」で表示 N・備考「冒頭のみ無料のため対象外」とする。メンバー限定版しか無い卓のページも公開する。冒頭のみ無料の公開版しか無い卓（2020〜2022年が中心、34卓）は公開しない（判断 LV-25・LV-26）
- メンバー限定版は「放送対局」に1本1行で持ち、公開版の行の属性（タイトル戦〜解説）を写す。**複数の卓が1本に入っている生放送は、まとめ単位に「、」区切りで卓をすべて並べ、関係する卓すべてのページに同じ動画を出す**（今の生成の動きのまま。判断 LV-25）
- 対局日: ライブは配信開始の JST の日付。半荘単位の動画は、同じまとめ単位の生放送の配信日が1日に決まれば、その日付（枝番に日の区別がある行は同じ枝番の生放送だけ）（判断 LV-23・LV-25）

**メンバー限定のラベル**（YouTube の表現に準拠。鍵のアイコンは使わない、判断 LV-26）:

- 文言「メンバー限定」。YouTube は題名の下に緑の文字・薄い緑の地の角丸で出す（文字色 `#107516`、`BADGE_STYLE_TYPE_MEMBERS_ONLY`。調査は CHAT-0916-LV-25 のログ）。/live も緑系の文字と薄い地で、ダークテーマでも読める色にする。色だけに頼らず文言を必ず出す
- 出す場所:

| 場所 | 出す条件 | 出すもの |
|---|---|---|
| 個別ページの動画カード（日付の行） | その動画がメンバー限定 | 「メンバー限定」のラベル |
| 個別ページのヒーローのメタ行 | ヒーローの動画（最初の動画）がメンバー限定 | 「メンバー限定」のラベル。「▶ 再生」は変えない |
| 期・タイトル戦・トップのカード、「この選手の他の対局」 | そのページの動画が**すべて**メンバー限定 | 「メンバー限定」のラベル（一部だけのときは出さない） |
| 検索の `data-info` | その範囲にメンバー限定の動画がある | 「メンバー限定」の語（検索で絞り込めるように） |

- **1本が複数の卓に出る場合**（同じ動画IDの別の行の分を含む、LV-30）: その動画のカードの最後の行に「ベスト16A卓・B卓を続けて配信」（まとめ単位を並べ、同じステージが続く卓は卓だけにする。ステージと卓の間に空白を入れない、判断 LV-28）。ほかの卓のページにも同じ動画が出ることが分かるようにする
- 期のページのカード（タイトル戦のページ）も、その期の動画がすべてメンバー限定ならラベルを出す（LV-27）
- ラベルの色: 文字 `#8fd19e`・地 `#1d3524`（コントラスト 7.4:1、`style.css` の `.mj-live-members`）。/live は常に濃色のため、濃色用の1組だけを持つ（LV-27）

**種別による小見出し**（YouTube の呼び分けに合わせる、判断 LV-25・LV-26）:

- 動画の一覧を、「連盟ch」の種別で見出し「動画」「ライブ」の2つに分ける。件数は出さない（判断 LV-28。「動画（N本）」の見出しと、その下のメンバー限定の注記はやめた）。小見出し「生放送のアーカイブ」（回戦以外の単位の動画に付けていた）はやめた（LV-27）
  - 「動画」: 種別 `動画`（半荘単位の動画と、通常のアップロードの卓・ステージ単位の動画）。並びは今の回戦のキー順、その後ろに回戦以外を日付順
  - 「ライブ」: 種別 `ライブ`（生放送。今後はほぼメンバー限定版）。配信日の昇順（判断 LP-09）
- 本数（期・タイトル戦・トップのメタ行・見出し・カード・説明文）は、複数の卓のページに出る動画を1本と数える（判断 LV-30。個別ページの本数はもともと重ならない）
- 並びは「動画」→「ライブ」（無料の半荘単位を先に）。片方しか無いページは、その見出しだけ
- 「半荘単位の動画の出場者の名前の行」（6名以上のページ）は、今までどおり回戦の動画にだけ出す
- **赤い「ライブ」の札は付けない**（YouTube では配信中を表すため、終わった配信に付けると誤解される）
- ヒーローの再生ボタンの動画（最初の動画）は、今の「回戦の動画の先頭、無ければ回戦以外の先頭」のまま

**データ**: 生成で「連盟ch」の種別・限定を読む（`lib/live.py` の `VIDEO_HEADERS`。LV-27 では列を足す前のシートのため任意の列にしていたが、貼り付け後の LV-29 で必須にした）。「放送対局」には持たない。空の種別は「動画」、空の限定はメンバー限定でない扱い

**貼る前のローカルでの確認**（LV-27）: `generate_live_pages.py` は「放送対局」「連盟ch」をシートの代わりに TSV から読める。名前の辞書・「タイトル戦」はシートを読む。CI・ワークフローからは使わない

- TSV は fetch_records() と同じく見出しの名前で列を読み、前後の空白を落とす。行番号（警告の「行N」）はシートの行と同じ

### 3-4. URL が変わったとき

- ステージ名・卓・まとめ単位を直すと URL が変わる。**301 は自動で作り、当面は消さずに残す**（判断 LV-05）
- 仕組みの案（LV-04 4-(5)）: 前回の生成で出したページの一覧（URL と、そのページの動画IDの集合）をリポジトリに持ち、消える URL について同じ動画IDを最も多く含む新しい URL へ 301 を `_redirects` の生成部分（`# live: generated` 〜 `# live: end`）に書く。手書きの行には触らない
- `_redirects` の上限は静的 2,000行・動的 100行（https://developers.cloudflare.com/workers/static-assets/redirects/ 、2026-09-16 取得）
- 除外にした動画だけのページは 404 にする
- 公開前の記号の変更では 301 を作らず、`data/live_pages.json` を作り直す（LV-12）
