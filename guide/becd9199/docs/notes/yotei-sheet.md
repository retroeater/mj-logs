# 連盟の予定表の取り込み（#448）

放送対局の公開カレンダー（#448）の2本目。連盟の「【一般公開】予定表」を Calendar API で読み、
スプレッドシート「ryoei.pro_日本プロ麻雀連盟_予定表」の3層へ取り込む。あわせて3本目として、層1の YouTube のライブの枠と
予定表の予定から、放送対局の公開カレンダーへ同期する（「公開カレンダーへの同期」）。
設計の調べは https://github.com/retroeater/mj/blob/1ad5d8be5a7b06ddd53620c536034cd78acddfdb/docs/logs/CHAT-0928-HC-01.md ・ https://github.com/retroeater/mj/blob/1ad5d8be5a7b06ddd53620c536034cd78acddfdb/docs/logs/CHAT-0928-HC-02.md 、実装は https://github.com/retroeater/mj/blob/1ad5d8be5a7b06ddd53620c536034cd78acddfdb/docs/logs/CHAT-0928-HC-06.md ・ https://github.com/retroeater/mj/blob/1ad5d8be5a7b06ddd53620c536034cd78acddfdb/docs/logs/CHAT-0928-HC-10.md 。

/live の3層（`docs/notes/live-channel-write.md`）とは別のスプレッドシート・別の表だが、考え方は同じ
（機械が置き換える【1】【2】と、平野さんが書く【3】。【3】の行は機械が予定表と予定IDでそろえる）。

## 流れ

毎朝の `.github/workflows/update-live-channel.yml` の層1の取り込み（ジョブ `update`）の後に、ジョブ `yotei` が動く。

1. **読み取り**（`scripts/fetch_yotei.py`、認証は `GCP_SA_KEY`＝カレンダー用のサービスアカウント）:
   予定表（カレンダーID は `scripts/lib/yotei.py` の `CALENDAR_ID`。連盟サイトの「年間行事予定」が埋め込んでいる一般公開のカレンダー）を
   `events.list`（singleEvents）で、**全期間**（過去分を含む。期間を指定しない）を読む（CHAT-0930-CAL-08。2026-09-30 時点で 1,132件、2024-12-01〜2027-03-31）。共有は要らない（2026-09-28 に読めることを確かめた）。
   2回読んで予定ID・更新日時の組が食い違えば止まる。30件未満でも止まる
2. **書き込み**（`scripts/write_yotei_sheet.py`、認証は `LIVE_SHEETS_SA_KEY`＝`live-channel-writer`）:
   【1】【2】をタブ全体の置き換えで書き、読み返して全セルを比べる。【3】は予定表と予定IDで完全に一致させる（下の「【3】の結び付け」）。
   書き込み先は `scripts/lib/sheets_write.py` の `WRITABLE` でこのシートの3タブ（と /live の3タブ）に限る
3. 書き込むのは、毎朝の実行（Worker の起動・schedule）と、手動実行で `apply` か `yotei_apply` を選んだときだけ。それ以外は dry-run（件数と内訳だけを出す）

`update` が失敗した日は動かない（`needs`）。`yotei` が失敗しても /live の取り込み・再生成には影響しない。

## 表

スプレッドシート ID は `scripts/lib/yotei.py` の `SPREADSHEET_ID`。

| タブ | 書く人 | 中身 |
|---|---|---|
| 【1】元データ | 機械（毎回置き換え） | 予定表の予定を加工せずに: 予定ID・開始・終了・終日・件名・説明・場所・状態・作成日時・更新日時・iCalUID・取得日時。開始・件名の順 |
| 【2】自動変換後 | 機械（毎回置き換え） | 日付・件名（前後の空白を落とす）・大会・分け・開始(仮置き)・開始の根拠・枠の開始(YouTube)・終了(仮置き)・終了の根拠・完全版の動画ID・無料版の動画ID・予定ID |
| 【3】手動補正 | 平野さん（機械は行の追記・削除と予定IDの記入だけ） | 日付・件名・掲載・開始・終了・備考・追加日・予定ID。**予定IDで【2】と結び付く**（#479） |

**掲載は【3】の手入力だけで決める。** 平野さんが予定をすべて目で見て判定し、【3】の掲載が `Y` の予定だけをカレンダーに載せる（空欄・`N` は載せない）。
自動の判定はしない（#448 の決定、2026-09-28。HC-06・HC-07 では件名の型で【2】に掲載の見込みを出していたが、HC-08 で外した）。

### 【3】の結び付け（#479 の決定、2026-09-30）

- 【3】の行と予定表の予定は**予定ID**で結び付ける。予定表で件名だけ変わっても、掲載・開始・終了は引き継ぐ
  （以前は（日付, 件名）で結び付けていて、2026-09-29 の「第8期WRC-Rリーグ…」→「第8期JPML WRC-Rリーグ…」の改名で掲載 Y の4件が外れた）
- **予定IDが空欄の行は、掲載 Y でも載せない**（（日付, 件名）には戻さない）
- **【3】は予定表の全期間と予定IDで完全に一致させる**（CHAT-0930-CAL-08。#479 の決定6〈消えた行は残す〉を置き換えた）。毎朝の取り込みで:
  - 予定表に無い予定IDの行（予定表から消えた・作り直された予定）は**削除する**（手で書いた掲載・開始・終了・備考も消える。掲載 Y の行は知らせる）
  - 予定IDが空欄の行は、（日付, 前後の空白を落とした件名）で【2】の予定1件に一致すれば予定IDを入れ、一致しなければ削除する
  - 【3】に無い予定IDの行を末尾に足す（過去の予定も。掲載は空欄）
  - 書く直前に【3】を読み直して最初に読んだ表と同じことを確かめ、行は値で探す（行番号を覚えて使わない）。書いた後に読み返し、予定IDの集合が【2】と同じこと・残した行の値が変わっていないことを確かめる
  - 1回で削除する行が60行（うち掲載 Y 10行）を超える・足す行が1500行を超えるときは、書かずに止める（`--allow-many-deletes`・`--allow-many`）
- 【3】の日付・件名は追記したときの値のまま（機械は書き換えない）。今の件名は【2】で見る
- 件名は【2】・【3】の追記・カレンダーで前後の空白を落とす。全角・半角は直さない。【1】は予定表のまま
- 「予定ID」列の位置は問わない（2026-09-30 に平野さんが先頭へ並べ替えた）。`write_yotei_sheet.py` は【3】を見出しの名前で読み書きし、「予定ID」列が無いとき・同じ予定IDの行が2つ以上あるときは
  何も書かずに止まる（`sync_live_calendar.py` も同じ予定IDで止まる）。列を足して既存の行を埋めたのは移行の Apps Script（`scripts/apps_script/add_layer3_event_id.gs`）
- **知らせ**: 毎朝の取り込みで、次のどれかがあった日だけ常設 issue「予定表の変化」（#481）にコメントする
  （ジョブ `yotei` の「予定表の変化をissueに知らせる」、形は #446・#426 と同じ）。掲載 N・空欄の予定の変化は知らせない
  - 予定表から消えた掲載 Y の予定（【3】の行を削除した。カレンダーからも消える）
  - 【3】で掲載 Y の予定（今日以降）の日付か件名が変わった（前の【2】と今の【2】を予定IDで比べる）
  - 【3】に新しい行を足した（掲載が空欄）。30件を超える日は件数だけ（`NOTICE_LIST_MAX`）
  - 【3】の見出しの不正・同じ予定IDで止まった（理由を書く）


### 【2】の規則（`scripts/lib/yotei.py`）

- **大会・分け**: 件名と YouTube の題名の両方から同じ規則で取る（`category()`）。鳳凰戦は A1・A2・B1 リーグと決定戦、女流桜花はリーグと決定戦、
  ほかの大会は「決勝・決定戦」とそれ以外
- **開始(仮置き)**: 層1の放送済みの完全版の枠のうち、過去2年の同じ分けの実際の開始（日本時間）の中央値を30分単位に丸める。
  同じ分けが3件未満なら同じ大会の中央値。それも3件未満（過去の配信が無い大会。鳳匠戦など）なら、同じ大会の配信予定の YouTube の枠のうち
  最も近い日の予定の開始（丸めない）。それも無ければ全体の中央値（2026-09-28 時点で 14:00）（#448 の決定、2026-09-28）。
  使った根拠（分け・件数・中央値、または使った枠）を「開始の根拠」に書く
- **枠の開始(YouTube)・完全版／無料版の動画ID**: 層1のライブのうち、同じ日（日本時間。開始は実際 > YouTube の予定）で、
  大会が同じで、節・ベストN・期が食い違わず卓が重なる枠。予定表で「ベスト8AB卓」と書かれた卓は YouTube の A卓・B卓のどちらにも当たる（#448 の決定）。
  同じ日・同じ題名の公開版とメンバー限定版は、メンバー限定版を完全版、公開版を無料版にする。片方しか無ければその枠が完全版
- **終了(仮置き)**: 同じ日の次の番組（【3】で掲載 Y の他の予定の開始と、層1の同じ日の他の枠の開始）のうち最も早いもの。無ければ 23:00。
  【3】の掲載が Y でない予定は数えない（#448 の決定、2026-09-28）。【3】は【2】を作る前に読む（`write_yotei_sheet.py`）
  開始は「枠の開始(YouTube)」があればそれ、無ければ「開始(仮置き)」

時刻の優先順位（実際 > YouTube の予定 > 平野さんの入力〈【3】〉> 予定表〈【2】の仮置き〉）はカレンダーへの同期（3本目）で使う。

## 公開カレンダーへの同期（#448 の3本目）

ジョブ `yotei` の最後のステップ（`scripts/sync_live_calendar.py`、組み立てと比較は `scripts/lib/live_calendar.py`）。
書き込み先はカレンダー ID `live_calendar.CALENDAR_ID`（公開カレンダーの ID のため、GitHub の変数ではなくコードの定数に置く）。
カレンダーの読み書きは `GCP_SA_KEY`（カレンダー用のサービスアカウント。平野さんが「予定の変更」で共有済み）。スプレッドシートは gviz で読む。
サイトからの導線は「リソース > カレンダー」（`_redirects` の `/resource_calendar.html` の埋め込みに `src`・`color` を1組、#480）。

- **予定は2種類**。どちらも私的拡張プロパティ `ryoei=live` と `key` を持ち、`key` で今の予定と結び付ける（手で足した予定には触らない）
  - **枠の予定**（`key=video:<動画ID>`）: 層1のライブ（取得不可を除く）を、同じ日・同じ題名でまとめた完全版の枠ごとに1件。メンバー限定版があればそれ、無ければ公開版。
    **チャンネルの最初（2015-08-03）から、放送済みの枠も載せる**（#450）。完全版は規則で全部載せ、例外だけを「【4】カレンダー非掲載」タブで外す（下）。
    同じ日・同じ題名の同じ種類の版が2本以上あれば、それぞれ別の予定にする（`yotei.full_frames(split=True)`。一部を無料で見られる版は、いちばん長い限定版に付ける）。
    **題名の違う公開版も、同じ日・同じ大会（`yotei.event_of()`）の限定版と実際の配信の時間が重なれば、その限定版の無料版にして予定にしない**（`yotei.attached_publics()`、CHAT-1002-CLD-02）。
    放送中に公開版だけ改名された枠（2026-10-01 の鳳匠戦）や、題名の表記が違う枠（「FocusM」と「Focus M」）を二重に載せないため。
    実際の開始・終了が両方ある（放送済みの）枠だけを見て、重なる限定版が2本以上なら重なりの最も長いものに付ける。
    効かせるのはカレンダー（`split=True`）だけで、予定表の【2】（`split=False`）は題名で組にしたまま（【2】にも効かせると鳳匠戦の過去の枠が減り、開始の仮置きが 11:00 → 14:00 に変わるため）。
    /live の掲載 Y/N とは別に決める（#453）
  - **仮の予定**（`key=yotei:<予定ID>`）: 予定表の【3】で掲載 Y の今日以降の予定（予定IDで結び付いた行。全期間を取り込んでも過去の予定は載せない）のうち、【2】の「完全版の動画ID」が空で、同じ日・同じ大会（`yotei.event_of()`）の枠がまだ無いもの。
    枠が出たら仮の予定は載せる予定から外れ、消える（1日にまとめて書かれた卓は同じ放送枠なので、その日の同じ大会の枠に置き換わる）。
    **日付が過ぎたら翌朝の実行で消す**（予定表由来の予定は将来の予定にだけ使う、#450）
  - **「【4】カレンダー非掲載」タブ**（/live の3層のスプレッドシート、平野さんが作った。#450 の決定で「カレンダーの除外」から改名）: 見出しは「動画ID」「参考:題名」「理由」（見出しの名前で読む。`live_layer3.fetch_calendar_exclusions()`）。
    ここにある動画ID の枠は載せない（載っていれば消す）。行が0件なら除外なし。**タブが無い・見出しが違うときは、カレンダーに書かずに同期のステップを失敗させる**（除外が黙って効かなくならないよう、2026-09-30 の決定。`sync_live_calendar.read_exclusions()`）
- **時刻**（#448 の決定）: 開始は 実際（`配信開始日時`）> YouTube の予定（`配信予定開始日時`）> 予定表の【3】の開始 >【2】の開始(仮置き)。
  終了は 実際（`配信終了日時`）> 実際の開始＋長さ（実際の終了が返らない放送済みの枠、#450）> YouTube の予定の終了 > 予定表の【3】の終了 > 同じ日の次の予定の開始 > 23:00（開始より前になるときは開始の1時間後）。
  足す前に保存した層1の行には `配信終了日時` が無いので、1回だけ取り直す（下の「層1の取り直し」）
  【3】の開始・終了は「16:00」の文字列でも時刻のセルでも読む（`live_calendar.parse_hhmm()`）
- **件名**: /live の【3】を反映したレコード（`live_layer3.fetch_matches()`、完全版か無料版の動画ID）があれば、`<期><タイトル戦> <ステージ>[ <卓>卓][ <回戦>]` に
  YouTube の題名の日の区別（初日・二日目・最終日など）を足したもの。無ければ YouTube の題名から【メンバー限定】【麻雀】【無料放送】【Free broadcast】を外し（ほかの【…】は残す。`live_calendar.TITLE_MARKS`）、全角英数を半角にし、`~…~` を空白に置き換えたもの
  （例「第21期女流桜花~Ａリーグ第６節Ｄ卓~」→「第21期女流桜花 Aリーグ第6節D卓」）。仮の予定は【2】の件名（予定表の今の件名の前後の空白を落としたもの。「（仮）」などは付けない）
- **説明欄**（#448 の決定、2026-09-28）: 1行目に載せる完全版の枠の URL。空行をはさんで【対局者】【実況】【解説】の見出しごとに1人1行。値の無い見出しは出さない。
  対局者・実況・解説は、/live の【3】にあればその値、無ければ層1の概要欄から抜く（「？？？？」「4位」「予選A卓1位」のような未定の値は出さない）。
  1つの枠で回戦・卓ごとに面子・実況・解説が違うとき（日本シリーズ・若獅子戦のベスト16など）は、すべての行から集めた重複のない一覧（初めて出た順。ABCD と ACEF なら ABCDEF）。
  対局者は概要欄の vs の行ごとに、行頭の見出し（「25回戦：」「A卓:」「1st stage:」など）と名前の前後の見出し・注記（「【予選A卓】」「※放送卓」）を外してから
  /live と共用の `live_extract.extract_players_and_staff()` に1行ずつ渡す（共用の関数は変えない。まとめるのは `live_calendar.py`）。
  **/live の【3】に値がある見出しは、【3】の値だけを使い、概要欄の名前を足さない**（見出しごと。「-」〈空として扱う〉も【3】の値。どの予定も【3】を書けば直せるように、CHAT-1002-CLD-06）。
  【3】が空欄の見出しは【2】の値で、【2】は1行分のことがあるので、概要欄に対局者の行が2行以上あれば【2】の値の後ろに概要欄の名前を足す（【2】の名前を含む概要欄の名前〈打ち間違いの「A v B」など〉は足さない）。
  足す概要欄の名前には、先に【2】と同じ「別名」の訂正をかける（`sync_live_calendar.load_name_fixer()`。登録名変更・どこにも無い名前はそのまま）。【2】で直した人を概要欄の誤記で2度載せないため（「畑谷翔太」と「畑谷翔大」、#491）。
  見分けは `live_layer3.merge_records()` がレコードに付ける `CORRECTED_KEY`（【3】に値がある補正の列の集合。/live・title/ の生成は読まない）。
  1行だけの枠は【3】・【2】の値のまま。同じ動画に【3】の行が複数あるときもまとめる。一部を無料で見られる版の URL・サムネイル・メンバー限定の印は載せない。
  仮の予定は「※開始時刻は暫定です。ライブ配信枠公開後に更新します。」の1行
- **作る・直す・消す**（`live_calendar.plan()`）: 今の予定（`ryoei=live`）は期間を区切らずに読み、載せる予定と比べる
  - 作るのは、載せる予定のうちカレンダーに無いもの（放送済みを含む）。今日以降（日付の近い順）を先に、次に放送済み（新しい順）
  - 直すのは、件名・説明欄・開始・終了のどれかが違う予定（PUT で置き換え、`key` は残す）
  - 消すのは、載せる予定に無いもの（日付が過ぎた・枠に置き換わった・掲載を外した仮の予定、除外・非公開・削除〈層1で取得不可〉になった枠）。
    一覧に消す理由を出す（`live_calendar.delete_reason()`）。**1回に消す予定が30件（`sync_live_calendar.MAX_DELETES`）を超えると、作る・直すも含めて何も書かずにステップが失敗する**
    （30件ちょうどは通る）。毎朝の実行（Worker の起動・schedule）はいつもこの上限で、超える日は毎朝同じく止まる
  - **意図して30件を超えて消すときは、手動実行の入力 `calendar_max_delete` にその回の上限（見込みの件数以上の整数）を入れる**（2026-10-03 の決定）。
    効くのはその1回だけで、schedule では使わない（`sync_live_calendar.delete_limit()` が `GITHUB_EVENT_NAME` を見て既定に戻す。
    Worker の起動〈`scheduled`〉ではワークフローが空の値を渡して既定に戻す）。
    1以上の整数でなければ止まる。既定と違う数のときは「上限を…に変えた」と、書き込みありなら消した予定（開始・件名・理由）を1件ずつ出す。
    先に `calendar_apply` を外して同じ数で実行し、消す件数と一覧を確かめてから `calendar_apply` を付ける
  - **同期の規則（`yotei.py`・`live_calendar.py`）を変える変更は、マージの前に修正前後の `build_desired()` を比べて消す件数を出し、30件と比べる。**
    超えるなら、入れる前に手順を決める（手動実行の `calendar_max_delete` で上限を上げる、など）。

## 手動実行

https://github.com/retroeater/mj/actions/workflows/update-live-channel.yml の「Run workflow」。

入力が切り替える書き込み（`update-live-channel.yml`。schedule では inputs が空になり、列「schedule」のとおり動く。
Worker の毎朝の起動〈入力 `scheduled`、手では付けない〉もほかの入力を無視して同じ列のとおり動く。docs/notes/scheduler-worker.md）:

| 入力 | ジョブ | 切り替える書き込み | schedule |
|---|---|---|---|
| `apply` | update（環境変数 `APPLY`） | 層1のコミット、/live の【1】【2】【3】、常設 issue「/live の未登録の名前」（#475）への知らせ。ジョブ regenerate（/live・title/ の作り直しとコミット）もこれで動く | 書く |
| `apply` / `yotei_apply` | yotei（環境変数 `APPLY` に合成） | 予定表のシートの【1】【2】【3】と、常設 issue「予定表の変化」（#481）への知らせ | 書く |
| `calendar_apply` | yotei（環境変数 `CALENDAR_APPLY`） | 放送対局の公開カレンダー（`apply`・`yotei_apply` とは別） | 書く |
| `verify`・`allow_many_changes` | update | 週1回の確認を行う・その上限を外す | 水曜だけ確認・上限あり |
| `allow_shrink`・`allow_many` | update | 【2】の減少・【3】の追記の上限の検査を外す | 外さない |
| `calendar_max_delete` | yotei（環境変数 `CALENDAR_MAX_DELETE`） | カレンダーの同期のこの回の削除の上限（既定 30。上の「作る・直す・消す」） | 使わない（30） |
| `backfill` | update | 層1の取り直し（下の「層1の取り直し」。追記したものをコミットするのは `apply` のときだけ） | 行わない |

- **ジョブ yotei のログに `yotei_apply` という名前は出ない。** ジョブの環境変数 `APPLY`（`update` の apply か `yotei_apply`）に合成されるため、ログの `APPLY` を見る
- 予定表のシートだけを書くとき: `apply` を外し、`yotei_apply` にチェック（/live の【1】【2】【3】と層1のコミットは dry-run のまま）
- 件数だけを見るとき: すべて外す。**dry-run でも【3】の見出しの検査（予定ID の列など）は行い、通らなければ失敗する**（失敗の通知メールが平野さんに届く。2026-09-30 の work/0930-cal-479 の試運転は移行の Apps Script の前だったためこれで止まり、対応は不要だった）
- 作業ブランチから実行すると、そのブランチのスクリプトで動く（層1はそのブランチのもの）

## 層1の取り直し（#450、1回だけ）

`配信終了日時` などの4項目（`fetch_live_channel_raw.LATE_KEYS`）は後から足したため、足す前に保存した層1の行には無い（2026-09-30 時点でライブ 4,091本のうち 4,050本）。
過去の枠の終了時刻に使うため、`fetch_live_channel_raw.py --mode backfill`（ワークフローの入力 `backfill`）で1回だけ取り直す。

- 対象は、放送済みのライブで `配信終了日時` が無いもの（`needs_backfill()`）。videos.list を50本ずつ（約81回・約81ユニット）
- 取り直して内容が変わった行だけを `data/live_channel_raw.jsonl` の末尾に追記する（既存の行は変えない。コミットの前のステップが削除行の無いことを確かめる）。
  取り直しても終了が返らない動画は追記しないので、2回目以降はほぼ何も足さない。返らない本数は出力に出る（カレンダーは実際の開始＋長さで代える）
- /live の【1】は動画ごとの最新の行なので、行数は増えない（14,103本のまま。値が埋まるだけ）
- 手順: `apply` と `backfill` にチェックして実行（層1のコミットと /live の【1】【2】【3】の書き込みを伴う）。`backfill` だけなら取り直した結果の件数を出すだけ（コミットしない）
