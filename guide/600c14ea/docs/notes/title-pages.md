# タイトル戦の新構成（title/ 配下、#222）

仕様の正本は #222 の本文。ここには実装の仕組みと、データの取り込み・運用で知っておくことを置く。

## ページと生成

- 扱うのは「タイトル戦」タブの区分=連盟 かつ 状態=継続 の大会だけ（CHAT-0916-TT-11）。それ以外の大会はページを作らず、
  検索のデータ（`title/search.json`）・歴代・入口・`sitemap-title.xml` にも出さない。区分・状態を変えて再生成すると、
  非表示になった大会のページは `title/` から削除される。非表示の大会の数と行数は生成の出力に出る
- 表示する大会でも「タイトル」タブに表示=Y の行が無い大会（記録の無い大会）は、ページ・入口・sitemap に出さず、大会名を生成の出力に出す。記録が入れば次の生成で自動で出る（CHAT-0916-TT-15）。
  大会の追加・表示順・区分・状態は「タイトル戦」タブで管理する
- `scripts/generate_title_pages.py`（`regenerate.py` の `OUTPUT_OVERRIDES` は `"title/"`）が次を書き出す
  - `title/index.html`（入口: 現タイトルホルダー。年の切り替えで各年の優勝者）
  - `title/<slug>/index.html`（大会ページ）
  - `title/<slug>/<期>.html`（期ページ。期は「期」列の数字。麻雀最強戦は `21.html` と `2021.html` が並ぶ）
  - `sitemap-title.xml`（全ページ。公開〈#413〉から `sitemap.xml` が参照する）
  - `title/search.json`（全ページの検索のデータ、#364）
  - `title/years.json`（入口の年の切り替えのデータ、#277）
- `render_content()` 方式。画像の読み込み失敗は `assets/title.js` が `data-fallback`（アバター）へ差し替える
- CSS は `style.css` の「タイトル戦(title/、#222)」節。クラスは `.mj-title*` と `body:has(.mj-title)` に閉じる
- 公開（#413、2026-09-28）: noindex を外し、`sitemap.xml` から `sitemap-title.xml` を参照する。navbar の「連盟 > タイトル」は `/title/` へ差し替えた（項目名は 2026-10-01 に「タイトル戦」へ改めた。入口の見出し・パンくず・og:title と揃える）。`llms.txt` に入口を載せた
  - canonical を出す（サイトの既定〈#113、出さない〉の例外。`saikyo/` と同じ形）。入口・大会ページ・期ページとも、スラッシュ付きの正規の URL（`https://ryoei.pro/title/`・`/title/<slug>/`・`/title/<slug>/<期>.html`）で、og:url と同じ値（`page_meta()`）
  - 旧表 `jpml_titles.html` は廃止し、`_redirects` で `/title/` へ 301（#441）。`?name=<選手名>` はそのまま付き、`assets/title.js` が `q` の無いときの検索の初期値に使う。
    `jpml_pros.html` の「決勝進出」は `generate_title_pages.final_counts()`（title/ に載る決勝の回数）で数え、`/title/?q=<名前>` へリンクする
  - `/title/<slug>`（末尾スラッシュなし）は `/title/<slug>/` へ 301（#455。下の「URL の解決」）
- OGP（#232、2026-10-01）: 決定の経緯は `docs/decisions/title.md`（grill Q1〜Q16 と DUP-07〜DUP-11）
  - og:image: 入口は `img/ogp/title/index-black.png`（「タイトル戦」）、大会ページと期ページは大会の `img/ogp/title/<slug>-black.png`（大会名）。
    黒地・白字の文字だけで、写真は使わない（肖像権）。`generate_title_pages.py` の `og_image_for()` が画像のある大会だけ差し替え、無ければ共通の `img/ogp.png`（最強戦と同じ作り）。og:image:alt は大会名（入口は「タイトル戦」）
  - og:title: 入口「タイトル戦 | 日本プロ麻雀連盟 | ryoei.pro」、大会ページ「<大会名> | …」、期ページ「<期の名前> | …」（`Period.title`。「第41期鳳凰戦」「第3回リーチ麻雀世界選手権」「麻雀日本シリーズ2025」のように、期と大会名の間は空けず、数え方は実物のまま）。
    `<title>` は正式名のまま（「… 歴代優勝者（第1期〜第42期）」「… 決勝結果」）。分けるのは `page_meta()` の `og_label`（`PageMeta.og_title`）
  - 画像は手で作ってコミットする（生成の Actions では作らない）: `python3 scripts/build_ogp_image.py --text <大会名> --color '#ffffff' --bg '#000000' --max-size 400 --tracking -0.03 --out img/ogp/title/<slug>-black.png`。
    フォントは Noto Sans JP Bold（`~/.local/share/fonts/NotoSansJP-Bold.otf`、クラウドのセッションでは `raw.githubusercontent.com/notofonts/noto-cjk` の `Sans/SubsetOTF/JP/NotoSansJP-Bold.otf` から取得できた）。長い大会名は横幅に収まるまで字が小さくなる（そのままでよい、平野さん 2026-10-01）
  - **新しい大会を表示するとき**: 上のコマンドで画像を1枚作り、ページの生成し直しと同じコミットに入れる（画像が無い間は共通の `img/ogp.png` のままで止まらない）。
    `scripts/tests/test_title_ogp.py` が、表示している大会すべてに画像があること・置いた画像が実在の大会に当たることを確かめる（無ければテストが落ちる）。
    大会名を変えたときも画像を作り直す。中身を変えるので名前（接尾辞 `OGP_DESIGN`）を変えるか、`docs/notes/ogp.md`「中身を差し替える画像はファイル名を変える」に従う
- 写真カードの処理は `generate_saikyo_pages.py` と重複している（共通化は #222 の未決定）
- 入口（#358・#364、2026-09-18）: タイトルホルダーを決勝日（日付列）の降順に並べ、カード全体を大会ページへのリンクにする。カードは写真そのもので、
  上端に大会名を帯（色は下の「帯と回戦ラベルの色」）で、下端に選手名を透明になるグラデーションに白文字と影で重ねる（#364。#358 の「大会名の帯と写真を縦に並べる」形はやめた）。
  大きさ・写真の値は最強戦の写真カード（`.mj-saikyo-card`）を `.mj-title-holder*` に写したもの（`.mj-saikyo*` は流用しない）。列は最小幅160px・最大4列。見出しと大会一覧・案内文は無く、h1 は読み上げ用に残す（案内文は CHAT-0918-TP-11 で削除）
- 大会ページ・期ページ（CHAT-0918-TP-11〜TP-13）: 入口と同じ写真カード（`photo_card_html()`・`.mj-title-holder*`）を並べる。帯の字の大きさは入口と同じく、並びの中で最も長い帯の字数で決める
  - 大会ページ: 各期の優勝者を新しい期から。帯に「第X期」、押すと期ページ。1位が2名の期（王位戦 第26期）は2枚。表と決勝メンバーの表示は無い
  - 大会ページ・期ページの見出しは画面に出さず（h1 は `visually-hidden`）、パンくず（1.125rem）を見出し代わりにする。大会ページの区分・状態・期の範囲の行も出さない（CHAT-0918-TP-14）
  - 期ページ: パンくず（最後の項目に対局日を「第1期（2021年3月30日）」の形で添える。空なら括弧ごと出さない。複数日の決勝は最終日、CHAT-0918-TP-17）→ 決勝に出た全員の写真 → 決勝ライブ → 決勝動画。前後の期へのリンクは無い（TP-15 で廃止）。帯に順位（同順位はそのまま、第26期王位戦は2名とも「優勝」）、押すと X（新しいタブ）。X ID の無い選手はリンクにしない。決勝が5名の期（`.is-many`）はパソコン幅で1行に並ぶよう最大5列
  - 期ページに無いもの: 「この選手の他のタイトル・決勝進出」、大会の歴代優勝者、X・note のテキストリンク、「決勝メンバー」の語、「連盟プロ以外」の所属団体（データの整備後に出す、#397）
- 固定バーと検索（#364）: 入口・大会ページ・期ページのすべてに、検索欄のバーを置く（入口だけ左に年の切り替え。タイトル戦のプルダウンと共有ボタン〈#409〉は #277 で外した。入口へはパンくずの「タイトル戦」で戻る。共有ボタンのサイト全体の見直しは #530）。navbar とバーは最強戦の年度ページと同じく固定し、
  高さは `assets/title.js` が `--mj-title-nav-h`・`--mj-title-filter-h` に入れる。検索は最強戦トップ（`build_top_data`・saikyo.js）の形を写したもので、
  歴代の決勝メンバー全体を選手名・期の表記・大会名・年で探し、選手の写真カード→出場した期の一覧で出す。検索している間はページの本来の内容（`.mj-title-content`）を隠す。件数は出さず、0件のときだけ固定バーの末尾に「該当する選手はいません」を出す（最強戦と同じ位置・見た目。要素は `assets/title.js` が作る。#412 の決定で TP-11 の「出さない」を取り消した）。
  検索結果の写真は入口などの写真カードと同じグリッド（`.mj-title-holders` と同じ列の式）に並べる（#410。最強戦とのカード幅 4.5px の差は許容、#412）。期の一覧は開いた写真の行の直下に出し（最強戦トップと同じ、#410 で案Aに決定）、一度に開けるのは1人だけ（ほかを閉じ、開く人の写真の画面上の位置を保つ。#410）
  データは `build_search_data()` が `title/search.json` に書き出し、検索欄を使ったときに読む（384ページ〈2026-10-04 時点〉に埋め込むと重いため）。JS・CSS は最強戦と共通化していない
  - **年は「タイトル」タブの日付列から取る**（書式は下の「日付列の書式」）。2026-09-19 に平野さんが公開HPの年度を貼り、2026-10-08 時点で363期すべてが年を持つ（最後に残ったリーチ麻雀世界選手権 第1・2回に、平野さんが 2014・2017 を `YYYY-XX-XX` で入れた、#385・#277）
- 期ページの放送（#222、2026-09-28 平野さんの決定）: 写真の直後に節「決勝ライブ」（`h2#title_lives`）→「決勝動画」（`h2#title_games`。2026-09-28 に「対局動画」から改名）の順。/live と同じ【3】手動補正＋【2】
  （`lib/live_layer3.fetch_matches()`）の決勝段階（決勝・決定戦・十段位決定戦）の行を、動画の単位（回戦・卓・日・ステージ）を問わずすべて載せる。
  載せる行は【3】の掲載が Y の行と、掲載が空欄で冒頭版（【3】の「冒頭」=Y）でない行（`is_listed()`、#476 の案A。掲載=Y なら冒頭版でも載る）。冒頭版だけの期には何も載せない（#476 で案B をやめた）。
  同じ配信日の決勝ライブが無料・メンバー限定の両方あれば、限定を載せない（`drop_member_duplicates()`、#487。限定しか無い日と決勝動画はそのまま）。
  決勝が複数日なら全日。期は（タイトル戦, 期）＝（大会名, `第N期`/`第N回`、西暦の期〈日本シリーズなど〉は `2025` の形）で突き合わせる（`broadcast_key()`。西暦の期は #452 で足した）。0本の節は出さない
  - 節の分け方は動画の単位: 日・ステージ（決勝の全体の放送）は「決勝ライブ」、回戦・卓は「決勝動画」（`GAME_UNITS`）。2026-09-28 時点で、この分け方は【2】の種別（ライブ／動画）と全行で一致する。
    2026-10-04 時点で決勝ライブ 94期・139本、決勝動画 88期・480本（合わせて146期・619本、両方ある期は36期。期ページの節の動画を数えた）
  - 並びは卓 → 回戦（最終戦は最後）→ 枝番（`day_branch_key()`: 無し・東場・南場 → 初日・二日目・三日目・N日目 → 最終日）→ 動画の単位 → 対局日。ステージは見ない（#476・#487）。決勝動画はサムネイルの左上のタブ（`Broadcast.tag`）に回戦名（卓は「A卓」）を重ねる。
    決勝ライブは同じタブに何日目か（`day_labels()`）を重ねる: その期の決勝ライブの概要の日付を古い順に並べ、異なる日付が2つ以上あるときだけ、最初を「初日」、最後を「最終日」、
    間を「2日目」「3日目」…とする（同じ日付は同じラベル）。1日だけの期は重ねない（2026-09-28 平野さんの決定。それまでの「ライブ（対局日）」「決勝」のタブはやめた）。
    2026-10-04 時点で24期・69本（2日 7期、3日 13期、4日 4期）
  - ライブの動画には /live のカード（`generate_live_pages.py` の `build_video_card()`）と同じ概要を付ける: サムネイルの右下に再生時間（`.mj-video-card-duration` を流用）、
    動画の下に日付とメンバー限定の印（`.mj-title-video-summary`）。日付は【2】の種別がライブなら配信開始日時、ほかは公開日時（/live の `Video.sort_date` と同じ）。
    対局者・実況・解説は出さない（/live のカードも出していない。実況・解説だけを出す案は、タイトル戦の検索で実況・解説の人が当たるのは違うため見送った。2026-09-28 平野さんの決定）
  - 決勝動画は、タブの文字だけで下には文字を出さない
  - メンバー限定の印（`.mj-title-video-badge`）は【2】の「限定」列が Y の動画に出す（どちらの節も）
  - それまでの3つ（回戦だけの「対局動画」、「決勝動画」タブの「放送」、/live の期ページへのリンク「放送対局」）を作り直したもの。「決勝動画」タブは読まない（載らなくなった8本は #452）。
    「放送対局」のリンクは廃止（/live 側の「決勝結果（タイトル戦）」は残る）。範囲の3案（決勝の最終日だけ／決勝すべて／全対局）から「決勝すべて」を選んだ
  - 【3】の行を掲載=N にする、または掲載を空欄にして冒頭=Y にすると、その動画は消える。掲載は /live でも使う（/live は Y の行だけ載せる）ので、title/ のために変えると /live も変わる
- **帯と回戦ラベルの色は `style.css` の `.mj-title` の変数2つ（`--mj-title-band-bg`・`--mj-title-band-fg`）だけで決める。** 今は黒の不透明度75%・白字（CHAT-0918-TP-16）。
  写真カードの帯（入口・大会ページ・期ページ）と回戦ラベルが同じ変数を読むため、1か所の変更で両方が変わる。
  配色を見比べるときは、実データの見本を並べた比較ページを生成スクリプトで一時的に書き出し、ラジオボタンと `:has(#…:checked)` で変数を差し替えた（JS なし・再読み込みなし。#364 の TN-01、TP-14〜TP-15。TP-16 で削除）。
  透過の案は明るい写真と暗い写真の両方で見る（帯の下の写真が透けるため）
- **入口の大会名の大きさは、下限も決める。** 「1行に収まる範囲で大きく」だけにしたら、幅360px（カード160px）で11.2pxになった（CHAT-0918-TH-04）。
  今は「帯（写真）の幅 ÷ 最も長い大会名の字数」（字数は生成時に CSS 変数 `--mj-title-taikai-em` で渡す）を14px〜1.25remに収め、下限で収まらない長い大会名だけ2行になる（TH-05）
- **写真は X の画像だけ**（「プロ」J列、「プロ」にいない選手は「連盟プロ以外」の X画像URL。`_400x400` に書き換える）。無い・既定アイコンなら代替アバター。
  「タイトル」タブの「画像URL」（龍龍の画像）は読まない。列があってもなくてもよい（龍龍への依存の廃止、2026-09-28。それまでの龍龍の元画像・縮小版の扱いは #443）

## 入口の年の切り替え（#277）

- 目的は「ある年の全タイトル獲得者を見られる」こと（同じタイトル戦の歴代は大会ページ）。決定は `docs/decisions/title.md`（2026-10-09 の NEN-08。年表ページ `/title/timeline/` の試作〈NEN-01〜07〉はやめた）
- 入口の固定バーの左に年のプルダウン（`#title_year`。「現タイトルホルダー」と、決勝のあった年の新しい順の「2026年優勝者」…）を置く。ピル型で送りの矢印は無い（NEN-09 の比較で S1 に決めた）。
  開いた一覧の選択肢は白地に #212529（プルダウン自体の白い文字を受け継ぐと、Windows の Chrome の白い一覧で読めなかった）。
  年を選ぶと読み上げ用の h1 を「タイトル戦 2025年優勝者」に、タブの題名を「2025年優勝者 | タイトル戦 | 日本プロ麻雀連盟 | ryoei.pro」に替え、「現タイトルホルダー」に戻すと元に戻す。URL は `/title/?year=2025`（範囲外・不正なら「現タイトルホルダー」）。
  「現タイトルホルダー」は今までの入口の焼き込みのまま（`<title>` は「タイトル戦 現タイトルホルダー・歴代優勝者 | …」、og:title・og:image・canonical は `/title/` のまま、`?year=` は sitemap に載せない）
- 年を選ぶと `assets/title.js` が `title/years.json`（`build_years_data()`。2026-10-09 時点で54年・約57KB）を1回だけ読み、空の並び `#title_year_cards` に入口と同じ写真カードを組み立てる。再読み込みはせず、`history.replaceState` で `?year=` を書き換える。
  `search.json` には決勝日と期の表記が無いため、別のファイルにした
- 出すのはその年（`period_year()`、検索の年と同じ）に決勝のあった期すべての1位（第26期王位戦は2枚、年2回の大会は2〜3枚）。並びは決勝日の降順で、月日の無い期（`YYYY-XX-XX`・日付が空。2026-10-09 時点で243期）は月日のある期の後ろに大会の表示順。
  帯は大会名で、同じ年に同じ大会が2期以上あるときだけ期を足す（例「JPML WRCリーグ 第17期」、24組）。カードを押すと期ページ（「現タイトルホルダー」のカードは大会ページ）
- 検索している間は、今までどおり本来の内容（年の切り替えの表示を含む）を隠す

## データ源

新しいスプレッドシート `<ライブ用スプレッドシートの ID>`（/live 用と同じ。値は `scripts/generate_title_pages.py` の `SPREADSHEET_ID`）の5タブ。

## 日付列の書式（#385、CHAT-0918-TP-12・TP-13）

「タイトル」タブの日付列は決勝日。その期の全行に同じ値を入れる。「XX」（小文字 `xx` も同じ）は仮（不明）の部分。

| 書式 | 意味 | 期ページの対局日 |
|---|---|---|
| `YYYY-MM-DD` | 確定した日付 | YYYY年M月D日 |
| `YYYY-MM-XX` | 年月まで（日が不明。予定の行など） | YYYY年 |
| `YYYY-XX-XX` | 年だけ。公式HPの「年度」を暦年とみなした仮の値（#385 の (B)）。後で実際の対局日に直す（#408） | YYYY年 |
| 空 | 不明 | 出さない |

- 「XX」を含む値は年度とも月とも書かない（予定の月は前後することがあるため、平野さん）。読めない値は出さずに警告する
- 入口の並び（決勝日の降順）では「XX」を0とみなす。検索の年（`period_year()`）は3つの書式のどれからも年を拾う
- 2026-09-19 時点（全3,271行）: `YYYY-MM-DD` 698 / `YYYY-MM-XX` 40 / `YYYY-XX-XX` 937 / 空 1,596 / それ以外 0。表示=Y の行に `YYYY-MM-XX` は無い

## URL の解決（_redirects）

`html_handling: "none"` はディレクトリの index を解決しないため、`_redirects` に次の3行を置く。

- `/title  /title/  301`
- `/title/  /title/index.html  200`
- `/title/:slug/  /title/:slug/index.html  200`（プレースホルダを含む行は動的ルールになり、それ以降の行も動的扱いになるため、ファイルの末尾に置く。
  /live の生成部分〈`# live: generated`〜`# live: end`〉より後ろに置き、/live の 301 が動的ルールの上限〈100行〉に数えられないようにする、#418。
  `generate_live_pages.py` の `update_redirects()` は目印の間だけを書き換えるので、この位置は保たれる）

`/title/<slug>`（末尾スラッシュなし）は、大会ごとに `/title/<slug>  /title/<slug>/  301` を `_redirects` に手で1行ずつ書く（20行、#455）。
大会を足したら1行足す（`scripts/tests/test_title_redirects.py` が検査）。`/title/:slug  /title/:slug/  301` のワイルドカードは `/title/index.html` にも一致して壊れるため置かない。
確認は wrangler 同梱の asset-worker（miniflare）の `parseRedirects`・ルール照合のコードを抜き出して行った（CHAT-0916-TT-10。
セッション環境では `wrangler dev` が動かない）。本番の応答は第1段のマージ後に確認済み（CHAT-0916-TT-16: `/title` → 301、`/title/`・大会ページ・期ページ → 200、`/title/<slug>` → 404）。

## 取り込み時の文字化け（CHAT-0916-TT-07〜TT-08）

- 取り込み用 CSV（UTF-8）のうち「髙」（U+9AD9）だけが置換文字2つに化けた。この文字は CSV の中で唯一 JIS X 0208（Shift_JIS / EUC-JP）に無い文字で、
  取り込みまでのどこか（ダウンロード後に開いた・保存したアプリ、アップロード時の文字コードの判定など）で JIS X 0208 の範囲に変換されたとみられる。どの段階かはセッションからは確かめられない
- 防ぐ手順: CSV はダウンロードしたファイルを他のアプリで開いて保存せず、そのまま「インポート」する。取り込み後は生成スクリプトを実行する（置換文字・制御文字があれば止まる）
- 「タイトル」タブは平野さんが直していく正本のため、取り込み用 CSV との差分は記録するだけで生成は止めない（CHAT-0916-TT-10 の判断 E）
