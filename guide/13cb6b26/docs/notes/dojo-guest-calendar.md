# 道場部ゲストのカレンダー同期（#390）

連盟サイトの告知画像を読み、「mj_道場部ゲスト」Google カレンダーにまだ無い予定を足す。
方式の調査は `docs/logs/CHAT-0921-DJ-01.md`、実装は `docs/logs/CHAT-0921-DJ-02.md`。

## 仕組み

- 画像の在りか: 連盟サイトの「本部道場ゲスト表」（`https://www.ma-jan.or.jp/dojo_guest.html`）。
  月ごとに4枚（道場部のゲスト・スタッフ、麻雀教室の講師・スタッフ）が載る。
  見出し「…YYYY年M月ゲスト　～道場部～」と直後の `<img>` の対応で画像の URL を取る（URL の規則には頼らない）
  - **見出しが誤っていると、その月は読まない。** ページの最も新しい月（種別を問わず見出しから取れた年月）に「ゲスト　～道場部～」が無ければ、
    その月の見出しと画像の一覧を #426 に知らせる（下の「通知」）。見出しやファイル名から推定して読むことはしない（`docs/decisions/dojo-guest.md`）
  - 掲載は前月下旬〜当月上旬とばらつく（実測: 2026年7月分 6/22、8月分 8/6、9月分 9/1）。X の告知のほうが早い月がある
- 読み取り: `scripts/lib/dojo_guest.py`。Claude API の画像入力（`claude-opus-5`、SDK は `anthropic==1.7.0` に固定）で、
  日付・名前・マスに付いた表示（NEW など）を JSON で受け取る。
  種別を選べるので、麻雀教室の講師・スタッフの画像にも同じ読み取りが使える（書き込みは道場部ゲストのみ）
  - **西暦は画像に書かれていない**ので、年はページの見出しから取る。画像から読むのは月だけで、対象の月と違えば止まる（画像の取り違えの検知）
- 突き合わせと書き込み: `scripts/sync_dojo_calendar.py`
  - **読み取った名前は「プロ」シートの登録名（在籍 Y）と完全一致で照合する。1件でも一致しなければ書き込まない。**
    2026年8月分の画像で「福島佑一」を「福島祐一」と読み違えた実例がある（#390 の調査）
  - 予定は終日1日1件、タイトル「<登録名>（道場部）」、説明欄は X のプロフィール URL（ID が無い人は空）。既存の予定に合わせてある
  - この同期が作った予定には私的拡張プロパティ `ryoei=dojo` が付く。手で足した予定と見分けるため
  - **まだ書き込んでいない月**（その月にこの同期が作った予定が1件も無い月）: 同じ日に同じ名前の予定が無ければ足すだけ。既にある予定は変えない
  - **書き込み済みの月**（この同期が作った予定が1件でもある月）: **実行した日（日本時間）以降の日だけ**を画像に合わせる。前日までは触らない。
    名前が替わった日は予定を書き換え（名前と X の URL）、画像から無くなった日は削除、増えた日は追加する。
    **書き換え・削除するのはこの同期が作った予定だけ。** 手で入れた予定（目印なし。2026-09 までの約1,450件）は変えず、画像と違えば「食い違い」として通知に書く。その日には足さない
  - **同期が作った予定を手で直した場合**（目印は残る）: 画像が差し替わらないかぎり、定期実行も入力なしの手動の書き込みも書き戻さない。
    画像が差し替わったときは画像を正とし、差し替わった画像と違えば自動更新で画像に合わせ直す（通知の「変更前 → 変更後」に出る）
  - 読み取りの応答が壊れている・日付が月の範囲外・同じ日が重複・名前が空のときは、書き込まずに止まる
- 通知: 常設issue #426「道場部ゲストの取り込み」（ワークフローはタイトルで探す）。**新しい画像を読んだときは、追加が0件でもコメントする**
  （平野さんが X の告知を見て先に手で登録した月は追加0件になるが、新規ゲストと当月誕生日は知らせたいため。2026-09-21 に条件を変えた）。
  画像が前回から変わっていない日は何も出さない。**同期が失敗したときも、失敗したことと実行ログを #426 にコメントする**（#472。以前は通知のステップが飛ばされ、メールだけだった）。
  **最も新しい月に道場部ゲストの見出しが無いときも、別のコメントで知らせる**（見出しの誤記の疑い。同じ見出し・画像の組では1回だけ。組が変わるか見出しが揃うまで繰り返さない。実行は成功で終える）。
  この判定はページを読んだ実行だけで行う（「画像のURL」を指定した実行はページを読まない）。
  書き込み済みの月は、追加する予定の代わりに当日以降の「変更前 → 変更後」と手で入れた予定との食い違い、自動で更新したか・止めたか（理由）を書く。
  コメントには、追加する予定・新規ゲスト（画像の NEW 表示 / 過去の予定に一度も出ていない。どちらで判定したかを書く）・
  その月に誕生日のゲスト（名簿の誕生日、`scripts/lib/birthdays.py`）・画像の注記・照合できない名前が載る
- ワークフロー: `.github/workflows/sync-dojo-calendar.yml`
  - 毎日 07:12 JST に見に行く。週次のジョブ（03:00〜06:23 JST）と重ねていない
  - 見る画像は、当月（日本時間）とページの最も新しい月の2枚（同じなら1枚）。当月の画像がページに見つからない（見出しの誤記）ときは、
    手動実行で読んで前回の状態に残した当月の画像を見る。翌月分が出た後の当月の差し替えにも気づくため
  - **新しい月は書き込まない**（差分と通知だけ）。書き込むのは、手動実行で「カレンダーに書き込む」を選んだときだけ
  - **書き込み済みの月の画像が差し替わったときだけ、定期実行が当日以降を自動で直して通知する**（`--auto-update`。手動実行には付かない）。
    照合できない名前が1件でもあるとき、または当日以降の変更（書き換え・削除・追加の合計）が **3件以上**（`AUTO_UPDATE_LIMIT`）のときは、直さずに通知だけにする。
    このとき、その画像に「保留」の印を前回の状態に付ける。反映は、内容を確かめてから「カレンダーに書き込む」を付けた手動実行で行う（保存した読み取り結果で、同じ範囲を直し、印を消す）
  - **入力なしの手動の書き込みが書き込み済みの月を直すのは、保留の印があるときだけ。** 印が無ければ「書き込み済みの月のため変えていません」と出して触らない
    （保存した読み取り結果は手直しより古いことがあるため）。まだ書き込んでいない月の初回の追加はこれまでどおり行う。
    「画像のURL」と「対象の月」を指定した手動の書き込みは、印に関係なく指定の月を当日以降で画像に合わせる（手直しも画像に戻る。途中で失敗した月のやり直しに使う）
  - 前回の状態（`dojo-state.json`）を Actions のキャッシュに置く。中身は画像ごとの Last-Modified と**検証を通った読み取り結果**、見出しの通知を出した組
  - 画像が前回から変わっておらず読み取り結果があれば、Claude API を呼ばない。書き込みの指定が無ければ何もせず通知もしない。
    **書き込みの指定があれば、保存した読み取り結果で照合と突き合わせをやり直して書き込む**（通知で確かめた一覧がそのまま入る）
  - 画像は変わっていないが読み取り結果が無い（キャッシュが消えた、2026-10-02 より前の形の状態）ときは、読み直して保存する。通知は出さない。
    このとき書き込みの指定があれば、読み直した結果をそのまま書き込むので、先に書き込みなしで実行して出力を確かめる
- 費用: 画像は 848×1200 で視覚トークン 1,333。読み取りは月1回で、**2026-09-21 の実績は2回（成功1・失敗1）で $0.05**。
  入力の $5/1M から見積もった $0.007/回より大きいのは、応答と思考の分が乗るため。月の上限額は $2 にしてある

## 設定手順（平野さん、Windows のブラウザで）

### (a) カレンダーをサービスアカウントに共有する

Google Cloud のプロジェクト・サービスアカウント・鍵（`GCP_SA_KEY`）と、管理コンソールの
「予備カレンダーの外部共有オプション」は #379 のときに済んでいる（`docs/notes/birthday-calendar.md`）。ここで足すのは共有だけ。

1. https://calendar.google.com/ を開く（`ryoei.net` のアカウント）
2. 左の一覧の「mj_道場部ゲスト」にカーソルを合わせ「︙」→「設定と共有」
3. 「特定のユーザーまたはグループと共有する」→「ユーザーやグループを追加」→
   サービスアカウントのメールアドレス（`…@….iam.gserviceaccount.com`。誕生日カレンダーの共有に出ているものと同じ）を入れる
4. 権限を「**予定の変更**」にして「送信」
   - 「予定の詳細の表示」までしか選べないときは、管理コンソールの外部共有の設定が戻っている。
     `docs/notes/birthday-calendar.md`「設定手順」の手順5-5 を見る
5. 同じ画面の「招待状の自動承諾」を「招待状を表示しない」にする（第三者の招待で予定が紛れ込まないようにする）

### (b) Claude API のキーを発行して登録する

2026-09-21 に実際に通した流れ。

1. https://console.anthropic.com/ を開き、ログインする
2. 左の「Settings」→「Limits」で、**月の利用上限**を設定する。2026-09-21 は **$2** にした。
   この同期が使うのは月 $0.05 程度なので十分で、取り違えや繰り返し実行で費用が伸びるのを防げる
3. 左の「API keys」→「Create Key」→ 名前（例: `ryoei-pro-dojo`）を入れる
   - **「ID連携（identity federation）で鍵を使わない方法」を勧めるダイアログが出る。「APIキーで続ける」を選ぶ。**
     GitHub Actions からの ID 連携は後で改善として検討する（鍵を置かずに済む、#430）。今回は鍵で通した
   - **有効期限は「なし」**にする（期限切れで毎月の取り込みが止まらないようにする）
4. 表示されたキーをコピーする
   - キーはこの画面を閉じると二度と表示されない。コピーし損ねたら作り直す
5. https://github.com/retroeater/mj/settings/secrets/actions を開く
6. 「New repository secret」→ Name に `ANTHROPIC_API_KEY`、Secret にコピーしたキーを貼る →「Add secret」
7. コピーしたキーはメモ帳などに残さない（残した場合はファイルを削除し、ごみ箱も空にする）

### (c) カレンダーIDを変数に登録する

1. https://github.com/retroeater/mj/settings/variables/actions を開く
2. 「New repository variable」→ Name に `DOJO_CALENDAR_ID`、Value に
   `c_vr4jbqlqs6tpd5i5cpt2ujv2lk@group.calendar.google.com` を貼る →「Add variable」

### (d) 手動実行で確かめる

(a)〜(c) が済んでから行う。ワークフローは `cloudflare` にマージされてから実行できる（既定ブランチに無いワークフローは起動できない）。

1. https://github.com/retroeater/mj/actions/workflows/sync-dojo-calendar.yml を開く
2. 「Run workflow」→ 入力は空のまま、「カレンダーに書き込む」のチェックは**外したまま**実行する
3. 実行結果の Summary に「読み取り 22件 / 照合できない名前 0件 / 既にある予定 22件 / 追加 0件」と出ることを確かめる
   （2026年9月中に実行した場合。9月分はすでに手で入っているので、追加は0件になる）
   - 「照合できない名前」が出たら、画像の読み違いか、「プロ」シートに無い名前（退会者・改名）。その名前を Claude Code に伝える
4. 翌月分の画像が出てから同じ手順で実行すると、「追加 20件前後」と新規ゲスト・当月誕生日が出る。
   内容を確かめたうえで、「Run workflow」→「カレンダーに書き込む」にチェックを入れて実行する
5. カレンダーで、予定のタイトルが「<登録名>（道場部）」になり、説明欄に X のリンクがあることを確かめる

### (e) 毎日の実行を有効にする

`.github/workflows/sync-dojo-calendar.yml` の `SCHEDULE_ENABLED` を `'true'` にする（Claude Code に頼む）。
`'false'` の間は、毎日 07:12 JST の実行が何もせずに終わる。

**(a)〜(e) は 2026-09-21 に済ませた**（下の「初回の実行」）。この節は、設定をやり直すときのために残してある。

## 手動実行の入力

| 入力 | 使う場面 |
|---|---|
| 画像のURL | 連盟サイトに載る前に X の画像で試すとき、過去の月をやり直すとき。空なら連盟サイトの最も新しい月 |
| 対象の月（YYYY-MM） | 画像のURLを指定したときは必須。読み取り結果の年月がこれと違えば止まる |
| カレンダーに書き込む | 外すと差分を出すだけ。既定は外れている |

コマンドラインから動かすときは次のとおり（`--compare` 以降はカレンダーの認証が要る）。

```
python3 scripts/sync_dojo_calendar.py                      # 画像を読んで一覧と照合の結果を出す
python3 scripts/sync_dojo_calendar.py --compare            # カレンダーを読んで追加する予定を出す
python3 scripts/sync_dojo_calendar.py --compare --apply    # 追加する予定を書き込む
python3 scripts/sync_dojo_calendar.py --entries-file x.json  # 読み取り結果を与える（Claude API を呼ばない）
```

## 初回の実行（2026-09-21）

`cloudflare` で apply なしの手動実行を行い、2026年9月分の画像で次を確かめた（CHAT-0921-DJ-03）。

```
2026年9月 ゲスト　～道場部～（https://www.ma-jan.or.jp/wp-content/uploads/202609R.jpg）

読み取り 22件 / 照合できない名前 0件 / 既にある予定 22件 / 追加 0件

### 新規ゲスト
- 大久保隼人（画像のNEW表示 / 過去の予定になし）

### 9月が誕生日のゲスト
- 樫野凪（09/25）
```

- 読み取った22件は「プロ」シートの登録名とすべて一致し、カレンダーの既存22件とも日付・名前が一致した（追加0件）
- カレンダーを読めたことで、サービスアカウントへの共有 (a) が効いていることも確かめられた
- 続けてもう一度実行すると「画像は前回の読み取りから変わっていません。何もしません。」で終わり、Claude API を呼ばないことを確かめた
- このときは通知が出なかった（当時は「追加も照合の失敗も無いときは通知しない」条件だったため）。
  **平野さんが先に手で登録した月は追加0件になり、要望（新規ゲスト・当月誕生日の通知）が満たされない**ので、
  2026-09-21 に「新しい画像を読んだときは追加0件でも通知する」へ変えた（CHAT-0921-DJ-04）。
  すでに読み取り済みの9月分は、画像が変わらないかぎり改めて通知されない。**#426 への通知の見え方は、10月分の画像が出たときが初めてになる**

## 毎月の運用

1. 翌月分の画像が連盟サイトに載ると、毎日 07:12 JST の実行がそれを読み、#426 にコメントする（追加する予定・新規ゲスト・その月に誕生日のゲスト）
2. 平野さんが内容を確かめる
3. 良ければ [ワークフロー](https://github.com/retroeater/mj/actions/workflows/sync-dojo-calendar.yml)を
   「カレンダーに書き込む」にチェックを入れて手動実行する（入力は空でよい）。通知で確かめた読み取り結果がそのまま書き込まれる（Claude API は呼ばない）
4. 「照合できない名前」が出ているときは書き込まれない。名前を Claude Code に伝える

#426 に「見出しが見つかりません」の通知が出たときは、通知にある画像が道場部ゲストの表かを確かめ、
「画像のURL」と「対象の月」を指定して書き込みなしで手動実行する（読み取り結果が #426 に出る）。良ければ同じ入力で「カレンダーに書き込む」を付けて実行する。

画像が同じうちは、書き込みの指定の無い実行は Claude API を呼ばずに終わる。通知も出ない。

月の途中で書き込み済みの月の画像が差し替わると、翌朝の定期実行が当日以降を直し、#426 に「変更前 → 変更後」を書く（平野さんの作業は無い）。
通知に「自動では更新していません」と出たときは、内容を確かめ、良ければ「カレンダーに書き込む」を付けて手動実行する（入力は空でよい。当月と最も新しい月の両方が対象になる）。
「手で入れた予定との食い違い」は同期では直さないので、必要なら手で直す。

X の告知で先にゲストの変更を知ったときは、同期が作った予定を手で直してよい。入力なしの「カレンダーに書き込む」（翌月分の書き込みなど）では書き戻されない。
後で連盟サイトの画像が差し替わると、画像のとおりに直される（手直しと同じなら変更なし）。

## 分かっていること・注意

- **名前の照合は完全一致。** 読み違い（福島佑一／福島祐一）も、改名（咲良美緒→さくら美緒、川上玲→川上レイ）も、退会者も、同じく「一致しない名前」として止まる。
  表記ゆれを自動で直さないのは、誤った名前で予定を作らないため
- 連名の予定（「松田彩花・伊達朱里紗（道場部）」のような形）は、そのまま1件として読み取る。「プロ」シートには無い名前になるので照合で止まる。
  その月は手で入れるか、Claude Code に相談する
- 「過去の予定になし」の判定は、カレンダーにある予定（2021-01-04 以降）だけを見る。それ以前に出た人は新規と出ることがある
- 画像には NEW のほかに「9周年イベント」「店内改装のためお休み」などの表示が入ることがある。マスに付いた表示は通知に出るが、予定の内容には反映しない
- 2026年10月は、道場部ゲストの画像（202610R.jpg）の見出しが「2026年10月ゲスト　～麻雀教室～」と誤っていた。同期は9月を最新月とみなし、
  9/29 から掲載されていた10月分に気づかなかった（#390。連盟サイトへの修正の依頼は平野さん）。これを受けて見出しの通知を足した
- 10月の見出しは 2026-10-02 のうちに「ゲスト　～道場部～」へ直った
- 入力なしの手動の書き込みは、2026-10-02 の修正までは書き込み済みの当月を保存した読み取り結果で直していた（手で直した予定を書き戻すおそれがあった）。今は保留の印があるときだけ直す
- 書き込み済みの月の自動更新（予定の書き換え・削除）は、2026-10-02 時点で本番ではまだ一度も動いていない（実際の差し替えが起きていない）。
  サービスアカウントの権限は「予定の変更」で、書き換え・削除もこの権限の範囲だが、本番では未確認
- 教室講師・スタッフの画像（#390 の残り）は、`--kind teacher` などで読み取りまではできる。書き込み先のカレンダーは決まっていない
