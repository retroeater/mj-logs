# 「ログ」の駅の一覧（国土数値情報）

「ログ」（#367・log/〈#639〉）の【2】自動変換後の「駅」「駅の候補」と都道府県（「駅」の【県】の印）は、Google の値を使わず、
国土数値情報から作った駅の一覧で決める（2026-10-29 の決定。Google の規約で Places から保存してよいのは place_id だけ）。

## 一覧

- ファイル: `data/stations_n02.json`（公開しない。`data` は `.assetsignore` にある）。1駅1行の `[駅名, 都道府県, 緯度, 経度]`、約9,000駅・約450KB
- 作り方: `python3 scripts/build_station_list.py [--n02 N02-25] [--n03 20250101]`（標準ライブラリのみ。`nlftp.mlit.go.jp` から約450MB を取り、作業ファイルは消す。約12分）
  - 駅: 国土数値情報「鉄道」（N02）の駅。N02 の駅は線（ホームの範囲）なので頂点の平均を点にし、グループコード（300m 内の同じ名前の駅）ごとに1つにする
  - 都道府県: 国土数値情報「行政区域」（N03）の都道府県ごとの面に駅の点が入るかで付ける（オープンデータの点と面だけ。Google の座標は使わない）。面に入らない駅（海沿いなど）は最も近い駅の県（N02-25・N03-20250101 では「大井競馬場前」の1駅）
- 更新: 年1〜数回、手で取り直す。N02 は年1回（2026年4月に 2025年度版〈2025-12-31 時点〉）、N03 は毎年1月1日時点。取り直したら `python3 -m unittest scripts/tests/test_stations.py` を回し、差分（駅の増減）をログに書く
- 読む関数: `scripts/lib/stations.py` の `StationList`（`lookup`・`nearby`〈800m 内の駅、自分は 0m〉・`resolve`〈本文の駅 → 一覧の駅〉）

## 決め方（`convert_x_posts.py` の `station_cells()`）

- 「駅」: 本文の駅（Claude が読む `stations`）のうち、一覧にある最初の駅（一覧の名前。東京都の外は【県】を付ける）
- 同じ名前の駅が複数の都道府県にあるとき: 本文のほかの駅から 3km 内の駅 → 無ければ東京都の駅 → それでも決まらなければ最初の駅で要確認（「同じ名前の駅が複数の都道府県にある」）。
  作業ブランチの `resource_logs.html` の駅で試すと、同じ名前の 642行のうち黙って誤るのは「【静岡】菊川」→東京都の2行だけ（2026-10-29）
- 「駅の候補」: その駅から 800m 内の一覧の駅（駅どうしの距離、`名前(距離m)` を近い順）
- 本文に駅が無い・一覧に無い（海外を含む）: 「駅」を空にして要確認（「本文に駅が無い」「本文の駅が一覧に無い（本文: …）」）。平野さんが【3】で駅を書く
- 既存の行（2026-10-29 まで）: 本文の駅を Claude Haiku で読み直して書き直した（CHAT-1029-LGN-07・08）。【2】だけでは飲食店の行の 22.5%（601行）で駅が空だが、【3】の駅（旧「ログ」の手書き）で上書きした後にページで駅が空の行は 2.6%（3,159行のうち 81行）。空の行は「駅なし」のまま載せ、必要なら【3】で埋める（#636）
- 駅の一覧を取り直したら: `convert-x-posts.yml` の `stations` の mode で、今の「駅」から計算し直す（dry-run で変わる行を確かめてから本番）
