# SNS ブック（選手の SNS の ID・画像の URL、#514）

選手の X・note・YouTube の ID と画像の URL を、ryoei.pro_選手の「プロ」「連盟プロ以外」から切り離して持つブック。
写真のリンク切れを自動で直す先にするため（正本・/live 用をサービスアカウントに共有しないで済むように）作った。決定は docs/decisions/saikyo.md の 2026-10-10 の節。

**2026-10-11 から、ページの生成と写真の検知はこのブックが正。** 旧列（「プロ」の XID・X画像・noteID・note画像・YouTubeID、
「連盟プロ以外」の X ID・X画像URL）は読まない。**旧列は 2026-10-12 に列ごと消した**（「プロ」の YouTube画像も一緒に、#327。消した後の見出しは「プロ」が 登録名・ソートキー・出身地・鳳凰Ampai・桜花Ampai・最終更新・表示、「連盟プロ以外」が 名前・名前かな・所属団体・所属補足）。
コードは旧列の見出しを求めない（`pro_sheet.fetch_pros()` は SNS の見出しを渡されると止まり、`sns.fetch_pros()` を使う）。**ID の直しは【2】で行う。**

## 生成の読み方（`scripts/lib/sns.py`）

- ページの生成は SNS の値をすべて `lib/sns.py` から読み、列の位置を持たない。`sns.fetch_pros()` は `pro_sheet.fetch_pros()` と同じ形で返し、SNS の見出し（XID・X画像・noteID・note画像・YouTubeID・YouTube画像）の値だけを SNS ブックから入れる。`sns.others()` は「連盟プロ以外」の行に X の値を入れて `NameBook` の形にする。title/ は「連盟プロ以外」の X ID・X画像URL を `sns.lookup()` の値で置き換える
- 通るもの: jpml_pros・saikyo・live・books・houou_race（`houou/` も）・title・wayhome・誕生日・道場部・jpml_test・`fetch_youtube_channels.py`・写真の検知
- 引く値: ID は【2】、画像の URL は【3】に【4】の空でないセルを重ねたもの（【4】の ID の列は使わない）。【2】の「-」は空と同じ（リンクもアイコンも出さない・代替アバター）。ID が空の SNS は画像も出さない。状態「一覧に無い」の行は使わない
- `lib/sheets.py` の `fetch_table()`（Sheets API、`sheets-reader`）で読む。1回の実行で1度だけ読む。【2】で名前が重複していたら生成を止める
- **【3】【4】の X画像URL は `_400x400`**（#558）。毎日の更新が前の値を残すときも `_400x400` に直して書く（下の「毎日の更新」）。ページで出す大きさは各生成スクリプトの定数で決め、`lib/x_images.with_size()` でシートの末尾によらず書き換える（books/ は凍結中で対象外。鳳凰戦の順位変動の丸〈28px〉とランキングの表のアイコン〈40px〉は `_80x80`〈2026-10-14〉、houou/ の選手の写真は `_200x200`。`generate_houou_race.py` の `IMAGE_SIZE` は houou/ の選手の写真にも効くので、丸は `CHIP_IMAGE_SIZE`、表は `generate_houou_pages.py` の `RANKING_ICON_SIZE` で小さくしている）
- 帰り道の写真の確かめ（`lib/wayhome.py` の `check_player_photos()`）は、この値（`_400x400`）に効く。読めなければ生成を止める（直す先は【2】の X ID か【4】）

## 検知と更新の役割

- **毎朝の検知（`check-image-links.yml`。`run-daily.yml` が `update-sns-book` の後に呼ぶ）は3つのジョブで画像を見る。** ジョブ `check` は `jpml_pros.html` の `<img>`（X・note・YouTube）、ジョブ `saikyo` は最強戦の写真（2026-10-13 から両方とも毎日。それまで `check` は週1回）、ジョブ `sns_book` はこのブックの実効の値（【3】に【4】を重ねた全行。ページに出ない行も見る）の画像（`scripts/check_sns_book_images.py`、2026-10-13 から）
  - `sns_book` が見る X の画像はシートの値の大きさ（`_400x400`）だけ。【3】に `_80x80` が残っていても `_400x400` に直して確かめる（#558）。既定アイコンは見ない。note・YouTube はシートの値のまま。ページで使う `_80x80` は `check`、`_200x200` は `saikyo` が見る
  - 結果は常設 issue「画像リンク切れの検知結果」（#352）の「SNS ブック」の節（`check` の節と別。各ジョブは自分の節だけを書き換え、全節で切れが無いと閉じる。閉じた後に切れが出たら、新しく作らずに #352 を開き直す〈2026-10-14 から〉）。所要は約4〜5分（1,313種類、2026-10-13）
- **X API を呼ぶのは SNS ブックの毎日の更新（`update-sns-book.yml`）だけ。** 写真の検知（`collect_saikyo_images.py`、更新の後）は X API を呼ばず、最強戦の写真（SNS ブックの実効の値）を HEAD で確かめ、取得できない選手の状態を【3】の X状態と【4】の有無で検知の issue に出す
- 【4】の値が取れない行は、状態「【4】手動補正の値が取れない(自動では直さない)」（2026-10-10 の決定）。それ以外は「【3】<X状態>」（上限で未取得・リンク切れ などは翌日以降の更新で取り直す）
- 更新が X API を呼べていない（認証の失敗・クレジット切れ・レート制限・トークンなし）行があるときは、issue に「自動解決は働いていません」の1行が出る
- **更新で【3】のページが使う値（SNS の ID・画像URL）が変わった日だけ、全ページを再生成する**（`update-sns-book.yml` のジョブ `regenerate` が `regenerate-page.yml` を `all` で呼ぶ）。【4】を直しただけの日は再生成されない（`regenerate-page.yml` を手動で `all`、または翌週月曜の定期の再生成）

## タブ

| タブ | 書くのは | 中身 |
|---|---|---|
| 【1】元データ | 機械（毎日置き換え） | シート（「プロ」「連盟プロ以外」）・名前・名前かな。「プロ」は在籍（「表示」が Y）の全員、名前かなは「ソートキー」。「連盟プロ以外」は名前のある全員、名前かなは「名前かな」の列。並びはシート > 名前かな > 名前（名前かなが空の行は名前の順で各シートの後ろ） |
| 【2】ID | 機械（名前の列と状態）・平野さん（それ以外の列） | 【1】の3列 + X・note・YouTube・備考 + 状態。**機械が書くのはシート・名前・名前かな・状態だけで、ほかの列はすべて平野さんの入力として扱う**（Instagram などは列を足すだけでよい）。名前で【1】と突き合わせ、入力ごと行を並べ替える。新しい人は行を足し、一覧から消えた人は消さずに状態「一覧に無い」で末尾へ回す（改名・退会で入力が消えないように）。SNS の列の「-」は確認済みのアカウントなし、空欄は未調査 |
| 【3】画像取得 | 機械 | シート・名前、SNS ごとに ID（取ったときの ID）・画像URL・取得日・状態。X は X数値ID（ハンドルを変えても変わらない番号）も持つ |
| 【4】手動補正 | 平野さん（見出しの1行だけ機械） | 【3】を上書きしたい人の行だけ。見出しは【3】と同じ（と備考）、空のセルは上書きしない。名前で引く。見出しは、空のときだけ毎日の更新が書く（`sheets_write.HEADER_ONLY`、2026-10-11 に書いた）。以後機械は書かない |

## 毎日の更新（`scripts/update_sns_book.py`）

`update-sns-book.yml` を Worker `mj-scheduler` が毎日 04:10 JST に起動する（入力 `scheduled`。docs/notes/scheduler-worker.md）。所要は約40秒。

1. 【1】を「プロ」「連盟プロ以外」から作り直す（変わったときだけ書く）
2. 【2】を【1】と名前で突き合わせて並べ替える。**書く前に、名前ごとの入力（空でないセル）が1つも変わらず・欠けていないことを確かめ、外れたら書かない。** 読んでから書くまでに【2】が変わっていたら書かない。書いた後に読み直して同じことを確かめる。名前の重複は止める
3. 【3】を作り直す。前の値を残し、取り直すのは次の行だけ:
   - X: ID が変わった・新しく入った行と、前の画像の、ページが使う大きさ（`_400x400`・`_200x200`・`_80x80`）とページで使わない大きさ（`_bigger`・`_normal`・原寸。`update_sns_book.CHECK_SIZES`、`_80x80` は 2026-10-14、残りは 2026-10-23 から）のどれかが HEAD で取れない行（アイコンを変えて配信元から消えた画像も、よく使う大きさは CDN のキャッシュが何日も 200 を返すため、キャッシュに残りにくい大きさも見る。`_mini` はキャッシュに残るので見ない。URL にクエリを付けてキャッシュを避けると、生きた画像も 404 になる。#352）と、**前の画像を別の X ID の行も指している行**（`shared_images()`。`_400x400` にそろえた URL ごとに X ID を大文字小文字を同一視して集め、2つ以上なら両方。既定アイコンは除く。状態「一覧に無い」の行も数える。届く画像でも別人のまま残るため、2026-10-19）を取り直す（取れる行・取り直せない行は前の値を残し、X画像URL だけを `_400x400` に直す。取得日は変えない。前の値を残した行のうち X数値ID が空のもの〈init で写したまま X API で取っていない〉の状態は「解決」でなく「シートから写した」）。取り直しても `_400x400`・`_200x200` は取れて一部の大きさだけ取れない写真は、取り直した URL を状態「解決(一部の大きさが取得できない)」で書き、その後は取得日から7日ごとにだけ取り直す（`PARTIAL_RETRY_DAYS`。毎日 X API を呼ばないため）。X API を呼んだ行は、名前・前の URL・今の URL・状態を1行ずつ出力する（dry-run では呼ぶ予定の行）。最強戦の写真の検知（`collect_saikyo_images.broken_urls()`）が確かめる大きさは `_400x400`・`_200x200` のまま。X 公式 API の user lookup（`collect_saikyo_images.py` の呼び出しと状態の分け方を使う、Secret `X_BEARER_TOKEN`）。**1回 30件まで**（`API_CALL_LIMIT`）。超えた分は「上限で未取得」で翌日に回る（前の値がある行は「リンク切れ・上限で未取得」、重複で取り直す行は「別の X ID と同じ画像・上限で未取得」で、前の値を残す）。認証の失敗・クレジット切れ・レート制限の後は呼ばない（終了コード1）
   - YouTube: `data/youtube_channels.json`（`fetch_youtube_channels.py` が API で取る）のチャンネルの画像。到達だけ HEAD で確かめる
   - note: **取らない。** note には公式に公開された取り方が無いため、写した値のまま到達だけ確かめる（切れたら「リンク切れ(取得しない)」）
   - ほかの SNS（【2】に足した列）: ID を写し、状態「取得しない」
   - 状態「一覧に無い」の人は前の値のまま

状態の文言: 解決・既定のアイコン・アカウントなし・アカウントなし(確認済み)・未入力・未取得・上限で未取得・リンク切れ・上限で未取得・別の X ID と同じ画像・上限で未取得（トークンが無いときは「…・未取得(トークンなし)」）・未取得(トークンなし)・取得したURLが取得できない・解決(一部の大きさが取得できない)・X API のエラー(…)・シートから写した（X は前の値を残した X数値ID の空の行。2026-10-19 から）・YouTube のデータから写した・確認済み(取得しない)・リンク切れ(取得しない)・未取得(取得しない)・YouTube のデータに無い・取得しない。

## 手動実行

`update-sns-book.yml` の入力 mode（dry_run は既定で真）:

- `check`: 読むだけ。タブ・見出し・行数、編集者か（ブックの名前を同じ名前で書き直して確かめる。見た目は変わらない）、【2】の入力のある名前の数、元の一覧（「プロ」「連盟プロ以外」の名前）の件数と名前かなのある行の数
- `init`: 使えない（「使えません」と出して終了コード 1。写す元の旧列を廃止したため、2026-10-12、#514）。2026-10-10 に実行済み
- `update`: 毎日の更新と同じ。dry-run では X API を呼ばず、呼ぶ予定の件数を出す
