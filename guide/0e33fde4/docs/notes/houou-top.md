# 鳳凰戦の新ページ `houou/`（トップ＋検索・ランキング・リーグ推移・順位変動）

鳳凰戦のページ群を `houou/` の下にモバイルファーストで作り直す仕様。親 issue は #518。
決定の一覧は docs/decisions/houou.md（2026-10-08）。ここには決定を画面・データに落とした仕様と、仮置きを書く。
仮置きは「（仮置き）」の印を付け、動作サンプルを見た後にまとめて確かめる。

## 目的

- 旧4ページ（`houou_ranking.html`・`houou_leagues.html`・`houou_race.html`・`houou_results.html`）を `houou/` にまとめ、スマホで使える形にする
- ランキングの集計を Python の生成に移す（#141。女流桜花・WRC は後で同じ部品を使う）
- 成績詳細を Google Charts から静的 JSON の自前の検索に置き換える（鳳凰戦の分だけ。女流桜花・WRC の成績詳細は据え置き、#111）
- 女流桜花（`ouka/`）へ横展開できる作りにする（出力は鳳凰戦だけ）

## 構成

| URL | 中身 | 旧ページ |
|---|---|---|
| `houou/` | トップ: 検索欄＋メニュー3枚＋説明文。`?name=` で選手の成績を同じページに出す | `houou_results.html`（置き換え） |
| `houou/ranking/` | ランキング9部門（#141 の移植） | `houou_ranking.html?sheet=鳳凰` |
| `houou/leagues/` | リーグ推移（移設） | `houou_leagues.html` |
| `houou/race/` | 順位変動（移設＋URL で期・リーグ指定） | `houou_race.html` |

ファイル（すべて生成物）:

- `houou/index.html`・`houou/search.json`（選手名の索引）・`houou/results/<選手名>.json`（選手ごとの成績、1,296ファイル〈2026-10-08 時点〉）
- `houou/ranking/index.html`（9部門を焼き込む）
- `houou/leagues/index.html`・`houou/leagues/data.json`（名前は仮置き）
- `houou/race/index.html`・`houou/race/<期>-<1|2>.json`
- JS・CSS は `assets/houou.js`（名前は仮置き）と `style.css` の `houou/` の節。共通の CSS 変数（幅・字の大きさ・カード）は順位変動の値を元にする（DESIGN.md は作らない）

生成:

- `scripts/generate_houou_pages.py` 1本が `houou/` 全体を書き出す（`regenerate.py` の `OUTPUT_OVERRIDES` に `"houou_pages": "houou/"`）。大会の設定（シート名・出力先・ページ名）を1か所に持ち、既定は鳳凰
- 集計は `scripts/lib/ranking.py`（9部門）・`scripts/lib/results.py`（選手ごとの成績・索引）。リーグ推移・順位変動は既存の `lib/leagues.py` と `generate_houou_race.py` の部品を lib に寄せて import する
- 既存の `generate_houou_leagues.py`・`generate_houou_race.py` は旧ページを廃止するまで残す（二重生成の期間がある）
- サブディレクトリなので `lib/page.py` の `asset_prefix` を使う。navbar.js の href はルート相対（docs/notes/static-generation.md「navbar.js と検索欄」）
- テスト（`scripts/tests/`）: ランキング9部門の集計（小さな固定データ）・成績 JSON の形・索引の正規化

## 画面ごとの仕様

### 共通

- 幅: トップ・検索結果の要約とグラフ・順位変動は最大 400px、ランキングと成績詳細の表は最大 720px で中央寄せ。スマホでは表だけ横スクロール
- navbar は共通のまま（ナビの位置の方針は #417、新サイト送り）
- 共有ボタン: 全ページに置く（既存の共通部品 `assets/share.js`・`scripts/lib/share.py`、#409）。表示中の状態（`?name=`・`?division=`・`?term=&league=`）を JS で共有 URL と文言に反映する（部品は生成時に焼き込む作りなので、差し替えの小さな拡張が要る）
- OGP: サイト共通の画像。選手ごとの画像は作らない

### トップ `houou/`

- h1「鳳凰戦（リーグ戦）」、title「鳳凰戦（リーグ戦） | ryoei.pro」（`title/houou/` の決勝の記録と区別する）
- 上に検索欄、その下にメニューのカード3枚（ランキング「通算得点など9部門」・リーグ推移「選手ごとの所属リーグの推移」・順位変動「期・リーグごとの節単位の順位」。文言は仮置き）、その下に説明文（`.mj-lead`、対象の期の範囲をデータから）。画像は使わない
- 検索欄（手本は `title/index.html`・`assets/title.js`）: `type="search"`・`aria-controls`。入力に合わせて候補を最大10件（選手名のみ、NFKC で正規化した部分一致。ふりがな・ローマ字は持たない。`title/` も氏名だけ）
  - 候補を選ぶと、検索欄の下にその選手の成績を出し、URL を `?name=` に置き換える（`history.replaceState`）。メニューは下へ
  - 完全に打って Enter で一致が1件なら、その選手を出す
  - 結果の表示中も検索欄は上に残す。「×」でトップのメニューに戻る
  - 結果の表示中の title と共有の文言は「前原雄大 | 成績詳細 | 鳳凰戦 | 日本プロ麻雀連盟 | ryoei.pro」の形
- 対象の選手は「鳳凰」タブ V列「表示」が Y の行のある選手全員（退会者も出す。ランキングの「在籍者のみ」とは独立）

### 選手の成績（トップの中）

- 並び: 選手名・通算の要約（出場期数・通算得点・最高リーグ。要約の項目は仮置き）→ 通算の推移 → 期ごとの表
- 通算の推移: JS で描く SVG のローソク足（期ごとに 期首の通算→期末の通算。上昇は暖色・下降は寒色）。Google Charts は使わない
- 期ごとの表: 新しい期が上。スマホは「期・リーグ・順位・結果・合計」、行を押すと第1〜13節を開く。720px では全列
- 各行から順位変動 `houou/race/?term=<期>-<1|2>&league=<リーグ>` へリンク（順位変動の対象の期〈第23期〜〉だけ）

### ランキング `houou/ranking/`

- 9部門（通算得点・通算得点/期・期最高得点・期単位浮き率・期連続浮き回数・節最高得点・節単位浮き率・節連続浮き回数・連続昇級回数）を1ページに焼き込み、セレクトで切り替える（インラインの `onchange` はやめ、JS で付ける）。既定は「通算得点」、`?division=<部門名>` を受ける
- 既定は「プロ」タブに在籍する選手のみ（#371）。表の上のチェックボックスで全員に切り替え、URL は `?all=1`
- h1 の下の1行と title・description に「第N期前期／後期 終了時点」（#228。例「第43期前期 終了時点」。期はデータの最新から。文言は仮置き）
- 上位100件（同点で100を超える分の扱いは、現行の挙動を確かめて合わせる）
- 前回比・直近5節（#234）は後の課題
- 進め方（#141 本文）: 集計だけ先に Python へ移植し、現行ページ（ブラウザの計算）の9部門×上位100件と突き合わせる。違いがあれば止めずに一覧にし、まとめて平野さんに確認を依頼する

## データの持ち方

- 正本は「鳳凰」タブ（A名前・B期・C前後・Dリーグ・Eリーグキー・F順位・G結果・H合計・I〜U 第1〜13節・V表示・Wプロ・X備考）。V="Y" の行だけ使う（2026-10-08: 15,416行、1,296名、第17期〜第43期）
- `houou/search.json`: 選手名の一覧（候補の表示用。各選手の出場期の範囲など、候補に添える情報は仮置き）
- `houou/results/<選手名>.json`: その選手の全行（期・前後・リーグ・順位・結果・合計・各節）。ファイル名は選手名そのまま（URL エンコードされる）
- 改名・同名は名寄せしない（シートの「名前」が同じなら同じ選手）。名寄せが要る例が出たら別 issue

## 非公開の形と公開の方針

- 段1（docs/new-page-checklist.md）: 全ページ noindex（`NOINDEX_TAG`）、navbar・sitemap・`llms.txt`・既存ページからのリンクに載せない。`assets-check.yml` の `allowed()` に `houou` を足す（配信の対象の決定は docs/decisions/publishing.md の書き方で残す）
- 公開の issue は、動作サンプルの後の実装の指示で起票する
- 公開の段（方針だけ）: 公開と同時に旧4ページを `houou/` 配下へ 301（`?name=`・`?division=` を引き継ぐ）。公開の条件は、プレビューと本番（未公開の形）での平野さんの iPhone での確認。告知の有無は公開の issue で決める。navbar「鳳凰戦」の項目は公開の issue で決める（仮置き: トップ・ランキング・リーグ推移・順位変動）
