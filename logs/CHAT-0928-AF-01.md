【Claude作成】Claude Code 向け指示：「連盟ch」の毎日の取り込みの「テスト」ステップが、テスト成功時に失敗する件の修正 Chat-Ref: CHAT-0928-AF-01 共通手順: CLAUDE.md「Chat-Ref」「ブランチ運用」「作業ログ」節のとおり（識別子確認 → origin/cloudflare を起点に work/<識別子>〈クラウドでは worktree を使わない。docs/notes/cloud-sessions.md〉 → ログ先行push → 最終報告の Chat-Ref の行の直前に「ログ（公開）」の行、最後の行に Chat-Ref）

0. 着手前に、このログの「指示」欄の末尾が、この指示文の末尾（最後の章の最後の行）と一致しているか確認し、一致しなければ作業せず報告する。このセッションの最初の指示なので、識別子 AF が他のセッションで使われていないかも確かめる。

目的 ワークフロー「『連盟ch』の毎日の取り込み」の実行 #14（約11時間前）が、update ジョブの「テスト」ステップで失敗し、regenerate ジョブは実行されなかった。原因を確かめて直す。
決定（平野さん、2026-09-28）

* テストをわざと落とす試験はしていない（シートのフィルタの有無の動作チェックはした覚えがある）。

前提（チャット側。平野さんの決定ではない。実物で確かめ、違えば止まる）

* 平野さんのスクリーンショットでは、「テスト」ステップのコマンドが `python3 -m unittest discover -s scripts/tests && exit 1` と表示され、出力は「Ran 253 tests … OK」の後に `Error: Process completed with exit code 1.`。チャット側の見立ては「`&&` のためテストが通ると `exit 1` が走る。書き間違い」。unittest は失敗時に自分で非ゼロ終了するので、`&& exit 1` を消せば足りる。
* 出力の「テストタブの gid が引けない」「URLError boom」の警告は、テストの中で起こしている例外の出力と見ている。
* 平野さんの「フィルタの有無の動作チェック」が、この行を入れた作業と関係している可能性がある。

手順

1. 対象のワークフローのファイルと行を特定し、`git log -S` 等でその書き方が入ったコミット（Chat-Ref・日時・関係する issue）を突き止める。`.github/workflows/` のほかのファイルに同じ種類の誤り（成功時に `exit 1` になる書き方など）が無いかも調べる。前提の見立てが違えば、分かったことを書いて止まる。
2. 修正する。着手前に docs/notes/branch-operations.md「ワークフローを変更したとき」を読む。作業ブランチでの手動実行が、本番のスプレッドシートへの書き込みや cloudflare への push を伴わずに済むかを先に確かめ、伴わずに済む場合だけ実行して「テスト」ステップが通ることを確かめる。伴うか判断できない場合は実行せず、その理由を書く。
3. 影響を調べてログに書く: この書き方が入ってから失敗した実行（見られる範囲で。クラウドで見られなければ「未確認の項目」へ）、止まった処理（層1の追記、【1】【2】への書き込み、regenerate による /live・title/ の再生成）、マージ後の次の実行で自動的に追いつくか、それとも手動で再実行が要るか。

止まる条件

* 前提の見立て（原因）が実物と違う。
* 同じ目的の issue や、同じファイルを変更している未マージの work/ ブランチがある（`git branch -r --no-merged origin/cloudflare` で列挙して確かめる）。
* 修正が `.github/workflows/` の該当行以外にも及ぶ必要がある。

完了条件

* 修正を作業ブランチに push し、cloudflare へはマージせず「判断待ち」で止める（ワークフローの変更は平野さんの判断でマージする）。
* ログに手順1〜3の結果があり push 済み。
* ターミナルへの最終報告の Chat-Ref の行の直前に `ログ（公開）: https://github.com/retroeater/mj-logs/blob/main/logs/CHAT-0928-AF-01.md` を書き、最後の行に `Chat-Ref: CHAT-0928-AF-01` を書く。
