決定（平野さん、2026-09-28）

* テストをわざと落とす試験はしていない（シートのフィルタの有無の動作チェックはした覚えがある）。

前提（チャット側。平野さんの決定ではない。実物で確かめ、違えば止まる）

* 平野さんのスクリーンショットでは、「テスト」ステップのコマンドが `python3 -m unittest discover -s scripts/tests && exit 1` と表示され、出力は「Ran 253 tests … OK」の後に `Error: Process completed with exit code 1.`。チャット側の見立ては「`&&` のためテストが通ると `exit 1` が走る。書き間違い」。unittest は失敗時に自分で非ゼロ終了するので、`&& exit 1` を消せば足りる。
* 出力の「テストタブの gid が引けない」「URLError boom」の警告は、テストの中で起こしている例外の出力と見ている。
* 平野さんの「フィルタの有無の動作チェック」が、この行を入れた作業と関係している可能性がある。

手順

1. 対象のワークフローのファイルと行を特定し、`git log -S` 等でその書き方が入ったコミット（Chat-Ref・日時・関係する issue）を突き止める。`.github/workflows/` のほかのファイルに同じ種類の誤り（成功時に `exit 1` になる書き方など）が無いかも調べる。前提の見立てが違えば、分かったことを書いて止まる。

3. 影響を調べてログに書く: この書き方が入ってから失敗した実行（見られる範囲で。クラウドで見られなければ「未確認の項目」へ）、止まった処理（層1の追記、【1】【2】への書き込み、regenerate による /live・title/ の再生成）、マージ後の次の実行で自動的に追いつくか、それとも手動で再実行が要るか。
