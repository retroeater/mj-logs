## 経過

- Chat-Ref の確認: `CHAT-0926-DK-03`・`CHAT-0926-DK-02` のコミットなし。DK は同じセッションの続き（DK-01 で識別子の確認済み）。
- マージの根拠: 「決定（平野さん）」の「読み取りを実行して確かめるのは省き、マージする」を、CLAUDE.md「ブランチ運用」の事前のマージ許可として扱った。
  指示文の確認（差分の範囲・衝突なし）が通ったらマージする。

### 手順1: 差分の確認

- `git diff --stat origin/cloudflare...HEAD`: `scripts/lib/dojo_guest.py`（+4 −1）、`docs/logs/CHAT-0926-DK-01.md`、`docs/logs/CHAT-0926-DK-03.md`（このログ）だけ。
  指示文が挙げた2つのほかにあるのは、このログだけ。
- origin/cloudflare は b7564497 から進んでいない。work/0926-dk はその子孫なので、マージは fast-forward になり衝突しない。

### 手順2: 確認を残す先

- handover.md 5章「期限付き・確認待ちタスク」の表: 行はどれも「決まった時点の確認を済ませてクローズ」の形で、この確認と同じ種類なので、ここに足した。
  CLAUDE.md の規則どおり、Chat-Ref は書いていない（handover.md 23,466 → 約23,800 バイト。警告域は 26KB）。
- #390: 道場部ゲストの取り込みの本体で open。#426 は通知専用の常設issueなので、確認の記録は #390 に書く。

### 手順3: マージで動くものと変わる範囲

- **Workers Builds**: `docs/` の外（`scripts/`）が変わるのでデプロイが1回走る。`scripts/` は `.assetsignore` で公開対象外なので、配信される内容は変わらない。
- **`regenerate-page.yml`**: `paths` の `scripts/lib/**` に当たるので起動する。`scripts/regenerate.py --changed` は `scripts/lib/` の変更を「全ページを作り直す」と判定する（`SHARED = "scripts/lib/"`）。
  - 凍結ページは除く
  - 生成物がスプレッドシートの最新と違えば `chore: regenerate ...` のコミットが入り、もう1回デプロイされる
  - 変わるのはデータの差分だけで、`dojo_guest.py` はどのページの生成にも使われていない
- **`assets-check.yml`**: cloudflare への push で毎回動く（サイズの検査）。
- **`sync-logs.yml`**: `docs/logs/**` と `docs/handover.md` が変わるので、`retroeater/mj-logs` に写る。
- **`sitemap-lastmod.yml`**: `**.html` の変更が無いので動かない（regenerate のコミットで HTML が変われば、そちらで動く）。
- **`sync-dojo-calendar.yml`**: push では動かない。schedule はデフォルトブランチ（cloudflare）のコードを使うので、マージ後の次の実行（毎日 07:12 JST）から新しいコードになる。
  ただし9月分の画像は前回から変わっていないため、API を呼ばずに終わる。新しいコードで初めて API を呼ぶのは、10月分の画像を読む回になる。
