### 前提の確認（公式ドキュメント）

docs.github.com はセッションのプロキシで拒否された（`CONNECT tunnel failed, response 403`、WebFetch も EGRESS_BLOCKED）。
公式ドキュメントの原稿（github/docs リポジトリ）を raw.githubusercontent.com から読んだ（main、2026-09-29 時点）。

1. **skip したジョブの課金**:
   - 課金は「ジョブごとの使用分を1分単位に切り上げる」: `content/billing/reference/actions-runner-pricing.md`
     「GitHub rounds the minutes and partial minutes each job uses up to the nearest whole minute.」
     （公開 URL: https://docs.github.com/en/billing/reference/actions-runner-pricing ）
   - 分は runner の処理時間で数える: `content/billing/concepts/product-billing/github-actions.md`
     「Minutes are calculated based on the total processing time used by each runner type during the month.」
     （https://docs.github.com/en/billing/concepts/product-billing/github-actions ）
   - `jobs.<job_id>.if` は「ジョブを実行させない」: `data/reusables/actions/jobs/section-using-conditions-to-control-job-execution.md`
     「You can use the `jobs.<job_id>.if` conditional to prevent a job from running unless a condition is met.」、偽なら「the job will be marked as _skipped_」
     （https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idif ）
   - **「skip したジョブは課金されない」と1文で書いた箇所は公式ドキュメントに見つからなかった。** 上の3つ（課金は runner の処理時間をジョブ単位で数える／
     `if` が偽のジョブは実行されない）から導いた。コミュニティの Discussion（https://github.com/orgs/community/discussions/120231 ）には
     「skip された run は課金されない」旨があるが公式文書ではない。実測の裏付けは下の検証（skip したジョブに runner が割り当たらないこと）で見る。
2. **run だけでジョブが無ければ0分**: 上と同じ根拠（分はジョブが runner で使った時間）。
3. **paths は push 全体の差分で判定、`!` が使える**: `data/reusables/actions/workflows/triggering-a-workflow-paths{1,4,5}.md`
   （https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushpull_requestpull_request_targetpathspaths-ignore ）
   - 「Pushes to existing branches: A two-dot diff compares the head and base SHAs directly with each other.」
     「Pushes to new branches: A two-dot diff against the parent of the ancestor of the deepest commit pushed.」
   - 「If you define a path with the `!` character, you must also define at least one path without the `!` character.」
     「A matching negative pattern (prefixed with `!`) after a positive match will exclude the path.」
     「A matching positive pattern after a negative match will include the path again.」
   - `'**'` は「This is the default behavior when you don't use a `path` filter.」（filter pattern cheat sheet）
   - 例外: push のコミットが1,000件超・差分の生成がタイムアウトなら常に走る。差分が3,000ファイル超で対象が先頭3,000件に無ければ走らない。

  セッションの説明が割り当てブランチ（claude/...）での作業を指示しているため、別ブランチの作成を「共有の資源の変更」とみなしたと見られる。
  止まらずに済む設定の案（変えていない）: リポジトリの `.claude/settings.json` の `permissions.allow` に `Bash(git checkout -b work/*)`・`Bash(git checkout -B work/*)`・
  `Bash(git push origin work/*)` を足す。許可ルールが auto モードの分類器より先に効くかは未確認。
