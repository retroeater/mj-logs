### 3. 結論

- **HTML に ETag が付かないのは `html_handling: none`（と `_redirects` の組み合わせ）のせいではない。** `auto-trailing-slash` にして `_redirects` の書き換えを外しても、200 で返る HTML（`/`・`/jpml_pros`・`/title/`）に ETag は付かなかった。CSS には同じ形で付く
- ここまでで分かったこと: ゾーンの機能（CW-14）でも html_handling（この実験）でもなく、Workers の静的アセットが HTML（`text/html`）に ETag を付けていない。公式の headers のページは既定で ETag を付けるとし、HTML の例外を書いていないので、**公式の記述と実物が食い違っている**（理由は不明。仕様の変更か、記述の漏れか）
- `html_handling` を本番で変える案は、ETag のためには意味が無い。影響だけが残る（`.html` 付きの URL がすべて 307 で転送され、og:url・sitemap・canonical の方針〈#89・#113〉と食い違う。`_redirects` の `/` などの書き換えを外す必要がある）→ **本番には入れない**
- 入れない場合の扱い（案。決定ではない）:
  - 案1: #449 を「状況: 保留」にし、HTML の ETag は Workers の静的アセットの仕様として受け入れる。docs/notes/cloudflare.md の1文（「原因は #449」）を「Workers の静的アセットの配信で付かない（2026-09-28 の実験）」に直す
  - 案2: 新サイト（#296）に申し送る。HTML を Worker のコードで返す構成にするなら、自前で ETag を付けて 304 を返せる（Worker のコードを持つことになり、`_headers` が効かなくなる注意がある。公式の headers のページ）
  - 案3: Cloudflare の Community などに「静的アセットの HTML に ETag が付かない」ことを問い合わせる（公式の記述との食い違いの確認）
