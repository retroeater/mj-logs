    > /live の掲載を自動で決められなかった（保留の）動画です。毎朝の取り込み（update-live-channel.yml）が書き換えます。「【3】手動補正」のその行の掲載に Y か N を入れると、次の朝の取り込みで一覧から消えます（規則は `scripts/lib/live_layer3.py` の `auto_show()`、#362）。
    >
    > | 【3】の行 | 動画ID | 題名 | 理由 |
    > |---|---|---|---|
    > | 3619 | `9poqArCQUgw` | 【メンバー限定】第４期紅龍戦~Ｄ卓~ | まとめ単位を記号にできない |
    > | （ほか3行） | | | |
    >
    > _2026-11-15（JST）の取り込みの時点で 4件_

    コメント: 「今日の保留 4件（2026-11-15）」の下に行番号・動画ID・題名・理由を30行まで（残りは「ほか N件は本文の表」）。保留が無くなった日は「保留が無くなったため閉じます（日付）。」を足して閉じる。本文とコメントの末尾に実行ログへのリンク
  - **決定とずらした点**: 配信予定（配信が始まっていない）の行は値は保留（空）のままにしたが、知らせからは外した。毎日の追記は配信前の行が多く、知らせると issue の開き直しと「今日の保留」の通知がほぼ毎日くり返すため（次の朝に配信開始日時が入ると自動で決まる）。配信予定も知らせるなら1行で戻せる
  - **title/ への効き方**: title/ の期ページは、これまで掲載が空欄で冒頭が Y でない決勝段階の行を載せていた（#476 の案A）。自動にすると、メンバー限定版が無い公開の生放送（題名に【無料放送】が無い）の決勝は自動の N になり、title/ に載らなくなる。追記の時点でメンバー限定版が同じ日に無いと冒頭は付かないので、こうした行は冒頭が空のまま N になる。全編無料だが【無料放送】が無い配信（第43期十段位決定戦の二日目・最終日のような例）は、【3】に Y を入れる運用になる。この効き方でよいかの確認
  - **自動にする大会の確認**: 決定どおりリーチ麻雀世界選手権・昇龍戦も自動にした。LVP-17 の直した案ではこの2大会の一致が低かった（15.4%・60%。主に【2】でまとめ単位が取れない保留と、世界選手権 第3回の公開の動画〈正解 N〉）。今の行は【3】が勝つので変わらない
  - **マージの前に要るもの**: (1) なくてもマージできる: 【2】の新しい列は、マージ後の最初の毎朝の取り込みが書く（それまでの再生成は列を空として読む）。(2) 「タイトル戦」シートの「自動掲載」の列は、足してもこのブランチのコードは読まない（仮の一覧のまま）。列を読む直しを入れてからマージするか、仮の一覧のままマージして後で直すかを決める。(3) 常設 issue は作らなくてよい（保留が出たら作られる）。(4) ワークフローの手動実行: 作業ブランチの apply なしの実行は済んだ（run 43686379781、success）。マージの後に cloudflare で apply なしを1回動かし、知らせの段の dry-run の出力を見るのがよい。(5) 告知の期間の決まり（docs/notes/page-announcement.md）を見て、マージの時機を決める
- 未確認の項目:
  - 保留が実際に出たときの issue の作成・コメント・閉じる動き（今日は保留が0件のため、dry-run でも「無い・閉じるものが無い」までしか通っていない。文面は例で確かめた）
  - コメントで通知のメールが届くか（GitHub の通知の設定による。ブラウザでしか確かめられない）
