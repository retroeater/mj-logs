| 論点 | 記述 | 出典 |

| 静的アセットの既定のヘッダ | `Cache-Control: public, max-age=0, must-revalidate` と **`ETag`（ファイルのハッシュ）を既定で付ける**。種類（HTML かどうか）による例外の記述は無い | https://developers.cloudflare.com/workers/static-assets/headers/ 「Default headers」 |
| Cloudflare が ETag を外す・弱める条件 | Respect Strong ETags が無効のとき、強い ETag を残すのは「圧縮が同じ」かつ「**Rocket Loader と Email Obfuscation が無効**」のときだけ。それ以外は弱い ETag に変えるか**外す**。弱い ETag を残すには Email Obfuscation・Automatic HTTPS Rewrites など、end-to-end compression の注記にある機能を無効にする必要がある | https://developers.cloudflare.com/cache/reference/etag-headers/ |

| Respect Strong ETags | Cache Rules で有効にすると Rocket Loader・Email Obfuscation・Automatic HTTPS Rewrites を自動で無効にする（RUM は挙げられていない） | etag-headers のページ |

### 2. 切り分けの実測（2026-09-28、`curl -sS -o /dev/null -D - -H 'Accept-Encoding: br, gzip' https://ryoei.pro<パス>`）

**(a) 本番と workers.dev の比較: できなかった。** 本番の Worker の workers.dev（`mj.<アカウントのサブドメイン>.workers.dev`）への接続は、このセッションのプロキシが CONNECT 403 で拒否した（cloud-sessions.md の MD-17 と同じ）。
ゾーンの機能を通らない配信での ETag の有無は確かめられていない。**止まる条件「切り分けの実測ができない」に一部当たる**ので、(b)(c) で分かった分を書く

**(c) 種類ごとの ETag（本番）**

| パス | content-type | ETag |
|---|---|---|
| `/jpml_pros.html`・`/index.html`・`/404.html`・`/title/index.html` | text/html | **無し** |
| `/robots.txt` | text/plain | **無し**（Cloudflare が管理セクションを前置して中身を変えている） |
| `/style.css` | text/css | `W/"..."`（弱い） |
| `/llms.txt` | text/plain | `W/"..."` |
| `/sitemap.xml` | application/xml | `W/"..."` |
| `/img/avatar.svg` | image/svg+xml | `W/"..."` |
| `/favicon.ico` | image/vnd.microsoft.icon | `W/"..."` |
| `/houou_leagues_data.json`・`/title/search.json` | application/json | `W/"..."` |

→ **ETag が無いのは text/html すべてと、エッジで中身を変えている robots.txt だけ。** 同じ text 系でも llms.txt・sitemap.xml・svg には付く。種類で分かれている

**(b) 本文の比較**: `index.html`・`jpml_pros.html`・`404.html`・`title/index.html` を本番から取得（br 展開後）し、リポジトリ（d12c5e98）のファイルと比べた → **4つともバイト単位で一致**。スクリプトの挿入などの書き換えは、このセッションへの応答には無い
- Web Analytics のビーコンは生成時にすべての HTML に焼き込み済み（配信対象の HTML 1,538 ファイルすべてに `static.cloudflareinsights.com/beacon.min.js` がある）。エッジで挿入されたものではない
- `jpml_links.html` の `href="http://www.ron2.jp/"` は本番でも `http://` のまま（Automatic HTTPS Rewrites が有効でも、書き換え対象の一覧に無いドメインは変えないため、オン・オフの判定には使えない）

**確かめられたこと**

- 静的アセットは既定で ETag を付けると公式にある。本番で ETag が無いのは text/html と、エッジで中身が変わる robots.txt だけ
- 本番の HTML の本文はリポジトリと同一（少なくともこのセッションへの応答では、目に見える書き換えは無い）
- Rocket Loader・Email Obfuscation は 2026-09-11 に Off と記録されている（#120。今の状態はセッションから見えない）

**推測にとどまること**

- **原因の見立て（最有力）: HTML にだけ効くゾーンの機能が有効で、Cloudflare が HTML の応答を展開・再圧縮する経路に入り、ETag を外している。** 公式の一覧のうち、HTML にだけ効き、#120 で確かめていないものが候補:
  1. **RUM（Web Analytics の自動挿入）**: cloudflare.md で「有効」と記録されている。ビーコンは HTML に焼き込み済みなので、自動挿入は本文を変えていない（重複して入れていない）が、機能が有効なだけで HTML が再圧縮の経路に入っている可能性
  2. **Automatic HTTPS Rewrites**: 状態の記録が無い（多くのゾーンで既定オン）
  3. **JavaScript detections**（Pro の Bot の機能）・AI Labyrinth（#447、オフに見えた）: 状態の記録が無い／未検証
- `html_handling: "none"`（#89）が原因という見立ては、公式に ETag との関係の記述が無く、**根拠が見つからなかった**。workers.dev と比べられれば切り分けられるが、今回はできなかった
- robots.txt に ETag が無いのは、管理 robots.txt の前置で中身が変わるためと見られ、同じ「エッジで手を入れると ETag が外れる」挙動と整合する（公式の明記は無い）

### 3. 直し方の案（案。決定ではない）

「ボット系の設定は1つずつ変える」と同じく、**1つずつ変えて、そのたびに下の確かめ方を行う**。

| 案 | 操作 | 誰が | ほかへの影響 |
|---|---|---|---|
| A. RUM の自動挿入を止める | Web Analytics のサイト設定（または Speed の Web Analytics (RUM)）で自動設定（自動挿入）をやめ、手動のスニペット（焼き込み済み）だけにする。画面の名前は未確認 | 平野さんのダッシュボード操作 | 計測はビーコンを焼き込んだ HTML から続く見込み（1,538 ファイルすべてに入っている）。ただし自動挿入と手動のトークンが同じサイトを指しているかは未確認。止めた後、Web Analytics の数字が落ちないか数日見る |
| B. Automatic HTTPS Rewrites を切る | SSL/TLS → Edge Certificates の Automatic HTTPS Rewrites をオフ | 平野さん | 配信対象の HTML で `src`/`href` に `http://` があるのは2件（`http://www.ron2.jp/`・`http://wrc2017vegas.com/`、ともに外部へのリンクで、読み込みではない）。Always use HTTPS と HSTS は別の設定なので影響しない |
| C. Configuration Rule で HTML のパスだけ止める | Rules → Configuration Rules で、`*.html` と `/`（または全体）に対し Automatic HTTPS Rewrites・RUM 等をオフ | 平野さん | 設定を個別に探さずに済むが、ルールが1本増え、何が効いたかの切り分けは A・B より粗い |

- **セッションで済む直し方は無い。** 原因がゾーンの機能なら `_headers` で ETag を足しても、その後の再圧縮で外れる見込み（未確認）。`_headers` に自前の ETag を書くことは、内容のハッシュを毎回生成物に合わせる必要があり、現実的でない
- **直ったことの確かめ方（直す前の状態では通らないもの）**:
  1. `curl -sS -o /dev/null -D - -H 'Accept-Encoding: br, gzip' https://ryoei.pro/jpml_pros.html` に `etag:` 行が出る（今は出ない）
  2. その ETag を `If-None-Match` に付けて同じ URL を取ると **304**（今は ETag が無いので 304 を試せない）
  3. `index.html`・`title/index.html` など数ページで同じ。どれもセッションから行える
- 変えた設定と日時を #449 に記録し、確かめ方の1・2 を通ったら cloudflare.md のキャッシュの節（#449 の1文）を直してクローズ
