## 目的
人物・外観などの写真や、空欄のあるカードがログにそのまま載るのを防ぐ。毎朝の取り込みで新しく変換する投稿を次の2つで確かめ、当たれば載せず（【2】の「表示」N）、平野さんに知らせる。
1. 1枚目の写真を Claude（Haiku）が見て、料理・飲み物が主でない
2. 「店名」「駅」「メニュー」「Google マップの URL」「画像」のどれかが空
あわせて、今ログに載っている投稿のうち 2. に当たるものを数えて一覧にする（今回は外さない）。

## 手順
1. 未マージの work/ ブランチで `convert_x_posts.py`・`convert-x-posts.yml`・`run-daily.yml` を変えているものを確かめる。変換で Claude を呼ぶ所、【2】に書く列と理由、常設 issue の upsert の作りを確かめて書く
2. 写真の判定の関数と判定の文を作り、試しと空欄の数えの一度きりの mode を足す
3. 作業ブランチの ref で手動実行し、写真の (i)〜(iii)（基準を満たすまで最大3回）と、空欄の数えをログに書く
4. 一度きりの mode を戻し、変換への組み込み（写真・空欄）・常設 issue・テスト・docs を入れる。テスト・ワークフローの検査（zizmor を含む）を回し、差分のレビューを受ける
5. `convert-x-posts.yml` を作業ブランチの ref・dry_run で手動実行し、新しい投稿が無いときに何も変わらないこと（画像の判定を呼ばないこと）を確かめる
6. 止まる条件に当たらなければ cloudflare へマージする。マージの後に最初に動く毎朝の変換の日時を書く

## 止まる条件
- 3回の試しで基準を満たさない（いちばん良かった結果を書いて判断待ちで止まる）
- 試しの費用が $3 を超える見込みになる
- テスト・ワークフローの検査が通らない
- 未マージの work/ ブランチが上のファイルの同じ箇所を変えている、または取り込みで衝突する
- 新しい依存（パッケージ・外部サービス）が要る（足さずに止まる）
- cloudflare への push が権限判定で拒否された（別の手段を試さずに止まる）
