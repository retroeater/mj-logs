目的
`title/` の生成で、龍龍（ron2.jp）の選手画像が実行のたびに元画像と縮小版（`-150x150`）の間で揺れるのを止める。X の写真（#380、UT-19）と同じく、生成時の到達確認（HEAD）をやめ、決まった URL を出す形にする。これが済んだら、UT-25 の毎朝の再生成に `title/` を含める（次の指示）。
決定（2026-09-27、平野さん）

* UT-25 の報告の案2: 毎朝の再生成に `title/` も含める。そのために、先に龍龍の選手画像の扱いを直す

前提（チャット側。平野さんの決定ではない）

* 今の仕組み（UT-25 のログより）: `generate_title_pages.py` の `upgrade_images()` が、龍龍の元画像に HEAD で届いたものだけ元画像にし、届かなければシートの縮小版のまま出す。UT-25 の作業ブランチの実行で届かず、`title/` の105ファイル・134か所が縮小版に戻った。`docs/notes/static-generation.md` の `check-ron2-images.yml` の項にも、続けて取りに行くと届かなくなる例がある。実物で確かめる
* 案: 生成では HEAD をやめ、元画像の URL を決定的に出す（縮小版の URL から `-150x150` などの末尾を外す規則）。ブラウザで元画像が読めなかったときは、縮小版の URL に切り替える（既存の `data-fallback` の仕組みに、縮小版を先に試す段を足すなど）。この形なら生成結果は外部の状態に左右されない
* 案を実装する前に、元画像が実際に無い（どの取り方でも 404 になる）選手がどれだけいるかを調べる。セッションから、間を空けて取りに行く（続けて取りに行くと届かなくなるため）。元画像が無い選手が多い（目安: 1割を超える）なら、ブラウザ側の切り替えに頼るのは読み込みの無駄が大きいので、止まって件数を報告する
* `title/` のほかに、龍龍の画像を出しているページ（`saikyo/`・`jpml_pros.html` など）と、同じ HEAD の確認をしている箇所を洗い出す。今回は `title/` だけ直し、ほかにあれば件数をログに書く（別に扱う）
* `check-ron2-images.yml` の役目（画像の到達の定期確認など）を読み、今回の変更で要らなくなるか、そのまま残すかをログに書く
* 同じ目的の issue があるか探し、無ければ起票する（題名は「龍龍の選手画像を決定的に出す」程度。#380 と同じ系統）。あればそちらを使う
* 検証は、修正後に2回再生成して2回目の差分が0であることを確かめる。1回目は、今コミットされている `title/` との差分が「龍龍の画像の出し方の変更」だけであることを確かめる

手順

1. `generate_title_pages.py` の `upgrade_images()`・`check-ron2-images.yml`・`static-generation.md` の該当の項・UT-19 と UT-25 のログを読み、「前提」と食い違えば止まる。元画像が無い選手の件数を調べ、同じ HEAD の確認をしているほかの箇所を洗い出す。issue を探す（無ければ起票）
2. 生成の HEAD をやめて決定的な URL を出し、ブラウザ側の切り替えを実装する。テストを足し、修正後に2回再生成して、1回目の差分の内訳と2回目の差分0をログに書く
3. cloudflare へマージする。マージ後の自動再生成の差分が手順2の1回目と一致することを確かめ、issue に結果を書く（揺れが止まったことは、UT-25 の続きで毎朝の再生成を入れたあとに確かめるので、issue はまだクローズしない）
