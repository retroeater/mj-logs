ほかの設定との関係（公式の記述ではなく、上の記述からの推定）:

- **Training = Disallow（#130）**: Disallow は robots.txt で学習拒否を宣言するだけで、守らないクローラーは止めない。AI Labyrinth はその「守らない」相手に効く、という補完の関係。ただし robots.txt の宣言を守らない相手をどう見分けるかは公式に書かれていない
- **WAF・Managed rules**: AI Labyrinth はブロックしない（mitigation ではない）ので、WAF の判定とは別。Events には別の Service として出るため、#130 の確認で見た Managed rules のブロックとは画面上で区別できる
- **#124 Rate Limiting（未設定）**: どちらも Events に出る。同時に入れると増えた記録の原因を分けにくいので、方針どおり時期をずらす
- **#9 CSP（未設定）**: 注入するのはリンク（`<a>`）で、スクリプトの注入とは書かれていない。CSP と衝突するかの記述は無い（未確認）
- **#449（HTML に ETag が無い）・キャッシュ**: 注入された応答は相手によって中身が変わる。エッジのキャッシュや ETag との関係の記述は無い（未確認）
- **Workers の静的アセットで効くか**: HTML を書き換える機能は Workers の静的アセットでは効かないものがあった（Speed Brain、#119）。AI Labyrinth が効くかの記述は無い。オンにした後、Events に「AI Labyrinth Served」が出るかで確かめるしかない

**セッションから確かめたこと（2026-09-28）**: `curl -H 'Accept-Encoding: identity' https://ryoei.pro/index.html` と `/jpml_pros.html` は、リポジトリ（origin/cloudflare 1df485df）のファイルと**バイト単位で一致**した。今はこのセッション（データセンターの IP）への応答にリンクは注入されていない。オフだからか、オンでも対象外だからかは区別できない

### 3. 有効にする・しないの比較と確認手順（案。決定ではない）

**有効にする場合**

- 利点: robots.txt の学習拒否（Disallow）を守らないクローラーに資源を使わせ、その情報が Cloudflare 全体の AI ボット判定に使われる。ブロックしないので、誤判定されても訪問者・検索用クローラーへの表示は変わらない（公式の記述）。Pro で追加費用なし
- 懸念:
  - 得が小さい（AL-01 の見立てのまま）。ryoei.pro の選手データの元は連盟の公開情報
  - どの相手に注入するかが公式に書かれていない。クラウドの Claude Code・GitHub Actions（データセンターの IP から取得する）が対象になると、取得した HTML に見えないリンクが混ざり、リンク検査（`check_image_links.py` など）や HTML の差分確認が乱れるおそれ（推測、未検証）
  - Workers の静的アセットで効くか分からない（効かなければ得が無い）
  - オフにしてもしばらく Events に記録が残る（切り分けのときに紛らわしい）

**有効にしない場合**

- 利点: 設定を増やさず、#130 で落ち着いた状態（Training = Disallow）の観察を続けられる。#124・#9 の順番に影響しない
- 懸念: 学習拒否を守らないクローラーへの手当ては無いまま（今もブロックはしていない）

**有効にするなら確認の手順（案）**

1. 平野さん（ダッシュボード）: Security → Settings を Bot traffic で絞り込み →「AI Labyrinth」をオン。オンにした日時を #447 に記録
2. セッション（直後と翌日）: `curl` で `index.html`・`jpml_pros.html` などを取り、リポジトリのファイルとバイト比較する（今回と同じ方法）。差が出たら注入されている → 取得に使う道具（リンク検査など）への影響を調べる。GitHub Actions の実行（`check-image-links` などの取得を伴うもの）のログにも異常が無いか見る
3. 平野さん（ダッシュボード、毎日1回を7日）: Security Events を Service「AI Labyrinth」で絞り、Served と Crawls の件数、User agent・ASN を見る（Events は1回に1日分まで）。Googlebot（AS15169）・Bingbot・Applebot に Served が付いていないこと
4. 平野さん（7日後）: Search Console のクロールの統計情報で、403 や 4XX の増加、クロール数の急な減少が無いこと（#304 の (8) と同じ画面）
5. 問題が出たらオフに戻す。オフにしても Events に記録がしばらく残ることを #447 に書き添える
- セッションから確かめられないこと: トグルの状態、Events・AI Crawl Control の件数、Search Console。これらは平野さんの画面の申告になり、検証できない
- 観察期間は 7日を案とした（Events が1日単位で、週をまたいだクロールの周期を1回見るため）。根拠のある公式の目安は無い
