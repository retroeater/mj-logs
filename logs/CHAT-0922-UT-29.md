### 手順2: 毎朝の処理が失敗したときの通知

**公式の文書**（docs.github.com はセッションのプロキシで遮断されていたため、同じ内容のソース `github/docs` リポジトリの main を raw で読んだ）:

- `content/actions/concepts/workflows-and-actions/notifications-for-workflow-runs.md`（公開ページ「Notifications for workflow runs」）:
  - 「If you enable email or web notifications for GitHub Actions, you'll receive a notification when any workflow runs that you've triggered have completed. … You can also choose to receive a notification only when a workflow run has failed.」
  - 「Notifications for scheduled workflows are sent to the user who initially created the workflow.」
    「If a different user updates the cron syntax, in the `schedule` event in the workflow file, subsequent notifications will be sent to that user instead.」
    「If a scheduled workflow is disabled and then re-enabled, notifications will be sent to the user who re-enabled the workflow rather than the user who last modified the cron syntax.」
- `content/actions/reference/workflows-and-actions/events-that-trigger-workflows.md`（`schedule` の節）:
  「Notifications for scheduled workflows are sent to the user who last modified the cron syntax in the workflow file.」
- チャット側の理解（cron を最後に変えたユーザー、手動実行は実行したユーザー）と一致。加えて「作った人が既定」「無効→有効にした人に移る」の2点がある

**`update-live-channel.yml` の履歴**:

- cron の行（`- cron: '43 17 * * *'`）は作成時のコミット 8f7ac955（2026-09-25、作成者・コミッターとも `retroeater <hirano@ryoei.net>`）で入り、その後変わっていない（`git log -L` で確認）
- 以後の変更（4e7c8e0f〜9ee5506f の6件）はコミットの作成者が `Claude <noreply@anthropic.com>` だが、いずれも cron の行には触れていない。
  なお、文書の「user」は push した GitHub アカウントを指すと読め、コミットの作成者の欄とは別（クラウドセッションの push も `retroeater` の名義で行われている。issue のコメントの投稿者が `retroeater` であるのと同じ）
- 実測: 定期実行（event=schedule）の3件（run 4・5・17、直近 https://github.com/retroeater/mj/actions/runs/36347752166 ）は `actor`・`triggering_actor` とも `retroeater`
- ワークフローの状態は `active`（無効化・再有効化の形跡は API からは見えないが、actor が `retroeater` のままなので、あっても届き先は変わらない）
- ワークフローに失敗時の issue 作成などの通知のステップは無い。通知は GitHub の Actions の通知だけに頼る。
  後段の `regenerate`（`regenerate-page.yml` の呼び出し）が失敗しても同じ run の失敗になる

**判断**: 失敗の通知は `retroeater`（平野さん）に届く見込み。平野さんの通知設定で Actions の通知が有効になっていることが条件（セッションからは見えない）。
届かない見込みではないため、届くようにする案の比較は省いた。

注意点（ログに残す）:

- 取り込み（update ジョブ）が失敗した日は `regenerate` が動かず、ページは古いまま（ワークフローのコメントのとおり）。通知が来たら run を開いて確かめる
- `SCHEDULE_ENABLED` が `true` でない日は定期実行が何もせず成功で終わる。止めていても通知は来ない
- 公開リポジトリの定期実行は、リポジトリに60日間動きが無いと GitHub が自動で無効にする（GitHub の仕様。今回の文書の範囲外で、ここでは確かめていない）。その後に別の人が有効に戻すと、届き先がその人に移る

**平野さん向けの確認の手順（Windows、ブラウザ）**:

1. ブラウザで https://github.com/settings/notifications を開く（`retroeater` でログインした状態）
2. 「System」の下の「Actions」を探す。右の「▼」（通知の送り先）で「Email」と「On GitHub」のどちらか（両方でもよい）にチェックが入っていることを確かめる
3. 同じところの「Only notify for failed workflows」（失敗したときだけ通知）にチェックを入れると、毎朝の成功の通知が来なくなる（入れるかは好み）
4. メールで受けるときは、同じページの上の「Default notifications email」が普段見るアドレスになっていることを確かめる。
   メールソフトの迷惑メール・振り分けで `notifications@github.com` が隠れていないかも見る
5. 実際に届くかの確認は、次に手動実行で失敗した run が出たとき（手動実行の失敗は実行した人に届く）か、定期実行が失敗した朝に、メール・https://github.com/notifications を見る。
   意図して失敗させる確認はしていない（本番のシート・ページを触るワークフローのため）
