### 4-3. #425 の「先に決めること」1〜4（本文から全文の要点を写す）

1. **最強戦シートに動画 URL（ABEMA）の列を足すか**（平野さんの判断・シート側の作業）
   - 今の「最強戦」シートは A〜L 列（対局日・年度・対局・ステージ・卓・順位・結果・名前・X・画像URL・表示・備考）で、動画 URL を入れる列が無い（2026-09-21 に gviz で確認）。L列「備考」は出場枠名と運用メモで、動画 URL には使えない
   - 比較: 「帰り道」はシートの H 列に決勝動画 URL を持つ（#318）。/live は「放送対局」タブの動画 ID 列からページを作る
   - 突き合わせの鍵は（年度, 対局, ステージ, 卓）
   - 列を足さずに個別ページを作っても、年度ページの一部の再掲にしかならない
   - 決めるのに要る材料: 列を足すかどうか（平野さん）と、動画 URL を誰がいつ入れるか
2. **ABEMA の制約 — サムネイルを自前で用意するか、リンクのみにするか**
   - ABEMA は日本国外から取得できない。サイトの自動処理（チャット側・Actions・Codespace）はすべて国外から動くので、サムネイル・タイトルの自動取得もリンク切れ検知もできない
   - 案1: 文字リンクのみ（外部ドメインへの依存が増えない）
   - 案2: サムネイルを自前で用意して `img/` に置く（枚数分の手作業と権利の確認）
   - どちらでも、方針「外部ドメインへの依存を増やさない」（CSP #9）に触れるかを先に見る。`check_image_links.py` 系の週次検知の対象にできない
   - 決めるのに要る材料: 権利の確認の可否、手作業の量（対局数・卓数）
3. **粒度 — 対局単位か卓単位か**
   - 年度ページ16枚で対局219・卓641（2026-09-21 時点）
   - 年度ページの「決勝」「ベスト8 A卓」は卓の見出し。共有ボタンは対局単位（`?match=`）
   - /live は卓ごと。/live に合わせるなら卓、既存の `?match=` に合わせるなら対局
   - 決めるのに要る材料: どちらにそろえるか（/live か `?match=` か）。sitemap は対局なら219件、卓なら641件増える
4. **既存の `?match=` の URL を個別ページへ畳むか**
   - 対局単位の URL（`saikyo/<年度>.html?match=<対局識別子>`）は既にあり、共有ボタンが配っている（canonical は年度ページ、sitemap には載せない）
   - 案A: `?match=` を個別ページへ 301 で畳む（共有済みの URL が動く）
   - 案B: 両方残し、canonical で個別ページに寄せる
   - 案C: 両方残し、個別ページ側を canonical で年度ページに寄せる（個別ページは検索に出ない）
   - 決めるのに要る材料: 3 の粒度（対局単位なら `?match=` と1対1）と、URL の形（本文の c-1〜c-3。c-1 なら `_redirects` に触れない）
