    - (a) 絞る: ①表示が空の行は警告しない（次の期の準備の行で、空はふだんの形と見る。Y・N 以外の値〈「y」など〉だけを警告）②表示 N の行の検査（名前・順位・日付・重なり）は、表示する大会（「タイトル戦」の区分=連盟・状態=継続）で、タイトルが大会名・期・期の表記と合う行（`expected_title()`、表示 Y の行と同じ形）だけにする ③重なりの鍵を（大会名, 期）にする。メリット: 今回のような「表示する大会の期に手で足した行」の書き違いだけを拾い、地方のリーグ・日本オープン・旧制度の「王位戦」の行（どれも今のページに関わらない）は外れる。当たりは 0 件に近い見込み（作業ブランチの check で数え直す）。デメリット: 表示する大会でない行・期の無い行の書き違いは拾わない。表示が空の行の書き忘れ（Y にし忘れ）も拾わない
    - (b) 今の検査のまま、警告の出し方を種類ごとの件数1行にまとめる（全件はログの詳細に）。メリット: 何も外さない。デメリット: 174件が毎回の生成の警告に残り、新しい書き違いが件数の変化でしか見えない
    - (c) 当たった行をシートで直す（表示が空の行に N を入れる、地方のリーグの行のタイトルに期を入れる、名前の無い行を消すか「-」にする）。メリット: 検査はそのまま使える。デメリット: 平野さんの手作業が多い（107行以上）。地方のリーグの行の期の書き方を決める必要がある
    - 推奨は (a)。目的（手で足した表示 N の行の書き違い）に合う範囲だけを見る。次の指示で (a) に直し、作業ブランチの check の当たりが20件以下ならマージする
  - WBK-03・WBK-12 のログの続き（docs のみ）は、コードと同じ作業ブランチにあり、まだ cloudflare に入っていない。次の指示（上の判断の続き）で一緒にマージする（それまで WBK-01〜03 は自動では消えない）
- 未確認の項目: なし
- エラー: なし
