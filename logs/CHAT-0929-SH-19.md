### 2. 「ログ（公開）」の URL（版ごとに変わる形）

- **選んだ形: `https://github.com/retroeater/mj-logs/blob/main/logs/<Chat-Ref>.md?v=<SHA>`**。`<SHA>` は最後に push した（ログを含む）mj のコミットの短い SHA（`git log -1 --format=%h`）
  - 理由: 最終報告を書く時点で分かる値だけで作れる。版ごとに URL が変わるので、チャット側が前に読んだ古い版を受け取らない。今の URL の末尾に足すだけで、平野さんが貼ればそのまま開ける。sync-logs のワークフローは変えなくてよい
  - 確かめ: このセッションからは github.com の画面は proxy が 403 を返して開けないため、同じ mj-logs を `raw.githubusercontent.com` で `?v=` の有無で取得し、同じ内容（SH-18 の完了した版、ガイドのリンク付き）が返ることを確かめた。GitHub の blob の URL も未知の問い合わせ文字列は無視する
- 比べたほかの案:
  - mj-logs のコミットに固定した URL（`blob/<mj-logs の SHA>/…`）: mj-logs のコミットは push の後に Actions（sync-logs）が作るので、最終報告を書く時点では SHA が分からない。待って調べる手順が増えるため採らない
  - `raw.githubusercontent.com` の URL: 版は変えられるが、今チャット側が開けている blob の形から変わる。変える理由が無いので採らない
- 直した箇所:
  - CLAUDE.md「作業ログ」節: 最終報告の項に「『ログ（公開）』の URL の末尾には `?v=<…短い SHA>` を付ける（理由）」の1行を足した
  - `docs/logs/_template.md`「ターミナルへ返す最終報告」: 例の URL に `?v=<SHA>` を付け、`<SHA>` の取り方と理由を足した
  - `docs/notes/chat-side-operations.md`「作業ログの読み方」: 「URL は末尾の `?v=` で版ごとに変わる。`?v=` を外したり書き換えたりしない」を足した
  - `docs/instruction-template.md` の完了条件の例: URL に `?v=<SHA>` を付けた
