### 目的（指示文の「## 目的」）
#390（通知先 #426）。月の途中で道場部ゲストの告知画像が差し替えられたとき（ゲストの変更・休み・追加）、毎朝の定期実行がカレンダー「mj_道場部ゲスト」を更新し、#426 に知らせるようにする。今の同期は予定を足すだけで、書き込みは手動実行のときだけ。

#### 決定（2026-10-02、平野さん）
- 月中にゲスト予定が変更された場合は、カレンダーを更新のうえ通知する。実行時点より過去の変更については対応不要。
- 書き込み済みの月の画像が差し替わったら、毎朝の定期実行がカレンダーを自動で更新し、#426 に通知する。新しい月の初回は今までどおり、通知を見てから手動で書き込む。（docs/decisions/dojo-guest.md の 2026-10-02〈CHAT-1002-DOJ-01〉「定期実行の自動書き込みは見送る」を、月中の変更に限って置き換える）
- 更新するのは実行した日（日本時間）以降の日だけ。当日を含む。前日までは触らない。
- 更新の仕方: ゲストが替わった日は予定の名前と X の URL を書き換える。ゲストが無くなった日（休みなど）は予定を削除する。増えた日は足す。
- 書き換え・削除は、同期が作った予定（目印付き）だけに限る。手で入れた予定は変えず、食い違いは通知に書く。
- 安全弁: 照合できない名前が1件でもあるときは自動更新せず通知だけにする。変更が多いときも自動更新せず通知だけにし、内容を確かめてから手動実行で反映する。閾値は3件。
- テストが通れば cloudflare へマージしてよい。
- 10月のカレンダー（CHAT-1002-DOJ-02 で書き込んだ22件）は平野さんが見て確かめた。問題ない。
- 「プロ」シートに「樫野凪」が無いのは改名のため。対応は不要。

#### 前提（チャット側。平野さんの決定ではない）
- 閾値の読み: チャット側の案「変更が6件以上なら自動更新しない」の数字を3に置き換えたものと読んだ。当日以降の変更（書き換え・削除・追加の合計）が3件以上なら自動更新せず通知だけ、2件までは自動更新する。数字は後で変えやすい形（定数1つ）にする。
- 「書き込み済みの月」の見分け方の案: カレンダーのその月に、同期が作った予定（私的拡張プロパティ `ryoei=dojo`）が1件でもあること。state に印を持つ形でもよい。実物に合わせて決める。
- 見る画像の案: 今は「ページの最も新しい月」の画像だけを見る。翌月分が掲載された後（例: 10/25 に11月分が出た後）に当月の画像が差し替わっても気づけるよう、当月（日本時間）の画像も見る。また、今の10月のように見出しが誤っていてページから当月の画像を見つけられないときのために、state に保存済みの当月の画像の URL の Last-Modified も確かめる（URL は平野さんが手動実行で指定したもので、見出しやファイル名からの推定〈B3〉ではない）。
- 手で入れた予定（目印なし）がある日は、画像と名前が違っても予定を足さず、食い違いを通知に書く（同じ日に予定が2件並ばないように）。新しい月の初回の書き込みの今の動き（同じ日に同じ名前が無ければ足す）は変えない。
- 自動更新を止めたとき（照合できない名前・変更が閾値以上）の反映は、今の手動実行の「カレンダーに書き込む」で行う。書き込み済みの月に対する手動の書き込みは、保存した読み取り結果で、同じ範囲（当日以降・同期が作った予定だけ）の書き換え・削除・追加を行う。
- 通知（#426）の案: 日付ごとの「変更前 → 変更後」、削除した予定、追加した予定、手で入れた予定との食い違い、自動で更新したか・止めたか（止めた理由と、手動実行の案内）。前日までの違いは載せなくてよい。
- 変えない動き: 画像が変わっていない日は何もせず通知もしない。まだ書き込んでいない月の画像が差し替わったときは、今までどおり読み直して通知するだけ（自動で書き込まない）。見出しの通知（B2）。
- サービスアカウントはカレンダーに「予定の変更」権限で共有済み（docs/notes/dojo-guest-calendar.md「設定手順」(a)）。予定の削除ができるかは確かめていない。
- 実際の画像の差し替えが起きるまで、本番での自動更新は動かない。この指示では本番のカレンダーを試験のために書き換えない。
- B1（連盟サイトの見出しの修正）は依頼済みで、反映の時期は未定（CHAT-1002-DOJ-02 の時点では直っていない）。
- #390 を閉じるかは平野さんが決めていない。閉じずに結果をコメントするだけにする。

2. 実装してテストを足す。テストは偽のカレンダーで次を確かめる: 当日以降で名前が替わった日は同期が作った予定が書き換わり通知に「変更前 → 変更後」が出る／画像から無くなった日は削除／増えた日は追加／前日までの違いは何もしない／手で入れた予定は変えず食い違いが通知に出る／照合できない名前があれば更新せず通知だけ／変更が3件なら自動更新せず通知だけで、手動の書き込みで反映される／変更が2件なら自動更新／まだ書き込んでいない月の画像の差し替えは通知だけ／最も新しい月が翌月でも当月の画像の差し替えに気づく／画像が変わっていなければ何もしない。修正前のコードで新しいテストが失敗することも確かめる。yml を変えるので、docs/notes/branch-operations.md「ワークフローを変更したとき」のとおり作業ブランチで書き込みなしの手動実行を行う（待つのは15分まで。画像が変わっていなければ何も起きない見込み。#426 に通知が出たら内容が事実と合っているかを書く）。docs/notes/dojo-guest-calendar.md（仕組み・毎月の運用・分かっていること）と docs/notes/static-generation.md の該当の行を、今の内容を読んでから実物に合わせて直す（「既存の予定は変更も削除もしない」「毎日の実行は書き込みはしない」の記述を今回の決定に合わせる。文書の直しは writing-for-agents の skill を使う）。
