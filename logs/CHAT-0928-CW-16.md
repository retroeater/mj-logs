### 4. 原因と記録

**原因**: Build watch paths の判定は、push に含まれる全ファイルで行われる。ログだけのコミットが先頭でも、同じ push に docs 以外の変更が入るとビルドされる。今日の例では、次のどれかで他セッションの成果物が push の範囲に入っていた:
- 作業ブランチへ `origin/cloudflare` を merge で取り込んでから push する（155c880 の work/0928-hc）
- マージ済みの作業ブランチを `origin/cloudflare` から作り直し、リモートの同名ブランチに push する（9ecc944、6c2eec78。リモートの古い先頭から見ると、他セッションのコミットをまとめて早送りすることになる）
- cloudflare へのマージで、作業ブランチに取り込まれていた他セッションのコミットが一緒に入る（155c880・35b29c3 の cloudflare）

ビルドの結果（デプロイされる中身）は変わらないので実害は小さい（ビルド回数・時間が増えるだけ）。

**docs/notes/cloudflare.md**（「ビルド成否と本番の確認範囲（check-runs）」の中、`docs/**` 除外の項）:
- 「逆に言えば、`docs/**` のみの push で…設定が外れた合図」を「push の範囲全体が `docs/**` のみなのに…」に直した
- 項「**判定は push 全体のファイルで行われる**」を足した（公式の出典、判定を飛ばす条件、よくある3つの場合、2026-09-28 の実測）
- 「work/ ブランチのプレビュー」の「先頭が docs/ だけのコミットの push ではビルドが走らないことがある（TH-03…）… 先頭のコミットで判定されている、という推定」の推定の文を、公式の説明と食い違い理由は分からない、に置き換えた。
  **TH-03 の f7d74e4・7e601b3 はコード（`scripts/generate_title_pages.py`・`style.css`・`title/`）を含むのに check-run が付かなかった**という観察は、公式の説明と合わない。ビルドがまとめられた可能性（同節の下）はあるが確かめていない
- サイズ: 44,209 → 45,129 バイト（cloudflare.md に上限は無い）

**直す必要（案。決定ではない）**: 実害が小さいので設定は変えなくてよいと見る。減らしたいなら:
- 案1（運用）: マージ済みの作業ブランチを作り直すときは、同名ではなく新しい名前のブランチにする（今回の -build・-sync のように）。新しいブランチへの docs だけの push はビルドされない
- 案2（運用）: 作業ブランチへ cloudflare を取り込むのは、コードを含む push のときに限る
- どちらも、プレビューを作りたいときには逆効果になりうる（ビルドされないとプレビューも作られない）
