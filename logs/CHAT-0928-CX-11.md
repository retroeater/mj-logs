### 手順1: `regenerate-page.yml` の構成と、足した手順

- ジョブは `regenerate` の1つだけ。手順: チェックアウト → Python → YouTube の取得 → 楽天の取得（凍結で `if: false`）→ **対象ページを再生成**（`regen`）→ サイトマップの lastmod の更新 → サイトマップの well-formedness の確認 → **変更をコミット・push** → 取得失敗の報告2つ
- 起動の経路は4つ（`workflow_dispatch`・`workflow_call`・`schedule`・`push`）で、どれもこの同じジョブを通る。**毎日の取り込み（`update-live-channel.yml`）の最後の /live・title/ の作り直しも `workflow_call` でこのジョブを呼ぶ**ので、1か所に足せばすべての経路に効く。title/ 以外のページだけを再生成する経路も同じ手順を通る（決定の「ページの更新がすべて止まる」のとおり。経路ごとに分けていない）
- 足した場所: 「サイトマップのwell-formednessを確認」の後、「変更をコミット・push」の前。名前は「title/ の転送の行を確認」、条件は `if: steps.regen.outputs.files != ''`（コミットの手順と同じ。再生成したものが無いときはコミットもしないので確かめない）
- 中身: `python3 -m unittest scripts/tests/test_title_redirects.py` を実行し、落ちたらテストの出力を出したうえで次の1行を出して `exit 1`:
  `::error::title/ の大会に末尾スラッシュなしの転送が足りません(不足: [...])。_redirects の「/title/  /title/index.html  200」の後に「/title/<slug>  /title/<slug>/  301」を足すと直ります(#455)。コミットせずに止めました`
  不足の大会は unittest の `AssertionError: Lists differ: [...]` の行から取る（取れないときは「上のテストの出力を参照」）

### 手順2: 検証（cloudflare 上でワークフローは動かしていない）

- YAML から「title/ の転送の行を確認」の `run:` を取り出し（`yaml.safe_load`）、Actions と同じ `bash -e` で実行した:
  - 今の状態: テスト2本 OK、終了コード 0
  - `_redirects` から judan の行を消した状態: 終了コード 1、`::error::` が1行（`不足: ['judan']`）
  - judan と wrc の行を消した状態: `不足: ['judan', 'wrc']`
  - 確かめた後、`_redirects` は元に戻した（`git diff` は `regenerate-page.yml` だけ）
- YAML の書式: `yaml.safe_load` で読めた。**actionlint 1.7.12**（PyPI の `actionlint-py` を scratchpad の venv に入れた）の指摘は「91:13: constant expression "false" in condition」の1件だけで、これは既存の楽天の取得の `if: false`（書籍の凍結）。修正前の版（origin/cloudflare）でも同じ1件で、足した手順による指摘は無い
- **落ちたときにコミットへ進まない理由**: GitHub Actions では、`if:` に `success()`・`failure()`・`always()`・`cancelled()` を含まない手順には既定で `success()` が付く。「変更をコミット・push」の `if:` は `steps.regen.outputs.files != ''` だけなので、実際は `success() && steps.regen.outputs.files != ''` になり、前の手順（足した確認）が失敗するとスキップされる。足した手順には `continue-on-error` を付けていないので、失敗はそのままジョブの失敗になる
- なお、この後ろの「取得失敗を報告」の2手順も同じく既定の `success()` が付くため、確認で落ちたときは動かない（YouTube の取得失敗の報告は出ないが、ジョブはすでに失敗している）
