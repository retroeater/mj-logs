4（HTTP 403）の調べ:

- コード: 403 のときは `Claude plan: HTTP 403` だけを投げ、応答の本文も拠点も残していなかった
- 公式の API のエラー（https://platform.claude.com/docs/en/api/errors.md ）: 403 は `permission_error`「Your API key does not have permission to use the specified resource」。ワークスペースの支出上限は 400
- 公式の Supported regions（https://platform.claude.com/docs/en/api/supported-regions.md 、175の国・地域）: 日本・韓国・台湾・シンガポールはある。香港・中国・マカオ・ロシアは無い
- Cloudflare の Placement（https://developers.cloudflare.com/workers/configuration/placement/ ）: 既定では Worker はリクエストを受けたところに最も近いデータセンターで動く。Smart Placement と Placement Hints で、裏の API の近くで動かせる
- 絞り込み: (b) キーの権限なら毎回落ちるはずで、4回だけ・同じ問いがほかの時刻に通るのと合わない。上限は 400 なので当たらない。(a) 対応していない地域に近い利用者の問いは、その近くの拠点から Anthropic を呼ぶので、4回だけ・時刻がばらばらなのと合う。(c) は否定できない。**(a) が有力だが記録からは確かめていない**
- キーの漏れや不正な利用を疑う手がかりは無い（403 の4回は質問欄から来た普通の問いで、記録の件数も1日の上限の中）
- 直したこと: 失敗の記録の答えに、応答の本文の `error.type`・`error.message`（200字まで）・`request-id` と、拠点（`request.cf.colo`・`country`）を書く
