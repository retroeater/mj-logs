### 手順2: 毎朝の再生成の実装（711cbc3a）

- 組み方: `regenerate-page.yml` に `workflow_call`（入力 `target_page`）を足し、`update-live-channel.yml` に2つ目のジョブ `regenerate` を足して
  `target_page: live_pages title_pages` で呼ぶ。`needs: update` なので取り込み（`update`）が成功したときだけ動き、さらに
  `update` の出力で「実行する（`run`）」かつ「書き込む実行（`apply`）」のときだけ動く。時刻は取り込みと同じ毎日 02:43 JST（17:43 UTC）の起動で、取り込みのジョブのすぐあと
  - lastmod の更新・サイトマップの検査・「変更があるときだけコミット」は `regenerate-page.yml` の既存の段をそのまま使う
  - `regenerate-page.yml` の `github.event.inputs.target_page` を `inputs.target_page` に変えた（`workflow_call` の入力は `inputs` にだけ入る。手動実行・週次は同じ値になる）
  - push の競合: `regenerate-page.yml` の push を、`update-live-channel.yml` の層1のコミットと同じ形（失敗したら `git pull --rebase --autostash` して3回まで）にした。
    同じ生成物が両方で変わって rebase が衝突したときは push せずに失敗する。checkout・push 先は実行ブランチのまま（#326）で、作業ブランチの実行は作業ブランチにコミットする
- 作業ブランチでの確かめ:
  1. 本実行（apply）: https://github.com/retroeater/mj/actions/runs/36321408512 成功。`update` 13:09:22〜13:11:21 UTC → `regenerate / regenerate` 13:11:24〜13:18:20 UTC の順に動いた。
     層1の追記は無し。再生成は **作業ブランチに 4699e4aa をコミットした**（cloudflare へは push していない）
  2. 取り込みの失敗（テストの段を一時的に `exit 1` にしたコミット 75767d30）: https://github.com/retroeater/mj/actions/runs/36322030886 `update` が failure、**`regenerate` は skipped**。一時の変更は 9ee5506f で戻した
- **4699e4aa の中身（想定外）**: `title/` の105ファイルと `sitemap-title.xml`。変わったのは龍龍（ron2.jp）の選手画像だけで、元画像（例 `fujimoto_t.jpg`）が縮小版（`fujimoto_t-150x150.jpg`）に戻った（134か所）。
  `sitemap-title.xml` の lastmod はそれに付随して 2026-09-27 になった。【3】の変更や `live/` の変化は無い
  - 原因の見立て: `generate_title_pages.py` の `upgrade_images()` は、龍龍の元画像に HEAD で届いたものだけ元画像にし、届かなければ縮小版のまま出す。
    この実行では Actions のランナーから元画像に届かなかったと見られる（ログ本文は読めない）。5分前の cloudflare での実行（手順1、36321262084）ではコミットが無く、届いていた。
    このセッションからは同じ画像に 200 で届く。docs/notes/static-generation.md の `check-ron2-images.yml` の項にも、続けて取りに行くと龍龍に届かなくなる例がある
  - 作業ブランチへは 07db9978 で打ち消した（cloudflare には入っていない）。作業ブランチの中身は 711cbc3a と同じ
- この結果、確かめる項目「変更が無ければコミットしない」が通らなかった（【3】に変更が無いのに、外部の画像の到達の揺らぎでコミットが出た）。
