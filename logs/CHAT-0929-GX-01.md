- **開発中の手動実行**（update-live-channel の dispatch 34回・check-image-links 12回・check-ron2-images など、16日で約250分）は一時的なもので、案の対象外とした。
- **Workers Builds の決定との関係**: 「docs だけの push でビルドが走るのを減らす運用は採らない」（2026-09-28）は Cloudflare Workers Builds の話。
  A・A2 は Actions の assets-check の起動条件だけを変え、Workers Builds の起動・本番反映には触れない。D（ログの push を減らす）は
  work/** の push が減るので Workers Builds のプレビューのビルドも結果として減るが、Workers Builds の設定は変えない。
- A で約3,000分、A2 まで入れて約3,600分を減らせる見込み（約9,100 → 約5,500分/月）。**残りの最大の塊は sync-logs（約3,400分/月、うち work 側 約2,600）**で、
  これは「作業中のログを節目ごとに mj-logs へ写す」運用の対価。ここを減らすには C（work/** で写さない）か D（push の回数を減らす）のどちらかが要り、
  どちらもログの運用（CLAUDE.md「作業ログ」・#440）の判断になる。
- 月3,000分（Pro の枠、#298 本文）に収めるには、A・A2 に加えて sync-logs を大きく減らす必要がある見込み（定期実行 約220分・regenerate 等 約300分は残る）。
