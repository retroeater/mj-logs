## 目的

CHAT-1021-LOG-01 で、生成を3層のスプレッドシートだけから作るようにしたところ、(1) 旧「ログ」で表示 N だったとみられる 2025-12 の31行がページに出るようになり、(2) 旧「ログ」から移した行の駅が手書きの駅から変換の駅に変わって、137行で駅が消え、396行で値が変わった（同じ名前の別の地域の店に当たった行が混ざる）。平野さんの判断に従って直し、ページを作り直してプレビューで止まる。

### 決定（2026-10-27、平野さん）
- 旧「ログ」で「表示」N の投稿は、3層でも出さない。ページに出ている行のうち旧「ログ」で表示 N の投稿は、【3】の「表示」を N にする
- 旧「ログ」から移した行では、旧「ログ」の駅を本文の駅と同じに扱う: 旧「ログ」の駅（「、」区切りのどれか）が「駅の候補」（店の位置から 800m 内）にあれば、そのうち最も近い駅を出す。候補に無い、または候補が空なら、旧「ログ」の駅（先頭の1つ）を出して要確認にする（別の店に当たった疑いの印）
- ほかは docs/decisions/operations.md の #367 の節のとおり（本文の駅が圏内なら本文の駅・Google の駅名の表示の整え方・【3】の空でないセルが【2】を上書き など）

### 前提（チャット側。平野さんの決定ではない）
- 2026-10-21 から、シートは読み取り用サービスアカウントの鍵で読むので、このセッションからは読めない。読み書き・再生成・前後の比べはワークフロー経由で行う（LOG-01〈1021〉と同じ）
- 旧「ログ」シートは3層のスプレッドシートに残っている（平野さんはまだ消していない見込み。要確認）。旧「ログ」を読む処理は、この指示の中だけの一度きりのものとして足し、この指示の中で消す（技術的負債を残さない）。消した後に `git grep` で旧「ログ」を読む所が残っていないことを確かめる
- 31行: LOG-01（1021）の推定では、2025-12-01〜12-30 の平野良栄 24行・谷岡育夫 7行。旧「ログ」での表示を投稿 ID で確かめ、N の行だけ【3】の「表示」を N にする（【3】に行が無ければ、投稿ID・表示 N の行を足す。ほかの列は書かない）。旧「ログ」で表示 Y の行や旧「ログ」に無い行が混ざっていたら、【3】は書かずに一覧にして報告する。31行の外にも、旧「ログ」で表示 N なのにページに出ている行があれば同じに扱い、数を報告する
- 駅の決め直しの対象: 【1】の区分「log」の行（旧「ログ」から移した 2610行）。旧「ログ」の「駅」を本文の駅に足して、今の駅の規則（`mode=stations` と同じ考え方）で【2】の「駅」「要確認」「要確認の理由」の3列だけを決め直す（案。要確認の理由の文面は「旧「ログ」の駅が圏内に無い（旧「ログ」: …）」など。実物に合わせてよい）。【2】のほかの列・【3】は書かない。Places・Claude は呼ばない（今の「駅の候補」で決める）

## 手順
1. #367 に他セッションの着手中コメントが無いことを確かめて着手中のコメントを残す（本文・状態・ラベルは変えない）。旧「ログ」を読む一度きりの処理を足し（テストを足す）、ワークフローで dry-run して、(a) ページに出ている行のうち旧「ログ」で表示 N の投稿の数と一覧（名前・日付）、(b) 駅を決め直す行の数と、決め直した後の駅の区分（旧「ログ」の駅が候補にあった・候補に無い・候補が空）の数を書く。31行の見込みと違えば止まる
2. 本番で、(a) の行の【3】の「表示」を N にし、(b) の【2】の3列を書く（書く前に読み直し、読んだときと違えば書かずに止まる）。書いたセルの数を列ごとに、要確認の数を理由ごとに（移した行・もとの行に分けて）表にする。一度きりの処理を消し、テストを通し、`git grep` で旧「ログ」を読む所が残っていないことを確かめる。決定を docs/decisions/operations.md の #367 の節に書く
3. ワークフローで再生成し、行数を見込み（3110）と比べる。cloudflare の resource_logs.html と投稿 ID で突き合わせ、LOG-01（1021）の表と同じ形で違いを数える（駅の違いは、上の「違ってよい」の種類ごとに分ける）。プレビューで、谷岡育夫 2025-06-08 の行（府中本町 など）・駅が要確認になった行の例・石立岳大の行・744行（平野良栄 2024-10-10）を確かめ、判断待ちで止まる
