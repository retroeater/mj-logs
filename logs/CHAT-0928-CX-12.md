手順

1. 準備: `regenerate-page.yml` の入力（`target_page` など）と、`steps.regen.outputs.files` がどんなときに空でなくなるかを読む。
   * 作業ブランチで title を再生成したときに、`files` が空でなくなる見込みがあるかを書く。
   * 見込みが無ければ、確認の手順を走らせる方法を探す。例: `files` を空でなくする入力、title/ の再生成に差が出る状態。ワークフローを検証のためだけに書き換える方法は、戻すことを前提に、ログに書いてから使う。
   * 方法が見つからなければ止まる。
2. 1回目: `_redirects` から大会の行を1行消すコミットを作業ブランチに push する（コミットの件名に「一時的」と分かるように書く）。そのうえで、`regenerate-page.yml` を作業ブランチで手動実行する（title を対象）。次を確かめて、ログに書く。
   * run の URL
   * ジョブが「title/ の転送の行を確認」で失敗したこと
   * 「変更をコミット・push」がスキップされ、作業ブランチに再生成のコミットが増えていないこと
   * `::error::` の注記が run の画面（annotations）に出ていること。取れる範囲で文言をそのまま書く
3. 2回目: 消した行を戻すコミットを push し、同じ条件で手動実行する。次を確かめて、ログに書く。
   * ジョブが成功したこと
   * 確認の手順が実際に走ったこと（スキップでないこと）
   * 再生成のコミットが作業ブランチに加わったかどうか。加わった場合は、変わったファイルの範囲（title/・sitemap の範囲か）
4. マージ: cloudflare との差分を確かめる（比較 URL）。差分は `regenerate-page.yml`、ログ、2回目の再生成のコミット（加わった場合）に限られるはず。1回目で消した行と2回目で戻した行は、合わせて差分が0になっているはず。
   * 差分が想定どおりなら、テスト（`python3 -m unittest discover -s scripts/tests`）が通ることを確かめて cloudflare へマージする。
   * マージの後、cloudflare の先頭のコミットの check-run「Workers Builds: mj」の完了を確かめる。
5. #455 に、2回の run の URL と結果、マージしたことをコメントする（末尾に `Chat-Ref: CHAT-0928-CX-12`）。#455 は閉じたままでよい。CX-11 のログの状態を「中断（CX-12 で続行）」に直す。

止まる条件

* 手順1で、確認の手順を走らせる方法が見つからない。
* 1回目で、失敗しない、コミットの手順に進む、または確認の手順より前で失敗する（YouTube の取得の失敗など。原因を書く）。
* 2回目で成功しない、または確認の手順がスキップされる。
