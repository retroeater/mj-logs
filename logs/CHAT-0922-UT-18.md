### (2) 揺れの原因（前提との食い違い）

- 前提は「生成側でサイズを決めておらず、取ってきた URL の末尾をそのまま使っている」。**実物は違う**:
  `generate_saikyo_pages.py`（`upgrade_x_images()`）・`generate_live_pages.py`（`resolve_photos()`、saikyo の定数を import）・
  `generate_title_pages.py`（`upgrade_images()`）は、シートの `_80x80` / `_normal` を `_400x400` に**書き換えている**。
  ただし書き換えの前に `_400x400` へ HEAD を1回送り、200 でなければシートの URL（`_80x80`）のまま出す。揺れはこの HEAD の結果の揺れ
- 既存の issue: **#359**（/live の揺れ、原因は上と同じ）と **#380**（X画像URLの処理を `scripts/lib/` に共通化し、到達確認の結果を残す。
  完了時に #359 もクローズ）。どちらも open で、未マージの work/ ブランチに着手の跡は無い
- 履歴の実測（`origin/cloudflare` の `chore: regenerate` 119件、2026-08-28〜09-27）: 同じ写真の `_80x80`⇔`_400x400` の入れ替わりを
  含むコミットは23件。入れ替わった写真は延べ7種類で、どれも同じ写真が何度も往復している（西野拓也の `fOEDy0z9` 等）。
  入れ替わりが出たファイルは延べ59（`live/` 35・`saikyo/` 15・`title/` 8・`jpml_pros.html` 1）。
  `jpml_pros.html` の1件（`d3f1a7cd`）は生成の揺れではなく、シートの J列が `_400x400` → `_80x80` に変わったもの
- 揺れた写真の今の状態（curl、2026-09-27）: 7種類のうち5種類は**全サイズ 404**（写真を変えたアカウントの古い URL。
  ただし `WeNOqhoY` は `_normal` だけ 200）、2種類（`HrWMTmeF`・`dsF6GkUA`）は全サイズ 200。
  つまり揺れは (a) 古くなった URL の `_400x400` が取得元・時刻によって 200/404 と揺れるもの、(b) 生きている URL の一時的な失敗、の2種類。
  (a) では `_80x80` に倒しても 404 で、倒す意味が無い
- `03c2108b` の `saikyo/`・`live/`・`title/` の差分の大半（53ファイル）は `WeNOqhoY` の `_400x400` → `_80x80`。今は `_400x400`・`_80x80` とも 404 で、
  どちらを出してもリンク切れ（`data-fallback` の代替画像が出る）
- 補足: Python の既定の User-Agent（`Python-urllib`）だと pbs.twimg.com は 403 を返す。生成側は独自の UA を付けているので影響なし
