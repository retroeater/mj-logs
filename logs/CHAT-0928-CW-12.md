手順

1. 配信対象の HTML（`.assetsignore` で除いた追跡ファイル）に、メールアドレス（本文・`mailto:`・属性の中を含む）がいくつ、どのページにあるかを数える。人のアドレスを見つけても、ログには件数・ページ名・ドメイン部分だけを書き、アドレス全体を書かない（CLAUDE.md「作業ログ」の個人情報の規則）。あわせて、Polyfill（`polyfill.io` など、Replace insecure JS libraries の対象）を読み込んでいるページがあるかを数える。

3. #449 に、ダッシュボードの状態（申告）と #120 の記録との食い違い、手順1・2の結果を短くコメントする。

### 2. 切ったときの影響

- **Email Address Obfuscation を切る: 影響なし（切ってよい）。** 配信する HTML にメールアドレスが1つも無いため、隠していたものが見えるようになるページは無い。
  CW-09 で本番の HTML がリポジトリとバイト単位で一致したのも、この機能がオンでも書き換える対象が無かったためと整合する（オンかどうかの判定にはならない）
- **Replace insecure JavaScript libraries を切る: 影響なし（切ってよい）。** Polyfill を読み込むページが無いため、置き換えられていたものは無い。外部のスクリプトは Web Analytics のビーコン（`static.cloudflareinsights.com`）と assets/vendor のローカル配信（CLAUDE.md「構成」）で、この機能の対象ではない
- どちらも代わりの手段（Configuration Rule）は要らない
- 切る順番はチャット側の案（Email Obfuscation → Replace insecure JS libraries → Web Analytics の自動設定）のままでよいと見る。1つ切るごとに CW-09 の「直ったことの確かめ方」（`jpml_pros.html` に `etag:` が出る → その値で `If-None-Match` → 304）をセッションで行える。今は ETag が無いので、この確かめ方は切る前の状態では通らない
