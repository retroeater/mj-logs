前提（チャット側。平野さんの決定ではない）

* 平野さんが 2026-09-28 に送ったダッシュボードのスクショをチャット側が読んだもの（申告であり、セッションからは検証できない）:
   * Automatic HTTPS Rewrites: オフ
   * Security → Settings の Email Address Obfuscation: オン（#120 では 2026-09-11 に Off と記録されている。食い違い）
   * Replace insecure JavaScript libraries: オン（説明文では対象は Polyfill）
   * Continuous script monitoring: オフ。JavaScript detections・Web Analytics の自動設定の状態は、まだ見ていない
* 公式ドキュメント（CW-09 のログ「1.」）では、Email Obfuscation は強い ETag を残す条件にも、応答を展開・再圧縮する機能の一覧にも入っている。Replace insecure JS libraries も一覧に入っている。どちらも HTML にだけ効く。チャット側の見立ては、Email Obfuscation が最有力（確かめていない）。
* 切る順番の案（チャット側）: Email Obfuscation → （ETag が戻らなければ）Replace insecure JS libraries → Web Analytics の自動設定。1つずつ切り、そのたびに CW-09 の「直ったことの確かめ方」を行う。

手順

1. 配信対象の HTML（`.assetsignore` で除いた追跡ファイル）に、メールアドレス（本文・`mailto:`・属性の中を含む）がいくつ、どのページにあるかを数える。人のアドレスを見つけても、ログには件数・ページ名・ドメイン部分だけを書き、アドレス全体を書かない（CLAUDE.md「作業ログ」の個人情報の規則）。あわせて、Polyfill（`polyfill.io` など、Replace insecure JS libraries の対象）を読み込んでいるページがあるかを数える。
2. 結果から、Email Obfuscation を切ったときの影響（アドレスがそのまま見えるようになるページ）と、Replace insecure JS libraries を切ったときの影響を書く。影響が無い、または小さいなら「切ってよい」、影響があるなら代わりの手段（Configuration Rule で HTML の一部のパスだけ止める等）を案として書く。
3. #449 に、ダッシュボードの状態（申告）と #120 の記録との食い違い、手順1・2の結果を短くコメントする。
