### 手順2: 案

| | 案1 値で持つ | 案2 数式で持つ（推奨） | 案3 機械が毎日書き直す |
|---|---|---|---|
| (a) 既存の4,304行 | Apps Script で一度、【2】から値を書く | 見出しの行（1行目）に数式を1つずつ置けば全行に出る（ARRAYFORMULA で動画IDから【2】を引く） | 次の毎日の実行で全行を書く |
| (b) 毎日追記する行 | 追記のときに【2】の値を書く（`build_new_rows()` に2列を足す） | 何も書かない（数式が新しい行にも広がる）。**追記がその2列に `""` を書かないようにする直しが要る**（下） | 追記と同じ実行で2列を全行書き直す |
| (c) YouTube で題名・公開日時が変わったとき | **古いまま残る。** 生放送の公開日時は配信前の値（枠を作った日時）で固まる。直すには Apps Script を再び流す | 【2】が毎日書き直されるので、翌朝には新しい値になる | 翌朝に新しい値になる |
| (d) 変えるもの | コード: `live_layer3.build_new_rows()`・`to_sheet_rows()`・テスト。シート: 列2つを足し Apps Script で埋める（平野さんが実行） | コード: `to_sheet_rows()` が参考の列に `None`（値を送らない）を置く・`append_only_errors()` が参考の列を比べない・テスト。シート: 列2つを足し、見出しの行に数式を置く（平野さん、または Apps Script） | コード: 2列だけを書く処理と、その確認（`append_only_errors()` の「既存の行が変わっていない」を2列だけ外す）。「【3】は機械は追記だけ」（#438）の原則を崩す |
| (e) 列の名前 | 「参考:公開日時」「参考:タイトル」 | 同じ | 同じ |

- 案2 で直しが要る理由: 今の `to_sheet_rows()` は知らない列に `""` を書く。「冒頭」の右の2列は備考より左なので、追記の行のその2列に `""` を書くことになる。
  Sheets API では `""` は「空の値を書く」、`null` は「書かない」。`""` が ARRAYFORMULA の広がり（spill）を止める（#REF!）かどうかは確かめていない（未確認）。
  さらに追記後の確認（`append_only_errors()`）は、追記した行を読み返して足した値と比べるので、数式の値が出る2列で「末尾に増えた行が足した行と一致しない」になり、**直さないまま列を足すと翌朝の追記が失敗する**
- 案2 の数式の形（実装のときにシートで確かめる。列記号に依らないよう【2】の見出しで列を引く）:
  `={"参考:タイトル"; ARRAYFORMULA(IF(A2:A="",, IFERROR(VLOOKUP(A2:A, {'【2】自動変換後'!A2:A, INDEX('【2】自動変換後'!A2:Y, 0, MATCH("タイトル", '【2】自動変換後'!A1:Y1, 0))}, 2, FALSE))))}`。
  公開日時は同じ形で、UTC の文字列を日本時間の `yyyy-mm-dd hh:mm` の文字列にする（`DATEVALUE`・`TIMEVALUE` ＋ 9/24 → `TEXT`）。文字列にしておけば gviz の列の型も文字列のまま
- 案2 のほかの点: 【3】は並べ替えてよい（live-channel-write.md「【3】の扱い」）。数式は各行の動画IDから引くので、並べ替え（見出しの行を除く）の後も行と値が合う。
  【2】が clear → 書き直しの途中の数秒は空に見える（参考の列だけ）。4,304行 × 14,102行の VLOOKUP の再計算で開くのが重くなるかは未確認
- 列の名前: 【2】と同じ「公開日時」「タイトル」だと、補正の列（【2】と同じ名前の列＝【2】を上書きする）と見分けが付かない。**「参考:公開日時」「参考:タイトル」**と頭に「参考:」を付け、並べたときに参考の列と分かり、後で補正の列を足す作業とも重ならないようにする。
  コードでは「参考:」で始まる見出しを追記で書かない・確認で比べない列として扱う（案2）
- 推奨: **案2**。理由: 追記の多くは配信前の行で、案1・値の写しでは生放送の公開日時が配信前の値（枠を作った日時）のまま固まり、掲載・冒頭の判断の参考としてずれる。案2 は【2】が変わると翌朝には追い付き、機械が【3】の既存の行を書き換えない原則（#438、案3 が崩す）も保てる。コードの直しも追記の2関数とテストだけで小さい
- 参考（決定ではなく確かめたいこと）: 掲載・冒頭を決める参考なら、生放送は「公開日時」より「配信開始日時」（配信前は「配信予定開始日時」）のほうが配信の日と合う。「冒頭」の規則（`opening_ids()`）もこちらで比べている
