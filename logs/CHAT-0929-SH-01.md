### 3. 実装する場合の材料

#### 触るファイルの範囲の見込み

- **ナビの右端（虫眼鏡の右）に置く場合: `navbar.js` だけで 1538ページに出せる。** 虫眼鏡は navbar.js の88行目で `nav` 直下の最後に置かれており、
  その後ろに1要素足せばよい。虫眼鏡の無い1521ページでは右端に単独で出る。index.html（navbar.js を読まない iPortfolio テンプレート）だけは別途。
  動作の JS（共有シート→コピー）と CSS（style.css）は足す必要がある。ページの再生成は不要。
- **本文の検索欄（`#searchBoxes`・filterbar）の右に置く場合: ページごとの直書きを触る。** `lib/page.py`、generate_jpml_pros / houou_leagues / ouka_leagues、
  filterbar を出す生成スクリプト（title / live / saikyo / books / video_wayhome）、手書き6ページ。検索欄の無い237ページには置き場所が無い。
- どちらでも、既に共有ボタンのある940ページ（live・wayhome・saikyo・books）で二重になる。navbar 側を出さない印（`data-search="off"` と同じ作り）を付けるか、
  既存ボタンを外すかの判断が要る。4本の JS に重複する共有ロジックは、1本（例: 共通の `assets/share.js`）にまとめる機会になる

#### 外部スクリプトを使わない方式と方針の関係

- Web Share API（`navigator.share`）＋非対応時の URL コピー（`navigator.clipboard` → `execCommand` → 手動）は、既存940ページと同じ方式で、外部ドメインを増やさない
- `_headers`: CSP は無い（meta の CSP も0件）。Permissions-Policy は `geolocation=(), microphone=(), camera=()` だけで、`web-share`・`clipboard-write` を制限していない。食い違いなし
- CSP（#9）・インラインハンドラ廃止: `addEventListener` で付ければ食い違わない。navbar.js は `document.write` で描くため、ボタンの要素は write で出し、
  ハンドラは DOMContentLoaded 後に付ける（`onclick=` 属性は使わない。docs/new-site-design.md「共有ボタン（URLコピー）」も同じ）。
  X / LINE の共有 URL（`x.com/intent/post`・`social-plugins.line.me/lineit/share`）へのリンクは遷移であり、スクリプトの読み込みではないので CSP の script-src には影響しない（既存 `lib/wayhome.py` のメニューと同じ）。
  既存のインラインハンドラは houou/ouka/wrc_ranking.html の `onchange="javascript:…"` 3件だけで、今回とは無関係
- 見送る点: SNS 公式のボタン（外部スクリプト）は使わない

#### OGP の現状（docs/notes/ogp.md）

- `og:title`・`og:image`・`og:url`・`twitter:card` は 1539件中 1538件にある。**無いのは 404.html だけ**（noindex で共有対象外）
- `og:image` の内訳: 共通の `img/ogp.png` 749件（トップ階層24・books 191・title 384・live 150）／YouTube サムネイル 771件（live 732・wayhome 39）／`img/ogp/*` 18件（saikyo 17・video_wayhome 1）
- 共有したときのカードは付く。ただし title/ など共通画像のページは、どのページを共有しても同じ画像になる（出し分けは #232 の判断待ち）
- ogp.md「共有ボタンの文言は `<title>` と同じになる作り（#191）」。`og:title` は短縮形、`<title>` は正式名で、文言の出どころは既存と同じく `<title>`（`document.title`）にするのが平仄

#### 実装案（実装はしない）

- **案1: navbar.js に共有ボタンを足す（全ページ一括）。** 虫眼鏡の右（無ければナビの右端）に1つ。押すと `navigator.share`、非対応ならURLコピー
  （X / LINE のメニューは付けず、コピー＋OS の共有シートだけ）。URL は canonical があればそれ、無ければ `location.href`（`?name=` などの状態を保つ）。
  共通 JS 1本＋navbar.js＋style.css。既存の共有ボタンがあるページは `<body data-share="off">` で出さない（生成スクリプトの変更と再生成が要る）か、
  逆に既存を段階的に外す。index.html は対象外か手で足す。
  利点: 触る範囲が小さい。欠点: #82・handover 4章の「現行サイトに作り込みすぎない」方針から外れる。ナビの幅（モバイルのハンバーガーの隣）の見た目の確認が要る
- **案2: #409 のとおり title/ から、filterbar の右に置く。** books の `.mj-book-share`（「検索欄の右」）・saikyo の固定バーの共有と同じ作りで、
  `generate_title_pages.py` と、4本に重複した共有ロジックを共通の JS にまとめたものを使う。他ページへの展開は1系統ずつ判断する。
  利点: 既存の方針（#409 の段階展開）どおりで、見た目が既存の共有ボタンと揃う。欠点: 「全ページ」にはならず、検索欄の無い237ページには置き場所が無い
