### 2. pdftoppm の処理（b86def3）

- 読み方は1つに寄せた: 56本すべてを pdftoppm で描く（JPEG を取り出す処理は外した）。理由: Flate・3枚に分かれた号と JPEG の号で処理を分けると、確かめる経路が2つになるため。JPEG の号も元の画像の横の画素数で描くので、画素はほぼそのまま
- 描き方: `pdfinfo` でページ数、`pdfimages -list` でページごとの画像の横の画素数の最大（3枚に分かれたページは3枚に共通の 1591）を読み、`pdftoppm -gray -png -singlefile -f N -l N -scale-to-x <横の画素数> -scale-to-y -1`。回転は pdftoppm が当てる
- 拡大: 切り出しの横を 1,354px に揃える（1591 幅の号は 1.6倍で今までと同じ。1193〜1240 幅の号は約 2.1〜2.2倍）。上限は 2.5倍・長辺 2576px・3.75MP
- poppler: ワークフローで `pdftoppm`・`pdfimages` が無いときだけ `apt-get install -y poppler-utils`（Python の依存は足さない）
- 目で確かめるための切り出し: direct の入力 `dump`（`200104_003-p01` の形）で指定したページの切り出しだけを、`actions/upload-artifact`（v7.0.2、SHA で固定、保持1日、if-no-files-found: ignore）で成果物 `news-dump` にする。新しい action を足すので、着手後に平野さんに確かめ、「upload-artifact を足す」の回答を得た（このセッションの質問）。リポジトリ・ログ・issue には入れない
- 号ごとの照合済みの割合の表を出すようにした（条件2のため）
- 試験: Flate の画像1枚のページ、JPEG・JPEG・Flate の3枚に分かれたページ、画像の無いページ、PDF でないファイルを試験の中で作り、pdftoppm で描いて寸法と画素を確かめる。`pdfimages -list`・`pdfinfo` の出力の読み方、小さい号の拡大、dump
