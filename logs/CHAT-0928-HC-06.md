決定（平野さん、2026-09-28。#448 の本文にもある）

* 予定表は Calendar API で読む。対象は今日から 2027-03-31 まで。
* 3層は /live と同じ考え方で使う。【2】【3】に掲載 Y/N を置き、【3】の行は日付＋件名で結び付ける。書き込みは `live-channel-writer`（平野さんが共有済みと申告）。
* 予定表の予定に時刻が無いときは、過去の同じタイトル戦を参考に【2】で開始時刻を仮置きする（例: 鳳凰戦 A2 → 16:00）。平野さんは【3】で上書きできる。
* 終了時刻は、同じ日に次の番組があればその開始時刻、無ければ 23:00。例外は【3】で上書きする。
* 予定表で1日にまとめて書かれた卓（「ベスト8AB卓」など）は、同じ放送枠で放送される。
* 掲載するのは完全版（全編）の枠。完全版がメンバー限定で、一部だけ無料の版もあるときは、その無料版のリンクも載せる。
* 判定がはっきりしない大会（王位戦のベスト72・本戦・準決勝、WRC-R リーグのトーナメント、WROTL、学生麻雀王位戦など）は、【2】で掲載 N にし、平野さんが【3】で Y にできる。

手順

1. 取り込みの確認と読み取り: docs/notes/static-generation.md「ワークフローを手動実行するとき」を読んでから、`update-live-channel.yml` を cloudflare ブランチで、毎朝の実行と同じ入力（層1をコミットし【1】【2】【3】に書く。verify はしない）で手動実行する。作業ブランチから実行しない。既に毎朝の実行が済んでいれば手動実行はせず、その結果を使う。結果で #448 のコメントの3点を確かめる。次に、Actions から `GCP_SA_KEY` で予定表を `events.list`（singleEvents、今日から 2027-03-31）で読めるかを、作業ブランチの手動実行で確かめる。
2. 【1】【2】【3】への取り込み: スクリプトとワークフローを作る。

* 【1】元データ: 予定表の予定を、加工せずに（予定ID・日付・件名・説明・更新日時・取得日時など）機械が毎回置き換える。
* 【2】自動変換後: 【1】の各行に、大会の分け、掲載 Y/N（配信あり見込み）、開始時刻の仮置き、終了時刻の仮置き、結び付いた YouTube の枠（完全版の動画ID・無料版の動画ID。同じ日・同じ大会の枠。層1から）を足す。開始時刻の仮置きは、層1の過去の同じ分けの実際の開始時刻から決め、使った根拠（件数など）の列も置く。終了時刻の仮置きは、同じ日の次の番組（予定表の他の行と、層1の同じ日のライブの両方）の開始時刻、無ければ 23:00。
* 【3】手動補正: 日付＋件名で【2】と結び付き、掲載 Y/N・開始・終了・備考を平野さんが書く。機械は【2】に新しく出た行を末尾に追記するだけで、平野さんの入力を書き換えない（/live の【3】と同じ考え方）。
