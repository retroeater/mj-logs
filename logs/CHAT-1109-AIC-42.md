## 目的

AIC-41 は、2回目のレビューで次の誤りが残ったため、マージせずに止まった（中高）。

- 名前の頭が一致する人が1人だけのとき、その人で答える形にした
- そのため、その大会に記録の無い人に決まり、記録のある人がいても「〜の記録に「…」に当たる選手はいません」と答える（WRC リーグの「勝」「とも」、鳳凰戦の「ロ」「ろ」など7語）
- かなの問いが、かなで書かれた名前の人に決まる（「とも」→ ともたけ雅晴、「こう」→ こうちゃん など、中）

平野さんの判断で、絞り方を狭める。1人には決めず、候補の並びを絞るだけにする。

### 決定（2026-11-09、平野さん）

- AIC-41 の「判断が必要なこと」への回答
  - 残った誤り（中高）と、かなの問い（中）: 次の形に狭めて直す
    - 名前の頭が書かれた語と一致する人が2人以上いて、かつ、その中にその大会に記録のある人（成績の行か決勝の順位）が1人以上いるときだけ、頭が一致する人たちに候補を絞る
    - それ以外（頭が一致する人が1人だけ・いない・いても記録のある人がいない）は、今の部分一致のまま
    - 1人には決めない（今1人に決まる問いも、今候補が出る問いも、答えは今と同じか、候補が絞られるだけ）
  - 読みの頭では絞らない（AIC-41 の 6a6f85425 の形）: このままでよい
  - ほかの大会への案内と決勝だけの答えは絞らない（AIC-41 の形）: このままでよい
- チャット側の見立ての誤り: AIC-41 の指示に「絞って1人ならその人で答えるのを第一の案」と書いたのはチャット側。それが今回の誤りの元になった
- AIC 系列のマージの例外は 2026-11-02 の決定のまま

### 前提（チャット側。平野さんの決定ではない）

AIC-41 のログ（作業ブランチ）と今のコードを読む。着手時に開き直す。

- 作業ブランチの AIC-41 の直し: `query.mjs` の `matchNames()` で、部分一致のうち頭が一致する人がいればその人たちだけを返す（表記の頭だけ。案内と決勝だけの答えは `nameCandidates(data, text, false)` で絞らない）
- 直し方: 上の決定の条件（頭が一致する人が2人以上、かつ、その中にその大会に記録のある人が1人以上）を足す。記録の有無は、今の `recordNames()` と同じ見方（`data.players[name]` か決勝の順位）でよい
- 今週の13の名字で変わるのは「原」だけの見込み（AIC-41 の表。鳳凰戦は42人 → 3人、WRC リーグは14人 → 2人、最強戦は21人 → 3人。それぞれ記録のある人を含むかを確かめる）
- 全数の比べ（AIC-41 の cmp41.mjs・rec41.mjs、16,105語・20,146語）で、次の3つを数える
  - 1人に決まる問いが変わった数（0 であること）
  - 候補から1人に決まるようになった数（0 であること）
  - 絞った後の候補に、その大会に記録のある人が1人もいないのに、絞る前にはいた数（0 であること）
- 答えが変わってよい問い: 候補を出す答えのうち、上の条件に当たって候補が絞られる問い（「原」など）
- 選手の役職などの人の属性は、ログ・テストに書かない（名前だけ）
- 本番の確かめは1日10問まで（同じ接続元から）。2026-11-09 は AIC-40 で4問使っている

   - 頭が一致する人がいても、その中に記録のある人がいない作り物の名簿で、今と同じ候補
