目的
Google Search Console（GSC）関連のタスクを洗い出して片付けるための、最初の棚卸し。issue の起票・変更・クローズ、コードの変更はしない（調べてログに書くだけ）。識別子 SC が使用済みなら止まって報告する。
前提（チャット側。平野さんの決定ではない。実物で確かめ、違えば止まる）

* 2026-09-21 の GC のチャットで、GSC 関連 issue を洗い出している（CHAT-0921-GC-01 のログ）。その時点で残っていたと見ているもの: #130（9/24 以降の 403 の確認とクローズ）、#269（10/1 の初回の定期実行の確認とクローズ）、#304（10/1 に初回の月次）、#427（該当 push を待つ、期限なし）、#413（title/ 公開後に大会名クエリの着地先を比べる）、#126（IndexNow は #156 待ち）
* GSC の「ページ」（インデックス登録）レポートは API で取れない（docs/gsc/README.md に記載がある想定）

手順

1. GC-01 のログを起点に、GSC に関わる issue をクローズ済みも含めて洗い出す（キーワード例: Search Console・GSC・インデックス・sitemap・robots・クロール・canonical・Bing・IndexNow。ラベル「分野: SEO/AIO」も見る）。GC-01 以降に増えた・状態が変わったものを必ず拾う。開いているものは1行ずつ「状態 / 次にやること / 担当（平野さんの手作業か Claude Code か）/ 期日または待ちの条件」を表にする。
2. 今の仕組みを確かめて書く: #269 の自動取得のワークフロー（ファイル名・スケジュール・取得している項目と期間・保存先の構成・次回の実行予定）、docs/gsc/ の中身の一覧と README の要点、#304 の本文の月次の項目一覧と実施記録の有無、サービスアカウント gsc-export の GSC 上の権限、GSC のプロパティの種類（ドメイン／URL プレフィックス）と所有権の確認方法。文書・ワークフローから分からないものは「記載なし」と書く（推測で埋めない）。
3. 下の候補ごとに、既に着手・記録・却下されたものがあるかを issue と docs で確かめ、「既存（issue 番号）／却下済み（理由の所在）／記載なし」の表にする。候補の良し悪しの判断はしない。
   * P1 「ページ」レポートの未登録（重複・クロール済み未登録など）の例示 URL を、URL の形（パス・パラメータ）で分類する
   * P2 URL 検査 API で sitemap の URL の登録状態・Google が選んだ正規 URL を定期取得する（API の利用上限と、gsc-export の権限で呼べるかも公式ドキュメントで確かめて書く）
   * P3 表示回数が多いのに掲載順位 4〜20 位・クリック率が低い「クエリ×ページ」の一覧
   * P4 国・言語別の表示回数とクエリ（海外からの検索）
   * P5 選手名のクエリの着地先ページ
   * S1 プロパティの所有権の確認方法の冗長化（GitHub Pages の停止〈#84〉の影響が無いか）
   * S2 「動画ページ」「拡張（構造化データ）」レポートの確認
   * S3 「リンク」レポート（内部リンク・外部リンクの上位）の記録
   * S4 「クロールの統計情報」のホストの状態（robots.txt の取得・DNS・サーバー接続）、手動による対策・セキュリティの問題の確認が #304 の月次にあるか
   * S5 BigQuery への一括データエクスポート

止まる条件

* 識別子 SC が使用済みの場合
* 対象の issue に他セッションの新しい着手中コメントがある場合（報告して、その issue は読むだけにする）
